## 二、深度图处理流水线

相机原始深度图不能直接喂进网络，要顺序经过五步：

```
resize → crop → inpaint → gaussian blur → clip & normalize
```

**训练侧与部署侧必须逐步一致。** 和 sim2sim 的其它环节一样，
这五步错了都不报错，只会让策略读到"另一个世界"的距离。

### ① resize —— 必须用最近邻

```python
image = cv2.resize(image, dsize=(w, h), interpolation=cv2.INTER_NEAREST)
```

两个坑：

**`dsize` 是 `(宽, 高)`，与 numpy 的 `(行, 列)` 相反。** 传反了图像会被转置，
不报错。验证脚本特意用非方形尺寸（36×64 裁剪后 31×55），
方形输入根本测不出这个错误。

**插值方式必须是 `INTER_NEAREST`。** 深度图的像素值是**物理距离**，
不能做加权混合。双线性会在物体边缘造出"介于前景与背景之间"的假深度 ——
那个位置其实什么都没有，策略会把它当成一个真实存在的障碍面。

### ② crop —— 裁掉边缘畸变区

```python
image = image[y1 : h - y2, x1 : w - x2]
```

真实深度相机的边缘畸变最大、无效点最多，裁掉可减少 sim2real 差距。

### ③ inpaint —— 补掉无效点

```python
mask = (image < 0.2).astype(np.uint8)
image = cv2.inpaint(image, mask, 3, cv2.INPAINT_NS)
```

深度相机在反光/吸光表面会返回 **0**，表示"没测到"。
但 0 在归一化后是**最近距离**，语义完全相反 ——
不补的话策略会以为镜头前紧贴着一堵墙。

用 `INPAINT_NS`（Navier-Stokes）而不是填常数：它沿等照度线把邻域深度
延拓进洞里，更符合深度图本身的连续性。

### ④ gaussian blur —— 必须是轻度的

```python
image = cv2.GaussianBlur(image, (3, 3), 1, 1)
```

抑制仿真深度图的阶梯状锯齿。核 3×3、σ=1 是轻度平滑：
**太强会抹掉台阶边缘，而台阶边缘正是跑酷策略最需要的信息。**
验证脚本用一条竖直阶跃边测过渡带宽度，实测 **2 像素**，边缘保留完好。

### ⑤ clip & normalize —— 零点与量程的定义

```python
np.clip(image, a_min=self.near_clip, a_max=self.far_clip, out=image)
image = (image - self.near_clip) / (self.far_clip - self.near_clip)
```

把 `[near_clip, far_clip]` 线性映射到 `[0, 1]`。
先 clip 再归一化，保证超出量程的值被**截断**而不是外推。

> 这与实践 2 的 `height_scan` 是同一件事：`offset=0.5` 不是物理常数，
> 而是训练时采用的**零点定义**，部署时必须保持一致，
> 否则策略读到的数值分布整体平移。

## 七、逐条核对官方规格（2026-09-05）

作业 §8 对 `DepthImagePipeline.append()` 给了**逐条**的实现规格，
不只是"跑通就行"。这里把每一条与实际实现对照，作为验收依据。

官方要求的处理顺序：
**resize → crop → inpaint → Gaussian blur → clip → normalize → append**

| # | 官方规格原文 | 实际实现 | 符合 |
|---|---|---|---|
| 1 | `self.shape` 按 `(height, width)` 保存，先解包为 `h, w` | `h, w = self.shape` | ✅ |
| | `cv2.resize` 的 `dsize` 顺序是 `(width, height)` 即 `(w, h)` | `dsize=(w, h)` | ✅ |
| | 插值方式为 `cv2.INTER_NEAREST` | `interpolation=cv2.INTER_NEAREST` | ✅ |
| 2 | `crop_region` 顺序为 `(y1, y2, x1, x2)` | `y1, y2, x1, x2 = self.crop_region` | ✅ |
| | 高度方向用 `y1 : h - y2`，宽度方向用 `x1 : w - x2` | `image[y1:h-y2, x1:w-x2]` | ✅ |
| 3 | 用 `(image < 0.2)` 找无效像素，转 `np.uint8` mask | `(image < 0.2).astype(np.uint8)` | ✅ |
| | `cv2.inpaint` 传入半径 3 与 `cv2.INPAINT_NS` | `cv2.inpaint(image, mask, 3, cv2.INPAINT_NS)` | ✅ |
| 4 | `cv2.GaussianBlur` 核 `(3,3)`，`sigmaX=1`、`sigmaY=1` | `cv2.GaussianBlur(image, (3,3), 1, 1)` | ✅ |
| 5 | clip 到 `[near_clip, far_clip]` | `np.clip(..., out=image)` | ✅ |
| 6 | 归一化 | `(image - near_clip) / (far_clip - near_clip)` | ✅ |
| 7 | 入队 | `self.que.append(image)` | ✅ |

### 三个容易写反的地方

**① `dsize` 的顺序与 numpy 相反**

OpenCV 用 `(宽, 高)`，numpy 用 `[行, 列]` 即 `(高, 宽)`。
`self.shape` 存的是 `(height, width)`，所以必须写 `dsize=(w, h)` 而不是 `(h, w)`。

写反了**不会报错**——只要图像不是正方形，resize 出来的图会是转置的尺寸，
后续 crop 索引仍然合法，一路跑到策略输入才表现为"感知乱掉"。

**② 为什么插值必须用 `INTER_NEAREST`**

深度图的像素值是**物理距离**，不是颜色。
双线性插值会在物体边缘生成"中间距离"的假像素 ——
比如台阶边缘 0.5 m 和 2.0 m 之间插出 1.25 m，机器人会以为那里有个不存在的斜坡。
最近邻插值保持深度值的离散性，宁可锯齿也不要虚假的平滑过渡。

**③ 为什么 inpaint 阈值是 0.2 m**

深度相机在极近距离（< 0.2 m）返回的是无效值（0 或噪声），
不是"这里有个很近的障碍"。直接喂给策略会让它以为前方一直有墙。
`cv2.INPAINT_NS`（Navier-Stokes）用周围有效像素的梯度场把这些空洞填上，
比简单填常数更符合深度图的空间连续性。

### 与实践 2 高度扫描的对照

同样是感知，两者的预处理思路不同：

| | 实践 2 高度扫描 | 实践 11 深度图 |
|---|---|---|
| 数据来源 | RayCaster 射线（仿真里精确） | 深度相机（有噪声、有空洞） |
| 无效值处理 | `clip(-1, 5)` 直接截断 | `inpaint` 修补 |
| 平滑 | 无（射线本身干净） | 高斯模糊（压相机噪声） |
| 时间维 | 5 帧历史 | 队列 + **随机延迟**（`resample_delay`） |

**随机延迟是实践 11 特有的**：真实相机有传输与处理延迟且不固定，
训练时随机化延迟能让策略对时序抖动鲁棒。
仿真里的 RayCaster 没有这个问题，所以实践 2 不需要。
