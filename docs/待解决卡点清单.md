### 声明的依赖 ≠ 真实需要的依赖

`instinct_rl/setup.py` 的声明与实测结果对照：

| setup.py 声明 | 实测结论 | 怎么测的 |
|---|---|---|
| `python_requires=">=3.12,<3.13"` | **过度声明**，3.11 完全可用 | `compileall.compile_dir()` 用 3.11 编译全部源码，零语法错误 —— 没用任何 3.12 专属语法 |
| `torch==2.11.0` | **过度声明**，2.7.0 全覆盖 | 提取代码里全部 81 个 `torch.*` API，在 torch 2.7 里逐个 `getattr` 验证，**无一缺失** |
| `numpy>=2` | **过度声明**，1.26.0 可用 | import 与实例化均正常 |

用 `==` 钉死版本通常只反映作者的开发环境，不代表代码真需要那个版本。
判据应该是「代码调用的 API 在目标版本里有没有」，不是「声明写了什么」。

### 反证：升级到 3.12 反而装不上课程指定的 IsaacSim

- IsaacSim 5.1.0 的 wheel 是 `Requires-Python ==3.11.*`，3.12 只有 IsaacSim 6.0
- 本机 `pxr`（USD 模块）的实际路径带 **`cp311`** 标记：
  `isaacsim/extscache/omni.usd.libs-1.0.1+69cbf6ad.lx64.r.**cp311**/pxr`
  —— 这些二进制扩展是**按 CPython 3.11 ABI 编译**的，换 3.12 直接失效

所以 `instinctlab` README 写的 Python 3.11 才是对的，`instinct_rl` 的 3.12 声明与之自相矛盾。

### 实际做的事（一个小包，非 20 GB）

唯一真实缺失的是 `pytorch_kinematics`，与 torch 版本无关：

```bash
# 装前先 dry-run 确认不会连带升级 torch/numpy
envs/isaaclab/bin/pip install --dry-run pytorch_kinematics
#   Would install arm_pytorch_utilities-0.5.0 pytorch-seed-0.2.0 pytorch_kinematics-0.10.0
#   ↑ 没有任何 uninstall / 升级，安全

envs/isaaclab/bin/pip install pytorch_kinematics
```

**装后立即比对 `pip freeze` 快照确认无回归**（实践 1~9 全靠这个环境）：

```
torch  2.7.0+cu128  →  2.7.0+cu128   未变 ✅
numpy  1.26.0       →  1.26.0        未变 ✅
差异仅新增 3 个包，无任何包被升级或卸载
```
