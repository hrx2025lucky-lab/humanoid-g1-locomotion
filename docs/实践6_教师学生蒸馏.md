# 实践 6 — 教师-学生蒸馏（全身运动跟踪）

> Teacher 能看到当前帧 + **未来 20 帧**参考动作（21×64 维 motion command），
> Student 只能看到当前参考帧 + 本体 + 历史 —— 更接近真机部署条件。
> 蒸馏的目的是让 Student 在信息更少的条件下学到 Teacher 的控制规律。

```
L = L_PPO + λ(step) · L_distill
```

两种蒸馏方式：
- **Action Matching** — 对齐动作本身（分布的均值）
- **KL Matching** — 对齐完整的高斯分布（均值 + 标准差）

---

## 一、KL 的方向不能写反

```python
kl = log(σ_s/σ_t) + (σ_t² + (μ_t - μ_s)²) / (2σ_s²) - 1/2      # 逐维
return kl.sum(dim=-1).mean()                                    # 对角协方差 → 求和 → batch 均值
```

必须是 **forward KL(teacher ‖ student)**：

| | 行为 | 后果 |
|---|---|---|
| `KL(teacher‖student)` | **mass-covering** | Student 分布被迫**覆盖** Teacher 的全部支撑集 |
| `KL(student‖teacher)` | **mode-seeking** | Student 缩到 Teacher 的某一个峰上，丢掉其余行为模式 |

原因在于 forward KL 在"Teacher 概率高而 Student 概率低"的地方给出巨大惩罚
（被 `p_t · log(p_t/p_s)` 中的 `p_t` 加权）。蒸馏要的正是前者 ——
Student 应当继承 Teacher 的**完整行为分布**，而不是只学会其中一种走法。

写反了数值和训练行为都会变，但**不会报错**。验证方法很简单：

```python
forward = diagonal_gaussian_kl(tm, ts, sm, ss)   # 0.6363
reverse = diagonal_gaussian_kl(sm, ss, tm, ts)   # 1.6137
assert not torch.allclose(forward, reverse)      # 非对称性是 KL 的定义性质
```

### 数值保护

```python
t_d = teacher_std.clamp_min(1e-6)
s_d = student_std.clamp_min(1e-6)
```

`std = 0` 会让 `log(0) = -inf` 且除零得 `nan`。一旦 `nan` 进入梯度，
**整个网络的参数会在一次更新内全部变成 nan**，而训练看起来还在跑
（这与实践 2 里 `height_scanner` 打空射线产生 `inf` 是同一类静默失败）。

### 与 PPO 的 `desired_kl` 无关

| | 衡量什么 | 用途 |
|---|---|---|
| 蒸馏 KL | Student 与 **Teacher** 的分布差异 | 作为 loss 参与反传 |
| PPO `desired_kl` | **新旧策略**的分布差异 | 自适应调整学习率 |

同名不同物，不要混。

## 二、Teacher 必须 `no_grad`，即使参数已冻结

```python
with torch.no_grad():
    teacher_actions = self.actor.teacher_forward(batch.observations)
```

`StudentTeacherActor` 已经把 teacher 参数设为 `requires_grad=False`，
但仍要包 `no_grad`。原因：

1. 不加会为 teacher 的**中间激活**构建计算图并保留下来，白白占显存
2. 在某些共享模块的写法下，梯度可能被错误地引流回去

**Teacher 在这里的角色是数据源，不是网络。**

### 观测不要手动分发

Teacher 和 Student 吃的是**同一个** `batch.observations`，
各自在内部取自己需要的切片（Teacher 用带未来参考帧的特权观测，
Student 用只含当前帧的受限观测）。手动切分观测再分别喂进去，
正是助教点名的高频错误 —— 通常表现为维度错误或蒸馏静默失效。

## 三、KL Matching 里的一个顺序陷阱

```python
with torch.no_grad():
    teacher_mean, teacher_std = self.actor.teacher_distribution_params(batch.observations)
student_mean, student_std = self.actor.output_distribution_params   # ← 只读，不重新前向
```

`output_distribution_params` 是 actor 上一次前向留下的**状态**，
由 `DistillationPPO` 的主更新循环在调用本方法前刚写入。

**若在这里再调一次 `self.actor(...)`，会覆盖掉那次前向的分布参数**，
导致 PPO 的 surrogate loss 与蒸馏 loss 基于不同的前向结果 —— 二者不再一致。
所以这里只读不算。

## 四、为什么系数必须退火

```python
λ = linear_anneal(start, end, num_updates, anneal_iters)
```

| 阶段 | λ | 效果 |
|---|---|---|
| 初期 | 大 | Student 主要模仿 Teacher，快速获得可用策略 |
| 后期 | 小 | 让 PPO 的环境回报主导，Student 适应自己受限的观测 |

**关键在于信息不对称**：Teacher 看得到未来 20 帧，Student 看不到。
Student 永远无法完全复制 Teacher 的动作 —— 硬压着它去匹配，
反而**阻止它学出"只有当前帧时该怎么办"的补偿策略**。

> 蒸馏过强限制 Student 适应受限观测，过弱则得不到有效指导。

退火用 `num_updates`（参数更新次数）而非环境步数计数：
这样改 `num_envs` 或 rollout 长度时 schedule 的语义保持不变。

KL Matching 退火到 `kl_coef_min` 而非 0，保留一个下限意味着即使训练后期
也维持轻微的分布约束，防止 Student 在 PPO 回报驱动下漂移到完全不同的行为模式。

## 五、诊断指标：loss 之外还要看什么

三个工具函数（TODO 3、5）全部包在 `no_grad` 里并用 `.item()` 取出 Python float，
彻底切断计算图。**忘了 detach 会把整张图挂在 metrics 字典里不被释放，显存缓慢泄漏。**

### Action Matching

| 指标 | 作用 |
|---|---|
| `Loss/bc` | MSE 被平方放大过，数值不直观 |
| `action_mae` | 与动作**同量纲**，直接回答"平均差多少" |
| `action_rmse` | 对大偏差更敏感 |

MAE 与 RMSE 一起看能判断误差是**均匀分布**还是被**少数离群点主导**。

### KL Matching

把 KL 这个标量拆成两个可解释的分量：

| 指标 | 含义 |
|---|---|
| `mean_rmse` | 两个分布中心差多远 —— "平均动作"学得像不像 |
| `std_rmse` | 两个分布宽度差多少 —— "探索程度"是否匹配 |

单看 KL 无法区分这两种失配。常见现象是 mean 已经贴得很近、
但 `student_std` 明显偏大（Student 因观测受限而保留了更多不确定性），
此时 KL 仍然不小，**却不代表动作学得差**。分开看才能定位问题。

> 又一次印证实践 2 的教训：只看总 loss 会错过任务层面的真实表现。
> 作业讲解也明确要求"不要只观察总 reward"，最终还要在 Viser 中
> 检查跟踪连续性、摔倒情况和转向动作质量。

## 六、Action Matching vs KL Matching

| | 对齐对象 | 传递的信息 |
|---|---|---|
| Action Matching | 分布的**均值** | Teacher 在每个状态下"做什么" |
| KL Matching | **完整高斯**（μ + σ） | 额外传递 Teacher 的**不确定性结构** |

KL 多传的那部分是：Teacher 在哪些状态下也拿不准、该保留多大探索幅度。
这个信息对 Student 后续用 PPO 继续改进很有价值。

**实现顺序建议先 Action Matching 再 KL Matching**：
前者监督目标直接、loss 好解释，能快速验证 Teacher/Student 的输入输出是否正确；
在此基础上再做 KL，分析"只匹配动作"与"匹配完整分布"的差异。

## 训练结果对比

两组各跑 3000 iter × 4096 env，共享同一个 Teacher checkpoint 与同一份受限 Student 观测。

复现：`python scripts/compare_p6_distill.py`

### ⚠️ 先说清楚：这不是严格的单因素对照

除蒸馏目标外，两组还有三处超参不同：

| 超参 | action_matching | kl_matching |
|---|---|---|
| `learning_rate` | 5e-4 | 3e-4 |
| `entropy_coef` | 0.0025 | 0.005 |
| `desired_kl` | 0.005 | 0.008 |

**所以下面的差距不能归因到蒸馏目标本身**，只能读作
"各自在其调好的超参下能达到什么水平"。要做因果结论，必须先对齐这三项再重跑。

> 这一条与实践 4 的做法形成对照：那里三组共用同一份 `rl_cfg` 和 `seed`，
> 唯一变量是一处配置差异，所以结论可以直接归因。
> 对照实验的价值完全取决于"是否真的只差一个因素"，
> 而这一点必须在训练**之前**逐项核对，事后无法补救。

### 蒸馏 loss：只看各自趋势，不可横向比大小

两组 loss 定义不同（MSE vs KL），量纲不可比：

| 组别 | loss | 首值 | 末值 | 降幅 |
|---|---|---|---|---|
| action_matching | `bc` | 0.5856 | 0.0437 | 93% |
| kl_matching | `kl` | 44.3022 | 2.0149 | 95% |

两者都收敛良好。**但蒸馏 loss 降下去不等于学生学得好** ——
它只说明学生在模仿教师的输出，不说明它在环境里表现如何。
这与实践 2 的教训同源：训练侧指标好看不代表任务学会了。

### 可比判据：学生自己的跟踪质量

| 指标 | action_matching | kl_matching | 更优 |
|---|---|---|---|
| 关节位置误差 | 0.4941 | **0.3884** | KL |
| 身体位置误差 | 0.0771 | **0.0697** | KL |
| 身体姿态误差 | 0.1692 | **0.1322** | KL |
| anchor 位置误差 | 0.5463 | **0.3376** | KL |
| 平均 episode 长度 | 196.0 | **196.4** | KL |
| 超时占比（越高越好） | 0.9899 | **0.9971** | KL |
| **失败占比**（越低越好） | 0.0101 | **0.0029** | KL |
| 策略噪声 std | **0.2942** | 0.2162 | AC |

KL matching 在**所有**跟踪指标上更优，关节误差低 21.4%，
失败率低 3.5 倍（0.29% vs 1.01%）。

### 收敛过程

```
iter    action_matching   kl_matching
0            0.5290         0.5290
500          0.6417         0.5294     ← AC 先变差
1000         0.6091         0.4579
1500         0.5625         0.4208
2000         0.5356         0.4030
2999         0.4897         0.3878
```

`action_matching` 在前 500 iter **先劣化**（0.529 → 0.642）再缓慢回落，
到 3000 iter 仍未回到起点水平；`kl_matching` 则单调下降。

这个现象与本文第一节讨论的 KL 方向性一致：
只对齐动作**均值**丢掉了教师分布的宽度信息，学生不知道教师在哪些状态下
"其实不太确定"，于是在这些状态上过度自信地照抄均值。而 KL 对齐保留了
完整的高斯，学生能学到"该谨慎的地方要谨慎"。
末值 `Policy/mean_std` 也印证了这点：KL 组 0.216 明显低于 AC 组 0.294，
说明它对自己的动作更有把握。

> 但仍需强调：**上述解释与超参差异这两个因素目前是混在一起的**。
> 这个结果足以作为"值得进一步验证的假设"，不足以作为结论。
