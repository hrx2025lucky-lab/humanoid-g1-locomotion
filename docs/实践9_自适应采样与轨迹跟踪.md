## 一、自适应采样：对着难点重点练

朴素做法是每次 reset 都从动作开头播放。问题是一段舞蹈里难度分布极不均匀 ——
可能 80% 的帧很好跟，只有某个转身或跳跃反复摔。均匀重放会把绝大部分采样
浪费在已经学会的片段上。

自适应采样把整段动作切成 `bin_count` 个时间区间，**统计每个区间的失败次数，
失败多的区间获得更高的起始帧采样概率**。

```
失败计数 F  →  + 均匀项 ρ/N  →  卷积平滑  →  归一化  →  multinomial 采样 bin
                                                              ↓
                                                    bin 内加 [0,1) 随机偏移 → 帧号
```

### 四个设计要点

**均匀探索项 `ρ/N`** —— 保证任何 bin 概率都不为 0。否则一个从未失败过的
区间永远不会被采到，策略会逐渐**遗忘**那段动作（catastrophic forgetting）。

**卷积平滑** —— 失败是稀疏事件，某个 bin 失败往往意味着它前后一小段都不好走。
把热度向邻域扩散，训练才会覆盖整个困难区段而不是死磕单帧。
核是几何衰减序列 `λ^i` 且已归一化，**只在右侧 padding** ——
核代表"当前 bin 对后续 bin 的影响"，是因果的。

**bin 内随机偏移** —— 没有它，所有落在同一 bin 的环境会从完全相同的帧起步，
采样多样性退化成 `bin_count` 个离散点。

**EMA 更新失败热度** —— 而不是直接累加：

```python
bin_failed_count = α · current_failures + (1 - α) · old_failures
```

策略在进步，早期的失败记录会过时。一直累加会让采样长期困在
"曾经很难但现在已经学会"的片段上。

## 二、两个把我卡住的数值细节

单元测试是**精确数值匹配**（固定随机种子），任何实现差异都会暴露。

### bin 宽度必须用整数除法

```python
bin_width = self.motion.time_step_total // self.bin_count    # ✅
bin_width = self.motion.time_step_total /  self.bin_count    # ❌
```

实测（`total=5, bin_count=2`）：

| | bin=1, offset=0.744 | 结果 |
|---|---|---|
| 浮点宽度 2.5 | `(1+0.744)×2.5 = 4.36` | → 4（期望 3）|
| 整数宽度 2 | `(1+0.744)×2 = 3.49` | → 3 ✅ |

用浮点会让末尾 bin 的采样帧越界到 `total-1` 之外再被 `clamp` 压回来，
**使最后一帧获得异常高的采样概率** —— 分布被扭曲且难以察觉。

### `top1_bin` 是归一化位置

```python
self.metrics["sampling_top1_bin"][:] = top1_bin.float() / self.bin_count
```

期望值是 `0.5` 而不是 `1`（`bin_count=2` 时 `argmax=1`）。归一化后表示
"最难的片段在整段动作的什么位置"（0=开头，接近 1=结尾），与动作总长无关，
便于跨实验对比。同理熵也除以 `log(bin_count)` 归一到 `[0,1]`。

验算：`p=[0.04545, 0.95455]` → `H=0.1849`，`H/ln2=0.26676` ✅ 与期望一致。

## 三、参考动作的对齐：只对 z 和 yaw

`_update_command` 每步把参考动作"对齐"到机器人当前的位置与朝向，
否则参考轨迹固定在世界原点，机器人一旦偏离就再也追不上。

**但对齐是有选择的**：

```python
delta_pos_w = robot_anchor_pos_w.clone()
delta_pos_w[..., 2] = anchor_pos_w[..., 2]        # 只替换 z

delta_ori_w = yaw_quat(quat_mul(robot_anchor_quat, quat_inv(anchor_quat)))
                                                   # 只保留 yaw
```

| 维度 | 处理 | 原因 |
|---|---|---|
| x / y | **跟机器人** | 不要求走到参考轨迹的绝对坐标（那等于同时考核导航），只要求"就地把动作做对" |
| z | **跟参考** | 否则蹲下/跳起这类高度变化无从考核 |
| yaw | **跟机器人** | 朝向是自由的 |
| roll / pitch | **跟参考** | 这是机器人自己的平衡姿态，属于被考核内容；一并对齐就等于把姿态误差抹掉了 |

**如果 roll/pitch 也对齐，跟踪奖励会失去意义** —— 机器人怎么歪都算"对齐后一致"。

## 四、P2 的 7 类曲线（通用诊断资产）

作业讲解给了一张表，适用于所有 RL 训练：

| 指标 | 健康趋势 | 异常信号 |
|---|---|---|
| `mean_episode_length` | 上升后平台 | 长期很短：频繁早停 |
| `motion_body_pos` reward | 上升后平台 | 抖动大：接触/尺度问题 |
| `time_out` | 上升 | 不上升：异常失败仍多 |
| `sampling_entropy` | **先降后回升** | 长期接近 0：采样塌缩 |
| `sampling_top1_bin` | 移动、无固定点 | 长期不动：同一片段持续失败 |
| `error_joint_pos` | 下降后平台 | **奖励升但误差不降：查定义** |
| `Policy/mean_std` | 下降但非 0 | 过早贴 0：停止探索 |

`sampling_entropy` "先降后回升"很有意思：训练早期采样会自动聚焦到困难片段
（熵下降），学会之后失败热度被 EMA 冲淡，采样重新铺开（熵回升）。
**长期贴 0 说明卡死了**，此时应检查 termination 是否过严。

> `error_joint_pos` 那条正是我们在实践 2 踩过的坑：
> reward 一路上升而 `error_vel_xy` 从 0.135 涨到 0.615，
> 机器人实际在原地踏步。

## 五、调试顺序（讲解明确给出）

```
先核对 shape / device / dtype  →  再核对公式  →  最后核对固定种子下的数值
```

配套的坑位表：

| 现象 | 常见原因 | 快速检查 |
|---|---|---|
| `bincount` 长度不对 | 未设 `minlength` | 结果恒为 `(bin_count,)` |
| 概率全 0 / 含 NaN | 忘加均匀项或归一化 | `p≥0` 且 `p.sum()==1` |
| 采样帧越界 | 用了 `T` 而非 `T−1`；未 clamp | `0≤t<T`，dtype 为 `long` |
| 目标骨架漂移/侧倒 | 漏 `env_origins`；四元数/yaw 错 | 单位四元数最小例子 |
| 跨框架属性错误 | 混用 `body_link_*` 与 `body_*` | 先过 Test 0 |

最后一条值得注意：IsaacLab 路线用 `robot.data.body_pos_w`，
MJLab 路线用 `robot.data.body_link_pos_w`。**两条路线不要混装。**
