# 课程 PDF 的解密与提取

> **2026-09-04 重大更正**：本文件早先版本（原名《课程材料可读性边界》）写着
> "课件 PDF 完全读不到，只能人工翻阅"。**这个结论是错的**——
> 425 页课件现已全部可读，含图表。错误的排查过程记在文末，教训比结论值钱。

## 一句话结论

课程 PDF 确实被深蓝学院加密（文件管理器里带锁图标），
但 **Python / Perl 读同一个文件会得到解密后的内容**，bash 工具则读到密文。
用 Python 整读再另存，就得到一份完全正常的 PDF。

```bash
python scripts/decrypt_course_pdfs.py --scan            # 体检
python scripts/decrypt_course_pdfs.py                   # 解密 + 提取文字
python scripts/decrypt_course_pdfs.py --render 第7章    # 课件转 PNG
```

产出在 `~/course_materials/`：`pdf/`（解密件）、`txt/`（文字）、`images/`（页面图）。

## 那个反常现象

同一个 inode、同一个大小，两种读法得到两种内容：

```
$ head -c 4 课件.pdf                                → TSZ#      （密文）
$ cat / dd / od                                     → TSZ#      （密文）
$ python -c "print(open('课件.pdf','rb').read(4))"  → b'%PDF'   （明文）
$ perl -e '...read(F,$b,4)...'                      → %PDF      （明文）
```

验证过 inode 相同（45926202）、大小相同（16505347），
并且把 Python 读到的内容 dump 成新文件后，
**bash 再读这个 dump 就是正常的 `%PDF-1.7`**。

机制没深究（大概率是某个 DRM 驱动按进程做透明解密）。
不影响使用：脚本用 Python 读、Python 写，一步到位。

## 两类 PDF，处理方式不同

| 类型 | 份数 | 页数 | 字体数 | 处理 |
|---|---|---|---|---|
| 作业 PDF（实践 1~11） | 13 | 17~32 | 179~339 | ✅ `pdftotext -layout` |
| 作业讲解 PDF | 9 | 2~19 | 2~10 | ✅ 同上 |
| **课件 PDF（第 2~8 章）** | **7** | **共 425** | **0** | ⚠️ 每页一张 1209×680 图片，需渲染成 PNG 后看图/OCR |

课件是 **0 个字体**——不是加密导致提取失败，而是幻灯片被整页转成了图片，
本来就没有文字层。**这两件事此前被我混为一谈。**

渲染后可直接阅读，图表也清晰：

```bash
python scripts/decrypt_course_pdfs.py --render 第7章 --pages 1-10
# → ~/course_materials/images/深蓝学院-...-第7章-课件_学员版/page-01.png ...
```

`--dpi` 默认 150。原图内嵌 192 ppi，再高只是插值放大不增信息；
太低则中文小字糊掉。单页约 90~200 KB。

## 公式提取质量

解密后用 `pdftotext -layout`，公式的**空间布局得以保留**，可正确还原：

```
                         1
q(D (x)) = max (0, 1 − (D (x) − 1) )
   ψ                           ψ
                                           2
                         4
```

读作 `q(D_ψ(x)) = max(0, 1 − ¼(D_ψ(x)−1)²)`——
分子 1 在上、分母 4 在下、平方 2 在右上、下标 ψ 在正下方。

对比早先那份没走 `-layout` 的结果：

```
q(D
(x)) =ψ max 0, 1 −
(D
(x) − 1)( 4
1
ψ 2)
```

符号全在但顺序全乱，无法可靠还原。**`-layout` 参数是关键。**

> 即便如此，关键公式仍建议交叉验证：优先看代码里的参考实现，
> 或直接渲染那一页看图。

## 教训：三个错误叠在一起

我一度给出结论"所有 PDF 都是 DRM 加密无法提取，课件完全读不到"。
它由三个独立错误叠成：

1. **只用 bash 工具做检测**。`head -c 4` 看到 `TSZ#` 就下定论，
   没试过其它读取方式——而 bash 恰恰是唯一读不到明文的那类。
2. **没搜现成副本**。上一个会话早已用 Python 提取过 29 份文本，
   我却只对 `.pdf` 原文件反复尝试。
3. **把两个独立原因混为一谈**。课件提取为空的真实原因是"没有文字层"，
   与加密无关；但因为认定加密是障碍，就没再往下查。

**转折点**：注意到一个矛盾——如果文件真读不了，
提取器不可能正确数出 51 页（与阅读器显示完全一致）。
顺着这个矛盾查才发现真相。

**方法规则**：

- 判定"读不了"之前，至少换两种工具验证（bash / Python / Perl 表现可能完全不同）
- 先全盘搜同名副本 `find / -iname "*关键词*"`，再判断原始格式
- **出现自相矛盾的证据时优先追矛盾**，不要挑一个符合预期的相信
