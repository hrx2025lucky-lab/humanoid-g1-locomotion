# 实践 2 奖励函数调参记录

> 第一次训练（10000 iter）跑出了一个"站着不动"的策略。这份文档记录从发现症状、
> 定位根因到修改权重的完整过程，重点在**为什么**每个权重是这个值。

---

## 一、症状

第一次训练跑满 10000 iter，从常规指标看**像是成功了**：

| 指标 | @2561 | @9999 | 看起来 |
|---|---|---|---|
| Mean episode length | 489.76 | **960.44** | 接近满分 1000 |
| `time_out` 占比 | 0.1427 | **0.9064** | 90% 是正常超时结束 |
| `bad_orientation` 占比 | 0.8573 | **0.0936** | 几乎不摔了 |
| Mean reward | 7.14 | **26.32** | 涨了 3.7 倍 |

录像却拍出了完全不同的东西：**机器人站在原地踏步，11.98 秒净位移不到 0.3 米。**

判读方法：play 相机锁定在 0 号机器人身上（`viewer.origin_type="asset_root"`），
机器人恒在画面中心，所以**背景的位移就是机器人的位移**。对比第 5 帧和第 598 帧，
背景台阶只偏移了约 30~40 像素；台阶在 8 米开外，折算下来位移 < 0.3 m。

**教训一：`episode length` 和 `reward` 涨了不代表任务学会了。**
这两个指标只说明"活得久"和"总分高"，不说明"在做我们想要的事"。

## 二、诊断：三个证据

### 证据 1 — 速度跟踪误差在**变大**

```
Metrics/base_velocity/error_vel_xy
  @2500 = 0.135    @5000 = 0.293    @7500 = 0.434    @末 = 0.615
```

单调上升。原因是 `lin_vel_cmd_levels` 课程在升档（0.1 → 0.5），指令越给越大，
而策略的实际速度基本没变，误差自然同步放大。**课程升了，能力没跟上。**

### 证据 2 — 主任务奖励早就见顶了

```
Episode_Reward/track_lin_vel_xy
  @2000=0.384  @4000=0.600  @6000=0.625  @8000=0.544  @9990=0.628
```

4000 iter 就到 0.600，之后 6000 次迭代只挪动 0.028，中间还因为指令升档倒退到 0.544。
**这条曲线早已进入平台期，再训 5000 次也不会变。**

反解一下跟踪误差：奖励形式是 `exp(-e²/std²)`，`std²=0.25`，
`exp(-e²/0.25)=0.628` → `e ≈ 0.34 m/s`。这和指令本身的幅值同量级，等于没在跟踪。

**教训二：判断"要不要继续训"，看主任务奖励的斜率，不看 reward 总值。**

### 证据 3 — 把所有奖励项拆开看

这是最关键的一步。按 `Episode_Reward/*` 全部列出终值（单位：每秒平均）：

```
feet_clearance       +0.8228   ← 第一大正奖励
track_lin_vel_xy     +0.6355   ← 主任务，上限只有 1.0
gait                 +0.5014   ← 上限就是 0.5，等于拿满
alive                +0.1448   ← 上限 0.15，拿了 96.5%
────────────────────────────
action_rate          -0.4281   ← 以下惩罚**只在动起来时才产生**
joint_vel            -0.1334
joint_deviation_arms -0.1228
joint_deviation_legs -0.0890
...
正奖励合计 +2.3273   惩罚合计 -0.9873   净 +1.3400
```

**站着不动，光靠 `feet_clearance + gait + alive` 就能白拿约 1.47，且几乎不付任何惩罚。**

## 三、根因：奖励函数把"站着"设成了最优解

### 3.1 两个"站着也能拿满分"的漏洞

**`foot_clearance_reward`（拿了 0.8228）**

```python
foot_z_target_error = (foot_z_world - target_height) ** 2
foot_velocity_tanh  = tanh(tanh_mult * ‖foot_vel_xy‖)     # ← 关键
reward = foot_z_target_error * foot_velocity_tanh
return exp(-sum(reward) / std)
```

设计意图是"只要求**摆动腿**抬够高，支撑腿不管"，所以乘了一个脚的水平速度项。
副作用是：**脚不动 → `tanh(0)=0` → 整个惩罚为 0 → `exp(0)=1.0` 满分。**
静止是这一项的全局最优。

**`feet_gait`（拿了 0.5014，上限 0.5）**

```python
is_stance = leg_phase[i] < 0.55        # 按 0.8 s 固定周期算的应然相位
reward += ~(is_stance ^ is_contact[i]) # 应然与实然一致就 +1
```

双脚长期着地时，相位 < 0.55 的那 55% 时间里"应该着地且确实着地"，照样得分。
算下来静止能拿约 0.55/1.0，我们实测 0.5014，吻合。

### 3.2 惩罚项的不对称性

`action_rate`、`joint_vel`、`joint_acc`、`feet_slide`、`energy` 这些惩罚项
**全部与运动量成正比**。站着不动 → 全部接近 0。

于是策略面对的实际选择是：

| | 正奖励 | 惩罚 | 净 |
|---|---|---|---|
| 站着不动 | ≈ 2.1（clearance + gait + alive + 小指令下的 track） | ≈ 0 | **≈ 2.1** |
| 努力行走 | track 最多再多拿 **0.36**（0.64→1.0 上限） | 付出全部动作惩罚 | 更低 |

**走路的边际收益上限只有 0.36，边际成本却是全套动作惩罚。理性策略当然选择站着。**

**教训三：奖励函数里，"什么都不做"往往是一个隐藏的强势策略 ——
因为绝大多数惩罚项都是对"做事"收费的。设计奖励时必须检查这个基线。**

## 四、修改方案与逐项原理

权重取自课程《人形机器人运动控制第二章作业讲解》p5/p6 的推荐表。
核心思路不是"把奖励调大"，而是**改变边际激励比**。

### 4.1 `track_lin_vel_xy` 1.0 → 3.0，`track_ang_vel_z` 0.5 → 2.0

最关键的一项。奖励形式 `exp(-e²/std²)` 值域是 `(0, 1]`，
**权重就是这一项的上限**。

- 改之前：跟踪从 60% 提升到 100%，只多拿 `1.0 × 0.4 = 0.4`
- 改之后：同样的提升多拿 `3.0 × 0.4 = 1.2`

1.2 足以盖过 `action_rate`（-0.43）等惩罚的增量，走路从此"有利可图"。
官方参考曲线该项终值 **2.2626 / 3.0**（约 75%）。

> 注意：`std` 保持 `sqrt(0.25)` 不变。`std` 决定的是"多大误差算差"的**尺度**，
> `weight` 决定的是"这件事有多重要"的**量级**。这次要改的是重要性，不是尺度。

### 4.2 `gait` 0.5 → **0**（关闭）

两个理由：

1. **课程给的理由**：粗糙地形上机器人需要临时改步频、延长某只脚的支撑时间来
   救失衡，甚至出现不对称的恢复动作。固定 0.8 s 周期的相位奖励是一种束缚。
2. **我们自己发现的理由**：它是"站着不动"的第二大收益来源（0.5014）。

用 `weight = 0` 而不是删除该项 —— `RewardManager` 不会跳过零权重项，
TensorBoard 里仍然可见（恒为 0），方便和上一次训练对照。

### 4.3 新增 `feet_air_time` = +0.5

**整个奖励函数里唯一直接给"迈步"发钱的项。**

```python
single_stance = (着地的脚数 == 1)
reward = min(单脚支撑时间) if single_stance else 0
reward = clamp(reward, max=threshold)
reward *= (‖cmd_xy‖ > 0.1)        # 零指令不发钱
```

- 双脚同时着地（站立）→ `single_stance=False` → **0 分**
- 双脚同时腾空（跳跃）→ 同样 0 分
- 只有交替迈步才得分

天然反"原地不动"，且不会鼓励空踏步（零指令时被掩掉）。
`threshold=0.5` 给腾空时间封顶，防止策略靠"单腿长时间悬空"刷分。

### 4.4 新增 `stand_still` = -1.0

```python
reward = Σ|q - q_default|
return reward * (‖cmd‖ < 0.1)     # 只在低速指令下生效
```

配负权重 = "指令接近零时，偏离默认站姿要挨罚"。

**它的作用不是让机器人更爱站着，恰恰相反**：它把"停"定义成一个具体姿态，
让"走"和"停"成为两个**可区分**的模式。缺了它，策略完全可以用同一套
原地小幅摆动去应付所有指令 —— 这正是第一次训练的失败形态。

### 4.5 `feet_clearance` 换成相对地形高度的版本

```python
官方: (foot_z_world          - target_height)²
改后: (foot_z_world - ground - target_height)²
```

`target_height=0.1` 在官方实现里是**世界系绝对高度**。平地上地面 z≡0，
"脚在世界里 0.1 m"和"脚离地 0.1 m"是同一件事；换到粗糙地形就不成立：
站在 0.3 m 高的台阶上，脚正确地抬到离地 0.1 m（世界系 0.4 m），
公式却算出 `(0.4-0.1)² = 0.09` 的误差并施加惩罚。**地形越高，正确动作被罚得越狠。**

权重维持 1.0，只修基准。`ground` 由 `height_scanner` 估计，
复用 Step 3 已有的 `ground_height_from_scan`（带 inf 防护）。

### 4.6 姿态约束加严

```
joint_deviation_arms    -0.1 → -0.5
joint_deviation_waists  -1.0 → -2.0
joint_deviation_legs    -1.0 → -2.0
base_height            -10.0 → -20.0
```

前三项：粗糙地形上手臂/腰乱摆会显著抬高重心晃动，让 `height_scan` 的观测
和真实落脚点失配。

`base_height` 加倍是**配合 4.1 的必要防守**：`track` 权重提到 3.0 之后，
机器人可能发现"弓身下蹲"能降低重心、更容易跑快拿分。加大高度惩罚堵住这条捷径。

> 这是调参里的常见结构：**放大一个激励时，要同时检查它会不会打开新的作弊路径。**

## 五、录像方式的修正

第一次录像用 `--video_length 600`，只拍到 60%。

```
episode_length_s = 20.0 s      (velocity_env_cfg.py:377)
step_dt          = 0.02 s      (decimation 4 × sim dt 0.005)

```

并自动挑选最新 run 的最新 checkpoint（按数字排序，避免 `model_9999` 排在 `model_10000` 之后）。

不必再靠背景像素偏移倒推。

## 六、复习要点

1. **`episode length` 和 `reward` 上升，不等于任务学会了。**
   必须回到任务本身的度量（这里是 `error_vel_xy` 和录像）。

2. **判断"要不要继续训"，看主任务奖励的斜率。**
   `track_lin_vel_xy` 在 4000 iter 就进入平台期，再训是浪费。

3. **诊断的决定性一步是把 `Episode_Reward/*` 全部拆开排序。**
   总分正常时，分项能暴露出策略实际在靠什么拿分。

4. **"什么都不做"是奖励函数里的隐藏强势策略。**
   因为几乎所有惩罚项都是对"做事"收费的。设计完奖励，
   先问一句："如果它一动不动，能拿多少分？"

5. **exp 型奖励的权重 = 该项的上限**，直接决定它能提供多大的边际激励。

6. **放大一个激励时，同步检查是否打开新的作弊路径**（如 track↑ 引发弓身下蹲 → base_height↑ 防守）。

7. **世界系绝对高度的判据，换到非平地一律要重新审视。**
   本实践里 `base_height`（奖励+终止）和 `feet_clearance` 三处都栽在这上面。
