### 实践01｜仿真环境与行走策略部署

Isaac Lab（训练）+ MuJoCo（跨仿真验证）· PPO

在 Isaac Lab 里训好的策略，搬到 MuJoCo 不一定还能走。不是算法的问题，是一堆接口对不上：两边关节的排列顺序不一样，网络吐出来的数也不是关节角度，得先乘个系数再加上默认姿势才是目标角。控制频率和 PD 参数只要有一处没对齐，同一个网络走出来的步态就变样。

验证分两步。先拿同一批观测分别喂给训练时的权重和导出后的模型，看输出对不对得上，确认导出没丢东西；再跑一段固定指令的闭环回放，看它在 MuJoCo 里是不是真的能走。

有一件事没做完：同一份权重在两个仿真器里跑同一段指令、逐帧比轨迹。所以我只能说链路是通的，不能说两边的动力学一致。

尚无展示视频。[项目详情](practices/01_simulation_baseline/README.md)

### 实践02｜感知驱动的粗糙地形行走

Isaac Lab · PPO · 高度扫描 · MuJoCo

平地能走的策略，上台阶就摔，因为它根本不知道前面有台阶。解法是在机器人脚下布一圈射线去量地面高度，把这些高度值接进观测，让它提前看到地形起伏。

听着简单，做的时候栽了两次。高度一开始我用的绝对值，结果机器人一抬腿整张高度图跟着漂，网络学到的全是噪声，换成相对机身的高度才对。另一次是射线打空，那种情况返回的不是数字，直接进网络会把整个观测污染掉，得先筛一遍。另外策略侧要加噪、价值网络不加噪，两条路分开配。

改完以后在原策略基础上又训了一轮做适配。评估是拿若干组一模一样的初始状态，新旧策略各跑一遍比，新的在速度和转速上都更准，也走通了一段台阶。

不过这是固定场景下的结果，转弯还是跟不太住，走直线也会往侧边飘。而且这轮改动里既有新训练也有终止条件的修改，改善到底该算谁的，我没法拆开。

### 实践03｜HoST仰躺起身（预训练策略部署）

HoST 预训练策略 · PD 控制 · MuJoCo

这一项没训练，是把别人训好的起身策略接进 MuJoCo 跑起来。

麻烦在于它的动作空间和常见的不一样：网络输出的不是"关节应该转到多少度"，而是"比上一帧多转多少"，得自己一帧帧累加。观测那边是好几帧历史拼在一起的一长串，关节顺序、时钟推进节奏，任何一处对错位机器人就起不来。这些都得照着原实现一项项核。

接对之后，机器人能从仰躺姿势自己翻起来站住。另外录了一段对比动画，展示如果按普通的绝对角度接口去接会是什么样。

只测了默认的仰躺姿势。换成别的跌倒姿态能不能起来，没试过；HoST 本身我也没有自己训。

### 实践04｜速度与骨盆高度联合控制

MJLab · PPO · 双指令控制

平常的行走任务只有一个指令：走多快。这一项加了第二个：骨盆保持多高。两个指令一起给，机器人就得学会一边压低身子一边往前走，也就是蹲着走路。

做法是训练时随机给高度指令，和速度指令一起拼进观测，再加一项奖励去惩罚高度偏差。能走出来之后我想确认一件事：效果到底是不是来自这条链路，会不会只是训练久了碰巧学会的。于是拆成两组消融，一组把高度奖励拿掉，一组把 Actor 能看到的高度指令拿掉，其余全部相同、预算也相同。两组都做不到按指令改高度，这才算说清楚。

限制是这只有一个随机种子、只在平地上跑过，朝向和左右位置都还会漂。后来加了朝向反馈，角度是稳了，但横向位置一直没做闭环。

### 实践05｜分层强化学习导航

Isaac Lab · 高层 PPO + 冻结的低层行走策略

思路是分工：底下那层已经会走路了，就把它冻住不动，只训上面一层。上层看目标点在哪，告诉下层"往这个方向以多快走"，至于腿怎么迈，上层不管。

这里最容易栽的是两层之间的接口。下层训练时用的观测配置必须原样深拷贝过来，我一开始是照着手写重建的，看上去一模一样，跑起来就是不对。噪声设置和历史长度这些细节对不上，下层拿到的输入和它训练时见过的不是一回事。

这一项本来想验证一个假设：用随机布局训练的上层，换到没见过的场景应该表现更好。做了成对实验，两个模型、两类场景、三个种子，每组都跑完整轮。

结果是没有。两者的成功局数基本一样，看不出随机布局有优势。这个结论我按原样写在这里，没有换个说法包装它。

### 实践06｜教师学生蒸馏：Action与KL对比

MJLab · PPO · Action Matching / KL Matching

仿真里有些信息真机上拿不到，比如机身的真实速度。训练时可以让"教师"用上这些特权信息学得又快又好，但教师本身没法部署。所以要再训一个"学生"，它只能看真机上有的东西，靠模仿教师把本事学过来。

模仿的方式有两种，这一项把它们放在同样的预算下比了一次。一种是直接学教师的输出动作，让两者数值尽量接近；另一种是让学生输出的整个概率分布去逼近教师的分布。后者用 KL 散度衡量差距。

结果是两个学生都能把动作库里的动作完整跟完，姿态误差也差不多。放到世界坐标下看，KL 那个反而还差一点。

有一点必须说清楚：拿来测试的动作全都在训练库里，不是没见过的新动作。所以这只能说明两种方法都学会了，不能拿来证明泛化能力。

### 实践07｜人体到G1的运动重定向

GMR · SMPL-X · 逆运动学，不含强化学习

想让机器人学人的动作，得先有人的动作数据。但人的骨架比例、关节数量、每个关节能转的方向都和 G1 不一样，动捕数据不能直接用。

这一项就是做转换：坐标系朝向怎么对齐、四元数的四个分量按什么顺序存、关节叫什么名字排第几位、帧率不一样怎么重采样、最后存成什么格式。全是琐碎但错一处就全崩的活。做完之后我特意反过来验了一遍下游：把产出的文件丢给实践 08 的数据加载器，确认能直接读进去，顺序也没错位。

视频里机器人在走路，但它其实没在"走"。那是把关节角度直接写进仿真的回放，不经过力矩控制。所以这些片段说明不了平衡能力，只能看动作映射对不对。片段也偏短，脚和地面的接触还有些问题。

### 实践08｜AMP拟人走跑与步态评估

Isaac Lab · PPO + AMP 对抗式动作先验 · G1 29 自由度

只用速度奖励训出来的机器人，速度是准的，但姿势很怪：僵硬、滑步、手臂乱甩。AMP 的办法是再加一个专门挑刺的网络，它一边看人类的真实动作、一边看机器人的动作，努力分辨哪个是机器人。机器人则想办法骗过它，骗得越像，风格奖励给得越多。

一开始机器人拖着腿走，怎么调都不好。查了很久才发现问题不在奖励权重上：判别器被一个稳定性保护机制全程掐住了，整轮训练下来它真正更新的次数一只手数得过来，风格奖励从头到尾卡在上限附近不动。等于那个"挑刺的网络"根本没在工作。解除之后抬脚高度立刻上来，拖腿和左右不协调一起消失了。还有个类似的坑是镜像损失，它的数量级比主目标大了近百倍，系数按默认的 1.0 给，机器人直接转过身去背对着走。

后面又花了十轮实验查剩下的步态问题，每轮开训前先把判定标准写死存档，免得跑完再找理由。延长训练、调风格和任务的配比、加关节速度惩罚、用框架自带的接触时序奖励，这四条路都试过，都不行。接触时序奖励那条还挺有意思：它其实可以被钻空子，机器人发现双脚一直贴着地也能拿分，于是双支撑不降反升。

真正管用的改动有两个。把判别器的梯度惩罚调高之后，摆臂方向修正了：原来是同手同脚，现在手臂和同侧的腿反着摆，换个随机种子还能复现。另一个是加了一项直接惩罚双支撑时长的奖励，占比从四成多掉到两成出头，进了正常人走路的区间。而且每只脚的摆动次数不降反升，说明不是靠单腿站着硬凑出来的，这个防作弊条件我在开训前就写进判据了。

整体还是没通过。门槛要求慢走和常速前进两个场景同时达标，目前没有模型能做到。问题在于航向和左右对称性是绑在一起的：双支撑压下去，单脚支撑的时间就变长，航向跟着歪；把航向权重提上去，航向是回来了，双支撑又涨回去，摆臂也变回同手同脚。三者互相拽着，暂时没解开。

### 实践09｜全身舞蹈轨迹跟踪

MJLab · PPO · BeyondMimic 方法

让机器人跟着一段两分钟的舞蹈跳完。长动作的麻烦在于中间只要有一处跟丢，后面就会一路崩下去。

对策是别平均地练。哪些片段老是失败，就让它们被抽到的概率高一些，多练几遍。另外相位怎么往前推、参考动作的坐标怎么对齐，都得处理好。

动作接口这边用的是"参考角度 + 策略修正量"，好处是能把两类误差分开看：姿势学得像不像是一回事，在世界里有没有跑偏是另一回事。对照组直接用参考角度做 PD、不给策略修正，撑不过一秒就倒了。

姿势是跟住了，但世界坐标下整个人在慢慢漂。没见过的动作和外力扰动都没测。还有一点要注意：完整视频用的播放条件和统计指标的那套不一样，不能拿画面直接当指标读。

### 实践10｜平台地形动作跟踪（HOI）

Isaac Lab · PPO · 高度扫描

在有平台的场景里跟踪全身动作。和纯动作跟踪的区别是：机器人得真的踩到平台上，而不是在空中把姿势比划对。所以要加地形感知，射线得和场景描述里的方块求交。

这一项此前最大的问题不是方法，是训练量。所选模型的规模离参考配置差着几个数量级，任何结论都站不住。后来补了一轮扩容训练，环境数和更新次数都提上去。为了不让自己事后挑好看的模型，评估用的存档在开训前就按固定间隔定好了。

扩容之后误差明显下降，而且世界位置、朝向、关节这三项是一起降的，不是某个指标碰巧好看。这样才能说"之前就是训练量不够"，在这之前那只是我的猜测。

但也还不算完整：本机显存扛不住参考配置的环境数，这轮仍然低于它。而且模型是从同一批候选里挑的，没有留一部分出来单独验证。

### 实践11｜深度感知与MuJoCo跨仿真验证

Project Instinct + MuJoCo（Sim2Sim）· PPO + 运动风格奖励

机器人靠一个深度相机看路过障碍。这里的深度图不能拿最新一帧直接用，得维护一个历史队列再从里面抽帧，模拟真实相机的延迟。图像本身还要缩放、裁剪、补空洞、模糊、归一化走一整套，我照着训练侧的定义补全，并写了单元测试逐项卡住形状和数值映射。

训好的策略导出成 ONNX 放进 MuJoCo，录了四组对照：参考策略和我自己训的，各跑平地和粗糙地形。参考策略在平地上一路走到底，骨盆高度也稳，说明我补的这套处理和整条链路是对的。粗糙地形上它爬上台阶后蹲住了，没摔，但也没完成跑酷。

我自己训的那个模型两种地形都几乎不动。当时我以为是跨仿真掉的，写在公开页上说"迁移落差约 28%"。后来扫了一遍指令才发现不是：回头看它在 Isaac 里的原生评估，速度误差和平均速度几乎一样大，意思是这个策略压根就没学会跟踪速度。不是 MuJoCo 把它弄坏的，是它本来就不行。那句话已经更正。

## 当前进展

做成的：双指令控制、两种蒸馏方式的对比、两分钟长动作跟踪、地形配对实验、平台路径跟踪。

没做成的有三项，我按原样写在这里。分层导航里随机布局训练没有显出优势；AMP 的自然摆臂和低速慢走过不了同一道门槛；自己训的深度策略搬到 MuJoCo 后几乎不动，跨仿真这一步不算成功。

每项结果我都留着当时的模型阶段、统计窗口、坐标系和初始状态限制。预训练部署、运动学回放和自己训练的，分开写清楚，没有混在一起说。具体数值和没覆盖到的场景，见各项目页。
