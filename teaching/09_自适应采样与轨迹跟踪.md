## 0. 一句话概括

要让 G1 机器人跟着一段舞蹈动作跳（`dance1_subject2.npz`，6574 帧 @ 50 fps）。
一段舞里有的段落好跟、有的段落（某个转身、某个跳跃）反复摔。
**如果每次都从头均匀重放，绝大部分算力会浪费在已经学会的简单段落上。**
自适应采样（adaptive sampling）干的事就一句话：**统计哪些片段常摔，
让机器人从这些"难点片段"附近多开局、反复练**——像学琴专挑弹错的小节练。

这个实践要补全两个核心函数（自适应采样 `_adaptive_sampling` + 参考动作对齐
`_update_command`），通过数值单元测试，再完整训练出一个能跳完舞的策略。

## 1. 问题从哪来（Why）

### 1.1 轨迹跟踪本身：让机器人"复现"一段参考动作

轨迹跟踪（motion tracking）= 给定一段参考动作（每一帧各个身体部位该在哪、
关节该转到哪），训练策略让真实机器人**逐帧复现**它。奖励就是"机器人当前姿态
和参考姿态有多接近"。这是人形运控里最基础也最关键的能力——先能精确复现，
才谈得上后面的泛化控制。

### 1.2 为什么均匀采样不够好（自适应采样存在的理由）

这是本实践最该讲透的一点，也是面试官会追问的"为什么不用最简单的均匀采样"。

**朴素做法**：每次环境 reset，都从动作第 0 帧开始播放。
**问题**：一段舞的**难度分布极不均匀**。假设 6574 帧里，80% 的帧是平稳走位、很好跟，
只有中间某个 300 帧的转身+跳跃组合反复摔。均匀重放意味着：

- 机器人绝大多数开局都在练那 80% 已经会的简单段落——**算力浪费**；
- 那个难点段落，每个 episode 只有很小概率播到，而且**得先撑过前面几千帧不摔**
  才能到达它——**难点样本极其稀缺**。

结果就是：简单段落练到烂熟，难点段落**永远样本不足、学不会**。整段动作卡在那个转身上。

**更糟的一层**：难点段落往往在动作中后段。均匀从头播，机器人早期策略差，
可能撑不到中段就摔了，**根本采集不到中后段的训练数据**——这叫"探索的地平线问题"。
你想练第 4000 帧的跳跃，可它 500 帧就摔了，那 4000 帧附近的经验一条都收不到。

**自适应采样的解法**：**直接从难点片段附近开局**。不用"从头撑过去"，
而是把机器人**空投**到"经常摔的那 300 帧"起点，反复在那里练。
这样难点样本从"稀缺"变成"管够"，中后段也不再依赖"前面别摔"这个前提。

> 一句话：均匀采样把练习均摊到所有片段，但**难度不是均匀的**，
> 于是简单的过度练、难的练不到。自适应采样把练习**按难度重新分配**。

### 1.3 为什么不能只练难点、彻底放弃简单段落？

反过来的极端也不行：如果只采难点，机器人会**遗忘**已经学会的简单段落
（catastrophic forgetting，灾难性遗忘）。所以自适应采样不是"只练难的"，
而是"**难的多练、简单的也保底练一点**"——下面 2.2 的均匀探索项就是干这个的。

## 2. 核心概念（零基础可懂）

### 2.1 bin：把整段动作切成时间区间

**生活化类比**：把一首曲子按小节划分，你统计"每个小节弹错几次"，
而不是精确到"第几个音符"。小节就是 bin。

**严格定义**：把整段动作的 `time_step_total` 帧，均匀切成 `bin_count` 个时间区间，
每个区间叫一个 bin。失败统计、采样概率都以 bin 为单位——**降维**：
不用管 6574 个帧各自的难度，只管 `bin_count`（比如 32）个区间的难度。

**在本实践中的体现**：一帧的帧号 `t` 属于哪个 bin，靠
`bin = (t · bin_count) // total`（整数除法，见坑 1）。

### 2.2 自适应采样的四个设计要点

把这四点理解了，`_adaptive_sampling` 就懂了。

**① 失败热度 F（每个 bin 的失败次数）**——难度的度量。
某个 bin 里开局的 episode 摔得多，说明那段难，F 高。

**② 均匀探索项 `ρ/N`**（`adaptive_uniform_ratio / bin_count`）——保底。
给每个 bin 的概率都加一个小正数，**保证任何 bin 概率都不为 0**。
否则一个从没失败过的 bin 概率是 0，永远采不到，那段动作会被遗忘（见 1.3）。
**去掉它会怎样**：策略逐渐忘掉简单段落，整体表现反而退化。

**③ 卷积平滑（convolution smoothing）**——把热度扩散到邻域。
失败是稀疏事件，某个 bin 摔往往意味着它**前后一小段**都不好走
（一个跳跃动作跨好几个 bin）。用一个几何衰减核 `λ^i`（已归一化）对失败热度做卷积，
把"这个 bin 难"扩散成"这一小段都要重点练"。
**只在右侧 padding**：核代表"当前 bin 对**后续** bin 的影响"，是**因果的**
（起点难，接下来一段都难）。**去掉它会怎样**：训练死磕单个 bin，
覆盖不到困难段落的完整跨度。

**④ bin 内随机偏移**——避免采样退化成离散点。
采到 bin 后，在 bin 内再加一个 `[0,1)` 的随机偏移换算成帧号。
**去掉它会怎样**：所有落在同一 bin 的环境会从**完全相同**的帧起步，
采样多样性退化成 `bin_count` 个离散起点，同一起点反复练意义不大。

### 2.3 EMA：指数移动平均（exponential moving average）

**生活化类比**：算"最近手感"，不是把这学期所有考试分数一股脑平均
（老分数拖后腿），而是新考试权重高、越老的权重指数衰减。

**严格定义**：用新观测和历史值加权更新，权重随时间指数衰减：

```
F' = α · f_current + (1 − α) · F_old
```

- `F'`：更新后的失败热度
- `f_current`：本轮新统计的失败次数
- `F_old`：历史累积的失败热度
- `α`（alpha，这里 = 0.001）：新样本的权重。α 越大越看重最近、记忆越短

**为什么用 EMA 而不是直接累加**：**策略在进步**，早期的失败记录会**过时**。
一个 bin 现在已经学会了，但它历史失败次数很高。直接累加会让采样**长期困在
"曾经很难但现在已学会"的片段**上。EMA 让旧失败记录随时间自然衰减，
采样跟着策略的当前水平走。

### 2.4 anchor 与参考动作对齐

**生活化类比**：老师的示范动作录在他自己站的位置。你要模仿时，
不是要求你走到老师**站的那个坐标点**，而是"就在你自己脚下，把这套动作做对"。
所以要把示范"平移旋转"到你当前的位置和朝向——这就是对齐。

**严格定义**：`anchor` 是"参考动作与机器人对齐所用的基准刚体"（通常是躯干/骨盆）。
`_update_command` 每步把参考动作对齐到机器人当前的 anchor 位姿，
否则参考轨迹固定在世界原点，机器人一偏离就再也追不上。

**关键——对齐是有选择的**（2.5 展开）：只对 **z（高度）和 yaw（水平朝向）** 处理，
x/y 跟机器人、roll/pitch 跟参考。

### 2.5 为什么只对齐 z 和 yaw（本实践的精髓设计）

| 维度 | 怎么处理 | 为什么 |
|---|---|---|
| x / y（水平位置） | **跟机器人** | 不要求机器人走到参考轨迹的绝对坐标（那等于同时考核导航），只要求"就地把动作做对" |
| z（高度） | **跟参考** | 否则蹲下/跳起这类高度变化无从考核 |
| yaw（水平朝向） | **跟机器人** | 朝向是自由的，机器人朝哪都行，只要动作对 |
| roll / pitch（前后左右倾） | **跟参考** | 这是机器人自己的**平衡姿态**，属于**被考核内容** |

**为什么 roll/pitch 绝对不能对齐**：如果把 roll/pitch 也对齐到机器人当前姿态，
就等于"机器人现在歪成什么样，就把参考也转成什么样"——**跟踪奖励会失去意义**，
机器人怎么歪都算"对齐后一致"，平衡直接学废。roll/pitch 是要考的，不能抹掉。

## 3. 算法原理

### 3.1 自适应采样的完整流程

```
_adaptive_sampling(env_ids)：
  1) 读失败环境：episode_failed = terminated[env_ids]   # 非超时终止 = 真失败
  2) 帧号 → bin：bin = clamp( (time_steps · bin_count) // total,  0, bin_count−1 )
  3) 统计本轮各 bin 失败次数：bincount(..., minlength=bin_count)
  4) 基础概率 = 历史失败热度 F + 均匀项 ρ/N
  5) 卷积平滑（几何核，右 padding，因果）
  6) 归一化成概率分布（sum=1）
  7) multinomial 按概率抽 bin（replacement=True，多个 env 可落同一 bin）
  8) bin 内 +[0,1) 偏移 → 帧号：(bin + offset) · bin_width，clamp 到 [0, total−1]，.long()
  9) 诊断指标：归一化熵、top1_prob、归一化 top1_bin
```

失败热度 F 本身由 `_update_command` 每步用 EMA 更新（见 3.2 步 7）。

### 3.2 参考动作对齐的完整流程

```
_update_command()：
  1) 所有环境帧号 +1
  2) 播放到结尾的环境（time_steps >= total）重新采样起始帧（走自适应采样）
  3) 把 anchor 位姿沿 body 维复制（每个 body 用同一个对齐变换）
  4) 位置对齐：delta_pos = 机器人 anchor 位置，但 z 分量换成参考的 z
  5) 姿态对齐：delta_ori = yaw_quat( quat_mul(机器人 anchor 朝向, inv(参考 anchor 朝向)) )  # 只留 yaw
  6) 用 delta_ori/delta_pos 把参考 body 位姿变换到机器人当前坐标系
  7) EMA 更新失败热度：F = α·f_current + (1−α)·F
  8) 清空本轮临时计数 _current_bin_failed（避免下轮 EMA 重复计入）
```

### 3.3 三个诊断指标：判断采样是否"塌缩"

采样机制看不见摸不着，靠三个归一化指标监控（`_adaptive_sampling` L358-364）：

- **归一化熵 `sampling_entropy`** = `entropy / log(bin_count)`，范围 [0,1]。
  均匀分布 = 1，全部概率集中在一个 bin = 0。除以 `log(bin_count)` 是为了
  **不同 bin_count 的实验能横向比**。健康趋势是"**先降后回升**"：
  早期采样聚焦到难点（熵降），学会后失败热度被 EMA 冲淡、采样重新铺开（熵升）。
  **长期贴 0 = 采样塌缩**，卡在同一片段反复失败，此时该查 termination 是否过严。
- **`top1_prob`**：最难 bin 的采样概率——最难片段有多突出。
- **归一化 `top1_bin`** = `argmax / bin_count`，范围 [0,1]：最难片段在整段动作的
  **什么位置**（0=开头，≈1=结尾），与动作总长无关，便于跨实验对比。

## 4. 代码走读

### 4.1 帧号映射到 bin + 失败统计

`bymic_commands_isaaclab_todo.py` L289-303：

```python
episode_failed = self._env.termination_manager.terminated[env_ids]   # 非超时终止=真失败

current_bin_index = (self.time_steps * self.bin_count) // max(self.motion.time_step_total, 1)
current_bin_index = torch.clamp(current_bin_index, 0, self.bin_count - 1)

self._current_bin_failed[:] = torch.bincount(
    current_bin_index[env_ids][episode_failed], minlength=self.bin_count
)
```

**`terminated` 为什么排除超时**：episode 结束有两种——超时（time_out，正常跑完，
不算失败）和真失败（摔倒/姿态越界）。自适应采样要对着**真失败**练，
所以用 `terminated`（不含 time_out）而不是笼统的 "done"。

**`max(total, 1)` 防除零**：total 理论上不会是 0，但除法分母一律加保护是好习惯。

**`clamp(..., 0, bin_count−1)`**：`time_steps` 恰好等于 `total` 时，
`(total·bin_count)//total = bin_count`，越界了（合法索引是 `0..bin_count−1`），clamp 压回。

**`minlength=bin_count` 必不可少**：`bincount` 默认返回长度 = "出现过的最大值+1"。
如果本轮最大失败 bin 是 5，返回张量长度就是 6，而不是 `bin_count`。
**长度随数据变化**，和 `bin_failed_count`（固定 `bin_count` 长）形状对不上，
后续相加直接崩。设了 `minlength`，返回长度恒为 `bin_count`（见坑 4）。

**张量形状**：`current_bin_index` 是 `(N,)`（N=总环境数）；
`current_bin_index[env_ids]` 取出本次 reset 的环境，`[episode_failed]` 再用布尔掩码
筛出失败的；`bincount` 结果是 `(bin_count,)`。

### 4.2 均匀项 + 卷积平滑 + 归一化 + 采样

L308-346：

```python
sampling_probabilities = self.bin_failed_count + self.cfg.adaptive_uniform_ratio / float(self.bin_count)

sampling_probabilities = torch.nn.functional.conv1d(
    torch.nn.functional.pad(
        sampling_probabilities.view(1, 1, self.bin_count),
        (0, self.cfg.adaptive_kernel_size - 1),        # 只在右侧 padding
    ),
    self.kernel.view(1, 1, -1),
).view(-1)

sampling_probabilities = sampling_probabilities / sampling_probabilities.sum()   # 归一化
sampled_bins = torch.multinomial(sampling_probabilities, len(env_ids), replacement=True)

offsets = sample_uniform(0.0, 1.0, (len(env_ids),), device=self.device)
bin_width = self.motion.time_step_total // self.bin_count      # ★ 整数除法
sampled_time_steps = (sampled_bins + offsets) * bin_width
self.time_steps[env_ids] = torch.clamp(sampled_time_steps, 0, self.motion.time_step_total - 1).long()
```

- **`conv1d` 的形状**：conv1d 要 `(batch, channel, length)`，所以概率 `view(1,1,bin_count)`，
  核 `view(1,1,-1)`。右侧 pad `kernel_size−1` 个 0，卷积后长度不变，`view(-1)` 压回 `(bin_count,)`。
- **`replacement=True`**：多个环境可以采到同一个难点 bin——本来就想让难点多开几个局。
- **`bin_width` 整数除法**：这是我们踩过的坑（见坑 1），也是单元测试专门卡的点。
- **末尾 `clamp` 到 `total−1` 再 `.long()`**：采样帧不能越界（合法帧号 `0..total−1`，
  用 `T−1` 不是 `T`），dtype 必须是 `long`（帧号是索引）。

### 4.3 归一化熵与 top1_bin

L358-364：

```python
probabilities = sampling_probabilities.clamp_min(1e-12)          # 防 log(0)
entropy = -(probabilities * probabilities.log()).sum()
normalized_entropy = entropy / math.log(max(self.bin_count, 2))  # 防 bin_count=1 除零
top1_prob, top1_bin = sampling_probabilities.max(dim=0)
self.metrics["sampling_top1_bin"][:] = top1_bin.float() / self.bin_count   # ★ 归一化位置
```

- `clamp_min(1e-12)`：熵公式有 `log`，概率为 0 会 `log(0)=−inf`。
- `max(bin_count, 2)`：`bin_count=1` 时 `log(1)=0`，除零；取 max 兜底。
- **`top1_bin / bin_count`**：`argmax` 返回的是 bin **下标**（`bin_count=2` 时可能是 1），
  除以 `bin_count` 归一化成"位置比例"。验证：`bin_count=2`、最难 bin 是 1 时，
  期望值是 **0.5** 而不是 1（见坑 2）。

### 4.4 EMA 更新失败热度

`_update_command` L477-483：

```python
self.bin_failed_count = (
    self.cfg.adaptive_alpha * self._current_bin_failed        # α · 本轮新失败
    + (1.0 - self.cfg.adaptive_alpha) * self.bin_failed_count # (1−α) · 历史
)
self._current_bin_failed.zero_()   # ★ 清空临时计数
```

- **`α` 和 `(1−α)` 的位置不能反**（坑 6）：`α` 乘**新样本** `_current_bin_failed`，
  `(1−α)` 乘**历史** `bin_failed_count`。反了就变成"压制新样本、放大历史"，平滑方向反了。
- **`zero_()` 必不可少**：`_current_bin_failed` 是本轮临时计数，用完必须清零，
  否则同一批失败会在下一轮 EMA 里**被重复计入**（坑 6 现象之一）。

## 5. 我踩过的坑（面试素材）

### 坑 1 · bin 宽度用了浮点除法，末帧概率被悄悄抬高

```
现象：单元测试（固定随机种子、精确数值匹配）第 1 项 _adaptive_sampling 过不了，
      采样帧号和参考实现差 1。
第一反应："差 1 而已，会不会是 clamp 边界或者四舍五入的小问题，无所谓？"
为什么这么想是错的：这不是无所谓的舍入。bin_width = total / bin_count 用**浮点**，
      会让末尾 bin 的采样帧越界到 [total−1] 之外，再被 clamp 压回 total−1——
      结果是**最后一帧获得异常高的采样概率**，采样分布被系统性扭曲，且很难察觉。
怎么找到真因：拿测试里的固定输入手算。total=5, bin_count=2, 采到 bin=1, offset=0.744：
      · 浮点宽度 2.5：(1+0.744)×2.5 = 4.36 → long 截断 4（期望 3）
      · 整数宽度 2：  (1+0.744)×2   = 3.49 → long 截断 3 ✅ 与参考一致
根因：帧号是整数索引，bin 宽度必须整数除法 total // bin_count，向下取整语义才对。
      浮点宽度会把本属于"末 bin 内部"的偏移放大到跨过边界。
教训：凡是最后要 .long() 当索引用的量，中间就该用整数运算，别让浮点误差偷偷改变落点。
      单元测试差"1"往往不是小事，是语义错误的信号。
```

### 坑 2 · 以为 top1_bin 应该是 1，其实期望 0.5

```
现象：单元测试里 sampling_top1_bin 期望 0.5，我的实现输出 1，对不上。
第一反应："bin_count=2 时最难的是 bin 1，argmax 就是 1，输出 1 没错啊？"
为什么这么想是错的：指标记录的是**归一化位置**，不是原始下标。
      要的是"最难片段在整段动作的什么位置比例"，得除以 bin_count。
怎么找到真因：读指标定义注释——top1_bin 归一化为 imax/bin_count，表示 0=开头、≈1=结尾。
      argmax=1，bin_count=2，1/2 = 0.5 ✅。
根因：把"下标"和"归一化位置"混了。归一化是为了跨不同 bin_count / 动作长度做横向对比。
教训：诊断指标的量纲和归一化方式要照定义读。同理熵也除以 log(bin_count) 归一到 [0,1]，
      验算 p=[0.04545, 0.95455] → H=0.1849，H/ln2=0.2668，与期望一致。
```

### 坑 3 · env_ids 二次索引：不报错、不改形状、更新落到错误环境

```
现象：训练能跑、形状全对，但某些环境的状态莫名其妙、参考目标像是串了。
第一反应："是不是仿真数值不稳定？换个 seed 再看看。"
为什么这么想是错的：换 seed 没用，问题稳定复现。这是索引逻辑错，不是随机性。
怎么找到真因：env_ids 已经是"要更新的环境"的一层索引了。如果又拿它去索引一个
      **已经按 env_ids 切过片**的张量（比如 tensor[env_ids][env_ids]），就成了二次索引——
      写法完全合法、shape 也对，只是更新落到了错误的环境上。把两个 shape 打出来对一眼就露馅。
根因：对"已切片张量"再切一次，第二层索引的语义变了（相对下标≠绝对下标）。
教训：这属于本项目反复遇到的一类——**不改变任何形状与量级的错误**
      （还有实践 5 的 update_history=False、实践 3 的四元数顺序）。
      共同对策：打印/手算最小例子去对，别看"程序跑通了没"。
```

### 坑 4 · bincount 忘设 minlength，返回长度随数据抖动

```
现象：某些 batch 下 bin_failed_count 相加时报形状不匹配，换个 batch 又好了，时好时坏。
第一反应："偶发的，重跑一下应该就过了。"
为什么这么想是错的：时好时坏正是没设 minlength 的典型症状。
      bincount 默认返回长度 = 最大失败 bin + 1，这个长度**取决于本轮失败落在哪**——
      失败都在前几个 bin 时长度短，有失败落在末尾 bin 时长度才够。所以时对时错。
怎么找到真因：检查 bincount 调用，确认没传 minlength。加上 minlength=bin_count，
      返回长度恒为 (bin_count,)，恒定了。
根因：依赖了一个"碰巧对"的长度，而它其实随数据变化。
教训：所有"输出长度应该固定"的聚合操作，都要显式钉死长度（minlength / 预分配）。
      间歇性 bug 优先怀疑"依赖了数据相关的形状"。
```

### 坑 5 · 混用 body_link_* 与 body_*（跨框架属性错误）

```
现象：接入训练框架后，body 位置对不上，跟踪目标整体偏了。
第一反应："是不是刚体顺序错了？"（顺序确实也要验，但这次不是。）
为什么这么想是错的：这次是**属性名**用错。IsaacLab 路线用 robot.data.body_pos_w，
      MJLab 路线用 robot.data.body_link_pos_w，两条路线属性名不同、语义有别。
怎么找到真因：先跑 Test 0（接口完整性检查），它专门验证用的是当前路线的正确属性。
      混用会在 Test 0 就暴露。
根因：两条仿真路线不要混装——选了 IsaacLab 就全程 body_*，选了 MJLab 就全程 body_link_*。
教训：跨框架移植时，先过接口一致性测试再查逻辑。别在两套 API 之间"半路换车"。
```

### 坑 6 · EMA 的两个写法错误：alpha 写反 / 临时计数没清零

```
现象：训练中采样一直"记仇"——早就学会的片段还被反复采，或者失败热度增长异常快。
第一反应："是不是 alpha 调太小了记忆太长？"去调 alpha 大小。
为什么这么想是错的：调 alpha 数值没解决，因为问题在结构不在取值。两种结构错：
      ① α 和 (1−α) 位置写反：F=αf+(1−α)F 里两者调换，数值范围/形状/量级全不变，
        只是"新样本被压制、历史被放大"，平滑方向反了。
      ② 临时计数 _current_bin_failed 用完没 zero_()：同一批失败被下一轮 EMA 重复计入，
        热度虚高、增长过快。
怎么找到真因：手算两轮 F′=αf+(1−α)F，拿固定输入对期望值——方向错会立刻看出来。
      再检查有没有 zero_()。
根因：又是"不改变形状与量级的错误"，跑得通、不报错，只有数值对不上。
教训：EMA 这类递推更新，手算两步验证方向；所有"每轮临时累积"的缓冲区，
      用完立刻清零，把它当成铁律。
```

## 6. 面试可能怎么问

**概念题**

1. **什么是自适应采样？为什么均匀采样不够好？**
   把动作切成 bin，统计各 bin 失败次数，失败多的 bin 给更高的开局采样概率。
   均匀采样不够好是因为**动作难度分布不均**：简单段落过度练、难点段落样本稀缺；
   且难点常在中后段，均匀从头播根本撑不到那里采不到数据。自适应采样直接从难点附近开局。

2. **只练难点会有什么问题？怎么避免？**
   灾难性遗忘——已学会的简单段落会退化。靠**均匀探索项 ρ/N** 给每个 bin 保底概率，
   保证没失败过的 bin 也能被采到。

3. **为什么参考动作对齐只对 z 和 yaw？**
   x/y 跟机器人（不考核导航，只要就地做对动作）；yaw 跟机器人（朝向自由）；
   z 跟参考（否则蹲/跳高度变化无从考核）；roll/pitch 跟参考（这是机器人自己的平衡姿态，
   是被考核内容，一并对齐就把姿态误差抹掉了，跟踪奖励失去意义）。

**实现题**

4. **卷积平滑为什么只在右侧 padding？EMA 里 alpha 放在哪一项？**
   卷积核代表"当前 bin 对**后续** bin 的影响"，是因果的，所以只向右扩散。
   EMA 是 `F' = α·新失败 + (1−α)·历史`，α 乘新样本；反了就变成压制新样本、放大历史。

5. **bincount 为什么要 minlength？bin 宽度为什么要整数除法？**
   minlength 让返回长度恒为 bin_count，否则长度随本轮最大失败 bin 变化、与热度张量形状对不上
   （间歇性崩）。bin 宽度用整数除法 `total // bin_count`，因为帧号是整数索引；
   浮点除法会让末尾 bin 采样帧越界被 clamp，异常抬高最后一帧的采样概率。

6. **采样帧越界怎么防？为什么是 T−1 不是 T？**
   合法帧号是 `0..T−1`（T 个帧的索引上界是 T−1），采样后 `clamp(..., 0, T−1)` 再 `.long()`。
   用 T 会越界一格。

**深挖题**

7. **训练里 sampling_entropy 应该长什么样？看到它长期贴 0 说明什么？**
   健康趋势是"先降后回升"：早期采样聚焦难点（熵降），学会后失败热度被 EMA 冲淡、
   采样重新铺开（熵升）。我们 20000 轮的实测 `sampling_phase_entropy` 从 0.9572
   起步、中段小幅下探（0.9953）后回升到 0.9973，正是这个形状。**长期贴 0 = 采样塌缩**，
   卡在同一片段反复失败，该查 termination 是否过严。

8. **训练中跟踪误差（error_joint_pos）不降反升，是不是学坏了？**
   不一定。我们 20000 轮里 `error_joint_pos` 从 0.93 升到 1.83，但那是因为
   **episode 长度从 5 步涨到 145 步**——机器人能跟到更靠后、更难的段落，
   误差自然累积，**分母（能跟到的帧数）变了，两个时刻的误差不可直接比**。
   真正的判据是回报和存活时长：reward 五段走势 1.883→4.903→5.920→7.166→8.339，
   episode 5→145，都是单调改善。看误差类指标前先确认分母一致。

9. **单元测试全过，是不是就说明训练一定对？**
   不是。单元测试（固定种子、数值匹配）只证明**算法与接口契约正确**，
   不证明 GPU 驱动、完整仿真环境或动作配置正确——这是讲解原话。
   所以调试顺序是"先核对 shape/device/dtype → 再核对公式 → 最后核对固定种子下的数值"，
   过了单测再进 GPU 训练。

## 7. 延伸：这个技术在工业界怎么用

**BeyondMimic（arXiv 2508.08241，2025）是招聘 JD 会点名的算法**，
它的定位是"从**动作跟踪**走向**通用人形控制**"：先用高质量的 motion tracking
把单段动作学到极致，再用引导扩散（guided diffusion）把多段能力组合成通用控制器。
本实践做的正是它最底层、最关键的那一环——**单段轨迹的高保真跟踪**，
而**困难片段自适应采样**是 BeyondMimic 让跟踪又快又准的核心训练技巧之一。

这个技巧的思想不止用于人形：

- **课程学习 / 优先经验回放（curriculum learning / prioritized experience replay）**：
  "对着难样本重点练"是一条贯穿 RL 的主线。DQN 的 PER 按 TD-error 给样本加权，
  和这里按失败次数给 bin 加权是同构的——都是把学习预算投给"最需要学的地方"。
- **自动课程（automatic curriculum）**：机器人从"难点附近开局"而不是"从头撑过去"，
  本质是在自动生成一条由易到难的课程，绕开了"探索地平线"问题。
- **真机迁移**：BeyondMimic 论文强调 tracking→真实机器人的迁移，
  这也是为什么参考动作对齐要那么讲究（只对 z/yaw、保留 roll/pitch 考核）——
  对齐方式直接决定了学到的是"真平衡"还是"被抹平的假平衡"。

在完整技术栈里，这个实践是**"把一段参考动作学到能上真机"**这一环。
上游接运动重定向（实践 7，把人体动作转成 G1 能做的参考）和数据采集，
下游接多动作融合与通用控制。理解了自适应采样，就理解了一个更普适的道理：
**训练效率的瓶颈往往不在算法本身，而在"你把算力花在了哪些样本上"。**
