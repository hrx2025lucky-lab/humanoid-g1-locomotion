## 0. 一句话概括

策略是在训练仿真器（IsaacSim/IsaacLab）里练出来的，要拿到另一个仿真器（MuJoCo）
里验证能不能用——这一步叫 **sim2sim**，是通往真机（sim2real）的排练。难点不在算法，
而在**两套仿真器对"同一个策略"的输入输出约定不一样**：关节排列顺序、正方向、动作
怎么缩放、默认站姿、PD 参数、观测怎么拼、深度图怎么预处理——六项**全部要显式对齐**，
错一项策略就废，且**不报错**。

## 1. 问题从哪来（Why）

### sim2sim 是干什么的

- **生活化类比**：你在**驾校的模拟器**里练会了开车（训练仿真器 IsaacSim），
  现在换到**另一台不同品牌的模拟器**（MuJoCo）上试试还会不会开。如果换个模拟器就不会了，
  那更别说上真车（真机）。sim2sim 就是"换一个物理引擎验证策略没有过拟合到训练器的
  具体实现"。
- **严格定义**：把在仿真器 A 训练得到的策略，不重新训练，直接部署到仿真器 B 上闭环运行，
  检验策略对"物理实现差异"的鲁棒性。它是 sim2real 的低成本前置排练。

### 为什么接口对齐是核心难点

策略是个 ONNX 神经网络：喂它一个观测向量，它吐一个动作向量。**它不知道**这些数字
背后的物理含义——第 3 维是哪个关节、动作要不要缩放、深度图归一化到什么范围。
这些"约定"在训练器里是一套，换到 MuJoCo 里如果**不手动对齐成同一套**，网络照样
输出数字、仿真照样运行，**没有任何报错**，只是机器人动作完全错乱直接摔。

参考答案（作业讲解第 29-30 行）把这句话点成**核心挑战**：
> "两套仿真器『接口不对齐』——关节顺序/正方向、动作尺度、默认姿态、PD 参数、
> 观测拼接顺序、深度图预处理**全部要显式对齐**。"

这六项就是本文的主线。

## 2. 核心概念（零基础可懂）

### decimation（控制降频）与控制频率

- **生活化类比**：物理引擎像一台**每秒拍 200 张的高速摄像机**（物理步进 200Hz），
  但大脑（策略）没必要每一张都做决策——它**每 4 张才想一次动作**，中间 4 张用同一个
  动作硬扛。"每 4 张想一次"就是 decimation=4，于是决策频率 = 200/4 = 50 次/秒。
- **严格定义**：物理仿真步长 `SIM_DT`，每 `DECIMATION` 个物理步执行一次策略推理，
  控制频率 = `1 / (SIM_DT × DECIMATION)`。
- **本实践**：`SIM_DT=0.005`（200Hz 物理），`DECIMATION=4` → **控制频率 50Hz**。
  两个物理步之间策略输出的目标位置不变，靠 PD 控制器每个物理步算一次力矩去逼近它。

### 两套关节顺序（policy order vs robot/SDK order）

- **类比**：同一支球队，**教练的花名册**按身高排（policy order），**球衣号码**按
  入队先后排（SDK order）。同一个人在两个名单里位置不同。你把"3 号该传球"的指令
  发出去前，必须先把"教练名单第 3 位"翻译成"几号球衣"。
- **本实践**：`POLICY_JOINT_NAMES`（策略/IsaacSim 顺序）与
  `UNITREE_G1_29DOF_SDK_JOINT_NAMES`（SDK/MuJoCo 顺序）是**两套不同排列**。
  代码用 `robot_to_policy` / `policy_to_robot` 两个索引表来回翻译（`config.py:18/51`）。

### 关节正方向（JOINT_SIGNS）

- **类比**：两套系统对"膝盖弯曲算正还是负"的规定可能相反。同一个角度值，一边是弯、
  一边是伸。
- **本实践**：`JOINT_SIGNS = [1,1,-1]*3 + [1]*20`（`config.py:276`）——前 9 个里
  每组第 3 个关节符号相反，其余为 1。读观测时乘一次符号翻译过来，发动作时再乘回去。

### PD 控制（比例-微分力矩）

- **类比**：把关节想成**带阻尼的弹簧**。目标位置是弹簧的自然长度，关节偏离目标越多，
  弹簧把它拉回去的力越大（比例项 Kp）；关节动得越快，阻尼越使劲刹车（微分项 Kd）。
- **严格定义**：`τ = Kp·(q_target − q) − Kd·q̇`。
  - `q_target`：策略给出的目标关节位置；`q`：当前关节位置；`q̇`：当前关节速度。
  - `Kp`（stiffness/刚度）：拉回目标的劲；`Kd`（damping/阻尼）：抑制震荡的劲。
  - **去掉 Kd 会怎样**：关节会像没有阻尼的弹簧一样**来回震荡不停**，甚至发散。
  - **Kp/Kd 必须和训练器一致**：训练时策略是在"某个 Kp/Kd 的身体"上学会发力的，
    部署换了 Kp/Kd，等于换了一副筋骨，同样的目标位置产生不同的实际运动。

### 深度相机与深度图

- **类比**：普通相机记录"颜色"，深度相机记录"每个像素离镜头多远"。跑酷要看清台阶、
  沟壑的**远近**，用的就是深度图。
- **本实践**：MuJoCo 渲染 270×480 的深度图，经预处理喂给 `depth_encoder`（ONNX）编码，
  再和本体观测一起喂 actor。

## 3. 算法原理

### 3.1 六项接口对齐（核心挑战，逐项拆）

| # | 要对齐的东西 | 不对齐的后果（全部静默） | 代码位置 |
|---|---|---|---|
| 1 | **关节顺序 + 正方向** | 动作发给错误的关节 / 方向反了，机器人乱动 | `robot_to_policy`, `JOINT_SIGNS` |
| 2 | **动作尺度 ACTION_SCALES** | 动作幅度整体放大/缩小，步子迈错 | `config.py:214` |
| 3 | **默认姿态 DEFAULT_JOINT_POS** | 动作是"相对默认姿态的偏移"，基准错则整体歪 | `config.py:183` |
| 4 | **PD 参数 Kp/Kd** | 同一目标位置产生不同实际运动，发力不对 | `STIFFNESS/DAMPING` |
| 5 | **观测拼接顺序** | 网络第 i 维读到的物理量对不上，输入全乱 | `update_observation` 6 项 |
| 6 | **深度图预处理** | 距离零点/量程/裁剪不一致，策略"看到另一个世界" | `depth_pipeline` 5 步 |

**动作解码公式**（`sim2sim.py:417`，把这条看懂等于把 1/2/3 全串起来）：

```
action = raw_action[policy_to_robot] · action_scale + default_joint_pos   # → 得到目标关节位置
action = action · joint_signs                                             # 翻回 robot 正方向
```

- `raw_action`：策略输出（policy 顺序、无量纲）。
- `[policy_to_robot]`：**第 1 项**——把策略顺序重排成机器人顺序。
- `· action_scale`：**第 2 项**——把无量纲动作放大成弧度增量。
- `+ default_joint_pos`：**第 3 项**——策略学的是"相对默认站姿的偏移"，加回基准
  才是绝对目标位置。**去掉这一项**，机器人会试图回到"全零关节角"那个扭曲姿势。
- `· joint_signs`：**第 1 项的正方向部分**——翻回机器人的符号约定。

这个目标位置再进 §2 的 PD 公式（**第 4 项** Kp/Kd）算力矩。

### 3.2 50Hz 是怎么推出来的，部署按 200Hz 会怎样

```
物理步长 SIM_DT = 0.005 s   →   物理频率 = 1/0.005 = 200 Hz
每 DECIMATION = 4 个物理步做一次策略推理
控制频率 = 200 / 4 = 50 Hz   →   控制周期 = 0.02 s
```

代码里对应 `keep_running`（`sim2sim.py:422`）：一次推理后，PD 力矩循环 `decimation` 次、
每次 `physical_step()`。末尾用 `time_to_sleep = SIM_DT × DECIMATION − 已耗时`
（`:434`）把节奏**卡回真实时间的 50Hz**，避免仿真跑得比真机快。

**部署时若按 200Hz 推理会怎样**（高频面试题）：
- 策略是在 **50Hz** 下训练的——它学到的"每次决策该迈多大一步"是按 20ms 一拍算的。
- 如果部署端每 5ms（200Hz）就推一次、每次都执行完整动作，等于**把动作播放速度快了 4 倍**：
  机器人的目标位置以 4 倍频率跳变，腿还没到位就被下一个目标拽走，步态紊乱、大概率摔。
- **关键**：这个错误**不会报错**——频率是个"外部节拍"，代码照跑，只是策略被塞进了
  一个它没在其中训练过的时间尺度。所以 `SIM_DT × DECIMATION` 必须和训练端一致。

### 3.3 深度图预处理五步（每步为什么非要不可）

管线顺序（`sim2sim.py:131`）：**resize → crop → inpaint → gaussian blur → clip & normalize**。

**① resize：270×480 → 36×64（最近邻 INTER_NEAREST）**
- 为什么 resize：原图太大，编码器要固定小尺寸；降分辨率也省算力。
- 为什么**最近邻**而非双线性：深度图的像素值是**物理距离**，插值混合会造出
  "介于台阶顶和台阶底之间"的**不存在的中间距离**，污染几何。最近邻只挑原像素，不混合。
- **易错点**：`cv2.resize` 的 `dsize=(宽, 高)`，和 numpy 的 `(行, 列)=(高, 宽)` **相反**，
  写反了尺寸就转置了（见 §5）。

**② crop：36×64 裁成 18×32（裁掉上 18 行、左右各 16 列）**
- 裁剪区域 `(18,0,16,16)`（`config.py:119`，含义 y1/y2/x1/x2）。
- 为什么裁边：真实深度相机**边缘畸变最大、无效点最多**，裁掉噪声最重的四周，
  留中间可靠区域。裁完 18×32 就是喂进网络的空间尺寸。

**③ inpaint：把无效点（洞）补上（cv2.inpaint, INPAINT_NS, 半径 3）**
- `mask = (image < 0.2)`：深度相机在**反光/吸光表面**会返回接近 0 的无效值，mask 标出这些洞。
- 为什么必须补：**0 在归一化后是"最近距离"**，直接留着 0，策略会以为"镜头前紧贴着
  一个障碍物"——语义完全反了。INPAINT_NS（Navier-Stokes）沿等照度线把邻域深度
  **延拓**进洞里，比填常数更符合深度图的连续性。
- **去掉这一步会怎样**：策略被大量假"贴脸障碍"干扰，跑酷时乱躲乱停。

**④ gaussian blur：轻度平滑（核 3×3，σ=1）**
- 为什么：抑制仿真深度图的**阶梯状锯齿**。
- 为什么只用 3×3、σ=1（轻度）：**太强会抹掉台阶边缘**——而台阶边缘正是跑酷策略
  最需要的信息。这是一个"降噪"和"保留有用边缘"的折中。

**⑤ clip & normalize：截到 [near, far] 再线性归一化到 [0,1]**
- 先 `clip(near, far)` 把距离夹进有效量程，再 `(x−near)/(far−near)` 映射到 [0,1]。
- 为什么归一化：训练时用的就是这个**零点与量程定义**，网络权重是按 [0,1] 输入学的。
- **去掉/改动会怎样**：差一个偏移或缩放**不报错**，只让策略读到"另一个世界的距离"——
  和 §3.1 第 6 项是同一类静默错误。

### 3.4 时间维度：60 帧队列抽 8 帧 + 随机延迟

策略要的不是一张深度图，而是**一小段深度历史**（看出障碍在接近还是远离）。

**队列与抽帧**（`sim2sim.py:83`）：
```
队列长度 length = 60（每帧预处理后入队）
down_sample_factor = int(length/60 × 5) = int(1×5) = 5
indices = linspace(-1 - 5×(8-1), -1, 8) = linspace(-36, -1, 8)
        = [-36, -31, -26, -21, -16, -11, -6, -1]     # nb_frames=8
```
- 从 60 帧里**等间隔抽 8 帧**（间隔 5），覆盖最近 36 帧的时间跨度。
- 为什么抽稀不用全 60：8 帧足够表达运动趋势，又把编码器输入维度压下来。
- 最终深度观测形状 **(1, 8, 18, 32)**（batch 1、8 帧、18×32）。

**随机延迟**（`resample_delay`，`delay_ranges=(0,1)`）：
- 每帧随机延迟 0 或 1 帧再取（`delayed_index = index − delay`）。
- 为什么：**真实深度相机有传输/处理延迟**，训练时注入随机延迟，让策略提前适应
  "看到的画面比现实慢一拍"，提高 sim2real 鲁棒性。这是一种**域随机化**。

### ② 六项本体观测按顺序写入（`update_observation`，`sim2sim.py:336`）

```python
obs_ring_buffer[0] ← base_angle_vel      = imu角速度 × 0.25              # 尺度也要对齐
obs_ring_buffer[1] ← projected_gravity   = quat_apply_inverse(quat, g)   # wxyz 重力投影
obs_ring_buffer[2] ← velocity_commands                                   # 速度指令
obs_ring_buffer[3] ← joint_pos_rel = (q·signs − default)[robot_to_policy]# → policy 顺序
obs_ring_buffer[4] ← joint_vel_rel = (q̇·signs × 0.05)[robot_to_policy]   # → policy 顺序
obs_ring_buffer[5] ← last_action                                         # 上一步动作
```

- **顺序就是契约**（第 5 项对齐）：网络训练时观测按这个顺序拼接，部署必须逐字复刻。
  换任意两项顺序都不报错，只让网络每一维读错物理量。
- `projected_gravity` 用 **wxyz** 四元数做 `quat_apply_inverse`（把世界重力转到机体系，
  等于告诉网络"身体歪没歪"）——注意这里是 wxyz 约定，和实践 7 的 npz(xyzw) 又不同，
  每个接口按各自约定来。
- 注意那些**观测缩放**：角速度 ×0.25、关节速度 ×0.05——这些也是训练端定的尺度，
  属于第 5 项的一部分，错了同样静默。

### ③ 控制主循环（`keep_running`，`sim2sim.py:404`）

```python
while viewer.is_running():
    t0 = perf_counter()
    self.update_observation()                       # 攒 6 项本体 + 1 深度
    history_obs = self.get_history_obs()[None, ...] # 拼历史
    raw_action = self.actor({"input": history_obs}).ravel()   # policy 顺序
    self.last_action = raw_action.copy()
    # 解码：policy→robot 重排 × 尺度 + 默认姿态，再乘符号（§3.1 公式）
    action = raw_action[policy_to_robot] * action_scale + default_joint_pos
    action = action * joint_signs
    for _ in range(DECIMATION):                     # 一次决策，PD 撑 4 个物理步
        tau = stiffness*(action - q) - damping*qd   # PD 力矩（§2）
        tau = clip(tau, -limit, +limit)             # 力矩限幅，保护关节
        ctrl[:] = tau; physical_step()
    time_to_sleep = SIM_DT*DECIMATION - (perf_counter()-t0)   # 卡回 50Hz 实时
    if time_to_sleep > 0: sleep(time_to_sleep)
```

- 一次推理 → 解码一个目标位置 → PD 循环 4 次逼近它 → 睡到 20ms 补齐。
  这条循环把**六项对齐**全用上了，是整份代码的主干。

### ④ 深度管线（`DepthProcessor.append`，`sim2sim.py:131`）

见 §3.3 的五步，代码里每步都补了 TODO 并写明理由。抽帧在 `get_depth_obs`（`:191`），

## 5. 我踩过的坑（面试素材）

### 坑一：`cv2.resize` 的 dsize 是 (宽, 高)，和 numpy 相反

```
现象：resize 后深度图“转置”了，宽高互换，后面 crop 全错位。
第一反应：以为 RESIZED_DEPTH_IMAGE_SHAPE 写错了。
为什么这么想是错的：常量没错，错在 cv2.resize 的参数约定。
      numpy 的 shape 是 (行, 列) = (高, 宽)；cv2.resize 的 dsize 是 (宽, 高)。
      直接把 (h, w) 传进 dsize 就把宽高对调了。
怎么找到真因：打印 resize 前后的 image.shape 对比，发现两个维度换了位置。
根因：OpenCV 与 numpy 的维度顺序约定相反。
教训：凡是 OpenCV 函数，dsize/point 都是 (x=宽, y=高)；numpy 索引都是 (行=高, 列=宽)。
      交界处必须显式写清，代码里我特意留了注释 “dsize 是 (宽,高)，与 numpy 相反”。
```

### 坑二：不 inpaint、把无效点 0 留着——语义正好反了

```
现象：跑酷策略无缘无故急停、乱躲，像前面老有东西。
第一反应：以为策略没训好。
为什么这么想是错的：策略没问题，是深度图喂错了。反光/吸光面返回的无效值≈0，
      而 0 归一化后是“最近距离”。留着这些 0 = 到处都是“贴脸障碍”。
怎么找到真因：可视化归一化后的深度图，发现无效区是最亮（最近）的一片。
根因：无效点未修补，0 的物理语义与“最近”重合，被策略读成障碍。
教训：深度图的“空洞”不是 0，是“未知”。必须 inpaint 用邻域延拓，
      绝不能当成有效的近距离。这一步删了不报错，只让策略疑神疑鬼。
```

### 坑三：把 sim2sim 当"重新训练"，纠结环境

```
现象：一度判定“要在本机另建一个 20GB 的 IsaacLab 环境才能做实践 11”。
第一反应：sim2sim 也要训练器，那就得装训练环境。
为什么这么想是错的：sim2sim 的 A/B 部分是**加载已有 ONNX 策略在 MuJoCo 里闭环**，
      根本不需要 IsaacLab 训练栈，只要 mujoco + onnxruntime + opencv。
怎么找到真因：读 sim2sim.py 的依赖，只 import 了 mujoco/onnx/cv2，没有 isaaclab。
根因：把“部署验证”误当成“训练”，只看了任务名没读实现依赖。
教训：这和实践 10 那个 offset 坑是同一个病根——**只读声明没读实现**。
      分清“训练”（要 IsaacLab+GPU，本实践的 C 部分）和“sim2sim 部署”
      （只要 MuJoCo，本实践的 A/B 部分），别被一个任务名吓到去装整套环境。
```

## 6. 面试可能怎么问

**概念题**

1. *什么是 sim2sim，为什么要做？*
   把训练器（IsaacSim）里训好的策略不重训、直接搬到另一个物理引擎（MuJoCo）闭环验证。
   目的是检验策略没有过拟合到训练器的具体实现，是 sim2real 的低成本前置排练。

2. *50Hz 控制频率是怎么来的？*
   SIM_DT=0.005 → 物理 200Hz；DECIMATION=4，每 4 个物理步推理一次 → 200/4 = 50Hz。
   两次决策间目标位置不变，靠 PD 每个物理步算力矩逼近。

3. *部署时按 200Hz 推理会怎样？*
   策略在 50Hz 下训练，动作按 20ms 一拍设计。按 200Hz 推理等于把动作播快 4 倍，
   目标位置以 4 倍频跳变，腿没到位就被下一个目标拽走，步态紊乱、摔倒。且**不报错**——
   频率是外部节拍，代码照跑，只是策略被塞进没训练过的时间尺度。

**实现题（六项对齐是重点）**

4. *sim2sim 要对齐哪些接口？为什么难？*
   六项：关节顺序/正方向、动作尺度、默认姿态、PD 参数、观测拼接顺序、深度图预处理。
   难在**全部静默失败**——策略是神经网络，不知道数字的物理含义，不对齐照样输出、
   照样运行，只是机器人读到"另一个世界的数据"然后摔。

5. *动作解码那行 `raw·scale + default` 每一项？去掉 default 会怎样？*
   `[policy_to_robot]` 把策略顺序重排成机器人顺序；`×action_scale` 把无量纲动作变弧度；
   `+default_joint_pos` 因为策略学的是"相对默认站姿的偏移"，加回基准得绝对目标；
   `×joint_signs` 翻回机器人正方向。去掉 default，机器人会试图回到全零关节角那个
   扭曲姿势。

6. *深度预处理五步，每步为什么？*
   resize（缩到固定小尺寸，用最近邻避免造出不存在的中间距离）→ crop（裁掉边缘畸变
   最重的区域）→ inpaint（补无效点，否则 0 被读成贴脸障碍）→ 轻度高斯模糊（抑锯齿
   但保台阶边缘）→ clip&normalize（对齐训练端的零点量程）。

**深挖题**

7. *为什么 resize 用最近邻不用双线性？*
   深度像素是物理距离，双线性会把台阶顶和底混合出一个不存在的中间距离，破坏几何。
   最近邻只挑原像素不混合。

8. *60 帧队列为什么只抽 8 帧？随机延迟干嘛的？*
   等间隔抽 8 帧（间隔 5，覆盖最近 36 帧）足够表达运动趋势，又压低编码器输入维度，
   得到 (1,8,18,32)。随机延迟 (0,1) 模拟真实相机的传输延迟，是一种域随机化，
   让策略提前适应"画面慢一拍"，提高 sim2real 鲁棒性。

9. *为什么 inpaint 的 mask 是 `depth < 0.2`？*
   反光/吸光表面深度相机返回接近 0 的无效值，mask 标出这些洞。补洞用 INPAINT_NS
   沿等照度线延拓邻域深度，比填常数更符合深度图连续性。

**状态题**

10. *你这个跑起来了吗？*
    A（深度预处理）+ B（用课程 ONNX 做 sim2sim 闭环）已完成，
    `verify_practice11_depth.py` 15/15 通过，能在 MuJoCo 闭环跑。

    C（自己训练跑酷策略）跑过一轮，但**那一轮的环境数用错了** ——
    脚本里 `${NUM_ENVS:-512}` 沿用了冒烟测试的规模，正式训练该用 4096。
    按课程折算基准 `Env × Iter ≈ 4096 × 10000`，512×3000 只有 **3.75%**，
    地形课程等级才爬到 1.28/9。已修正为 4096 重跑。

    > 这题反而是个好素材：当时 3000 轮只跑了 148 分钟、比预期快 6 倍，
    > 我第一反应是"GPU 独占所以更快"，把它当好消息收下了。
    > 实际主因是环境数少了 8 倍。
    > **性能突然变好和突然变差一样值得怀疑** —— 都该先去核对配置。

## 7. 延伸：这个技术在工业界怎么用

- **sim2sim 是 sim2real 的标准中间站**。真机实验昂贵且有损坏风险，先在第二个物理
  引擎里验证策略的鲁棒性，能在上真机前拦掉大部分"只在训练器里成立"的过拟合。
  Unitree、宇树、各家人形团队的部署流程普遍有这一步。
- **接口对齐 = 部署工程的日常**。真机 SDK 的关节顺序、正方向、单位、控制频率几乎
  一定和训练器不同，这套"两套名单 + 索引映射 + 符号 + 尺度 + PD + 观测顺序"的对齐
  代码，就是把仿真策略搬上真机时**每次都要写**的胶水层。
- **深度感知 + 域随机化**：跑酷这类需要看地形的任务，深度相机是主流传感器。
  训练时对深度图注入延迟、噪声、无效点（就是这里的 inpaint/blur/delay），
  是缩小 sim2real 差距的关键手段——真机深度图远比仿真脏。
- **在完整栈里的位置**：`感知(深度) + 跟踪/AMP 策略训练 → sim2sim 验证(本实践) →
  真机部署`。本实践是"把策略推向真机"的最后一道仿真关卡，串起了前面实践 6(蒸馏)、
  8(AMP)、10(地形感知) 的产物。
- **Project Instinct**：本实践的跑酷策略基于 Project Instinct 思路（作业标题），
  把深度感知、动作先验、地形跑酷整合进一个可部署的策略——是前面所有实践的集大成。
