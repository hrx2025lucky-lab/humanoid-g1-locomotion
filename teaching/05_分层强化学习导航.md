# 实践 5 · 分层强化学习导航

> **一句话**：让一个已经会走路的策略去"当腿"，再训练一个新策略去"当脑子"——
> 脑子只管往哪走，腿只管怎么走稳。

---

## 1. 问题从哪来

### 不分层会怎样

假设你要训一个策略，输入是"目标在哪 + 周围地形长什么样"，输出直接是 G1 的
**29 个关节角**。这个策略同时要学会：

- 怎么迈腿才不摔（平衡与步态）
- 障碍物在哪、该往哪绕（导航与避障）

这两件事的**时间尺度差了两个数量级**。保持平衡是毫秒级的反馈——脚一歪就得
立刻调整；而"绕过前面那块石头"是秒级的决策。让一个网络同时管这两件事，
结果通常是：还没学会站稳，就没机会体验到"绕过障碍"的奖励。

这在强化学习里叫**探索难题**：有价值的行为（到达目标）要在一长串正确动作
之后才出现，而随机初始化的策略连第一步都走不好。

### 分层怎么解决

把问题拆成两层：

```
高层（新训练）      每 4 个物理步决策一次
  输入：目标在哪 + 高度图 + 自身状态
  输出：3 维速度指令 [vx, vy, ωz]
        ↓
低层（已训练好，冻结）  每 4 个物理步推理一次
  输入：速度指令 + 本体感知
  输出：29 维关节角
        ↓
物理仿真          每个物理步都执行
```

**低层是实践 2 训练好的粗糙地形行走策略**，直接拿来用、参数冻结。
高层只需要学"给什么速度指令"，这个动作空间从 29 维降到 3 维，
而且每个维度都有直观含义。

> 这就是**技能复用**（skill reuse）：把已经学会的能力打包成可调用的模块。
> 和软件工程里调用一个库函数是同一个道理——你不需要知道 `sort()` 内部
> 怎么实现，只要知道它能排序。

## 2. 核心概念

### 2.1 分层强化学习 HRL

**类比**：公司里的总经理和车间主任。

总经理说"这个月产量提高 20%"，他不管具体哪台机器怎么转；
车间主任接到指令，负责把它变成机器的实际操作。
总经理换人了，车间主任的工作方式不用变——**接口是稳定的**。

**严格定义**：把策略分解为多层，上层输出的不是环境的原始动作，
而是下层的**目标或指令**。数学上，上层在一个抽象的动作空间 $\mathcal{A}_{high}$
上做决策，下层负责把 $a_{high}$ 映射到原始动作空间 $\mathcal{A}_{env}$。

**本实践的具体形式**：

$$a_{high} = [v_x, v_y, \omega_z] \in \mathbb{R}^3$$

裁剪到低层训练时见过的范围：

$$v_x \in [-0.5, 1.0],\quad v_y \in [-0.5, 0.5],\quad \omega_z \in [-0.5, 0.5]$$

**为什么要裁剪**：低层策略是在这个速度范围内训练的。给它 $v_x = 5.0$
这种没见过的指令，它的输出是未定义行为——不会报错，但会输出乱七八糟的关节角。
这叫**分布外输入**（out-of-distribution），是策略复用最常见的失败方式。

### 2.2 多时间尺度控制

三个频率同时在跑，容易搞混：

| | 频率 | 周期 | 干什么 |
|---|---|---|---|
| 物理仿真 | 200 Hz | 5 ms | 积分动力学方程 |
| 低层推理 | 50 Hz | 20 ms | 算一次 29 维关节角 |
| 高层决策 | 50 Hz | 20 ms | 算一次速度指令 |

`decimation = 4` 就是这个 4：**每 4 个物理步做一次策略推理**。

关键点（也是 TODO 5 考的）：

> 低层策略每 4 个物理步**推理**一次，但低层的 action term 每个物理步
> 都必须 `apply_actions()`。

**为什么**：推理算出的是"目标关节角"，而 PD 控制器要在**每个物理步**
根据当前关节角与目标的差算力矩。中间那 3 个物理步不重新推理，
但要持续用上一次的目标角度做 PD 控制。

漏掉这一点会怎样？关节在 3 个物理步里没有力矩输出，机器人会抽搐。

### 2.3 高度扫描与最大池化

**RayCaster** 从机器人上方往下打一排射线，测出脚下每个格点的地面高度。
本实践 V5 的扫描区是 **5.0 × 3.0 米、分辨率 0.12 米**
（`navigation_env_cfg.py:107-108`）。

射线数量不是简单的 `size / resolution`，因为格点**含两端边界**。
代码里用 `torch.arange(-size/2, size/2 + eps, step=resolution)` 生成
（`observations.py:45`），等价于：

$$n = \left\lfloor \frac{size}{resolution} \right\rfloor + 1$$

$$n_x = \lfloor 5.0 / 0.12 \rfloor + 1 = 41 + 1 = 42, \qquad
n_y = \lfloor 3.0 / 0.12 \rfloor + 1 = 25 + 1 = 26$$

$$42 \times 26 = \textbf{1092 根射线}$$

> 这个 **+1 很容易漏**。如果按 `round(5.0/0.12)=42` 再 +1 会得到 43×26=1118，
> 差 26 维——网络照样能建起来不报错，只是维度对不上后面的 376。
> 同类的 off-by-one 在实践 10 也出现过（1.6/0.1=16，含边界是 17，
> 17×17=289 而不是 256）。

1092 维直接进网络有两个问题：
1. 第一层权重矩阵会很大（1092 × 隐层维度）
2. 相邻射线的高度高度相关，信息冗余

所以做 **2×2 最大池化**，降到 21 × 13 = **273 维**。

**为什么用最大池化而不是平均池化**：导航关心的是"这里能不能过"。
一个 2×2 区域里只要有一个高点，机器人就过不去——取最大值保留了
"最坏情况"，取平均会把障碍物抹平。

**TODO 2 的坑**：必须先把一维的 1092 恢复成二维的 (26, 42) 网格，
再做二维池化。直接对一维向量做池化，等于把不相邻的格点混在一起，
空间结构就全错了。

```python
# 正确：先恢复网格
h = h.view(num_envs, ny, nx)           # (N, 26, 42)
h = h.unsqueeze(1)                     # (N, 1, 26, 42) 加通道维给 max_pool2d
h = F.max_pool2d(h, kernel_size=2)     # (N, 1, 13, 21)
h = h.flatten(1)                       # (N, 273)
```

### 2.4 观测维度的构成

高层的 376 维观测：

$$\underbrace{3}_{\text{目标位置}} + \underbrace{3}_{\text{线速度}} + \underbrace{3}_{\text{角速度}} + \underbrace{4}_{\text{姿态四元数}} + \underbrace{3}_{\text{重力投影}} + \underbrace{273}_{\text{池化高度图}} + \underbrace{29}_{\text{关节角}} + \underbrace{29}_{\text{关节速度}} + \underbrace{29}_{\text{上次动作}} = 376$$

**注意**：Actor 不能同时放原始 1092 维和池化后的 273 维，否则维度对不上。
Critic 可以额外看 `base_height` 和目标距离——这是**非对称 actor-critic**：
critic 在训练时可以用特权信息，actor 只能用部署时拿得到的信息。

### 多频率循环（TODO 5）

```python
def apply_actions(self):
    # 每个物理步都会被调用
    if self._counter % self.cfg.low_level_decimation == 0:
        # 每 4 步重新推理一次
        self._low_level_actions[:] = self._policy(self._get_low_level_obs())
```

## 5. 我踩过的坑（这是本实践最有价值的部分）

### 坑 1 · 到达率恒为 0，排查了十一轮

**现象**：修复了训练发散之后，策略跑满 3000 轮，到达率始终 **0%**。
但表面指标全是好的——episode 长度满值 150、`time_out` 占 99.4%、
摔倒率只有 0.6%。

**第一反应**：这是典型的"站着不动"局部最优——摔倒的惩罚远大于移动的收益，
所以策略学会了原地不动混时间。

**为什么这么想是错的**：这个假设本身合理（实践 2 确实遇到过），
但我没有验证它。查 `position_progress` 是正的、距离误差在下降，
说明机器人**确实在朝目标移动**。不是站着不动。

**十一轮排除**：奖励权重、终止条件、观测归一化、动作裁剪范围、
课程设置、目标采样、EMA 平滑、探索噪声……每一项都单独验证，
全部排除。

**转折点**：写了个 oracle 测试——**用脚本直接生成"转向目标 + 前进"
的完美指令**，绕开 RL 策略。如果连脚本化的完美指令都到不了目标，
那问题就不在策略学习，而在任务本身。

结果：到达率 **0%**，摔倒率 **84.4%**。

这一下把问题范围从"RL 训练"缩到了"高层给的速度指令送到低层之后发生了什么"。

**根因**：`ObservationManager.compute_group()` 的签名是

```python
def compute_group(self, group_name: str, update_history: bool = False)
                                          # ↑ 默认 False
```

IsaacLab 的标准环境走的是 `compute(update_history=True)`
（`manager_based_rl_env.py:238`），但 HRL 的低层 obs manager 是我们自己建的，
照搬官方示例时没传这个参数。

`update_history=False` 时代码走 `elif` 分支：

```python
circular_buffer = CircularBuffer(...)   # 只重新绑定了局部变量
                                        # 没有存回成员
```

**每次调用都重新走这条路，每次都用当前帧填满 5 个槽位。**
低层看到的"5 帧历史"实际是**当前帧重复 5 次**。

为什么上游示例不会出问题：IsaacLab 官方的 navigation 示例里
`history_length` 出现 0 次——不传该参数无害，文档明确说是 no-op。
而课程的低层策略是 `history_length = 5`。

**修复效果**：

| | 修复前 | 修复后 |
|---|---|---|
| oracle 到达率 | 0% | **46.9%** |
| oracle 摔倒率 | 84.4% | **0%** |
| 训练到达率 | 0%（3000 轮） | **97.5%**（954 轮） |

**教训**：

1. **不改变形状、不改变量级、不报错的 bug 最难找。** 观测张量的形状
   完全正确（5 帧就是 5 帧），数值也在合理范围，只是内容重复了。
2. **oracle 测试是切分问题域的利器。** 用脚本代替策略，能把
   "算法学不会"和"任务本身有问题"彻底分开。
3. **复用上游代码时，要检查默认参数是不是为你的用法设计的。**
   `update_history=False` 对不带历史的观测是无害默认值，
   对带历史的就是致命的。

### 坑 2 · `goals_reached` 是个不产生数据的指标

**现象**：修复之后，95% 的 episode 都到达了目标，
但 `Metrics/pose_command/goals_reached` 仍然显示 **0.0000**。

**根因**：这个指标只在 `update_goal_on_success=True` 时累加，
而 Baseline 用的是 SingleGoal 模式——到达即终止、不重采目标，
所以计数器永远不会加。

正确的判据是 `Episode_Termination/goal_reached`。

**教训**：**指标显示 0，要先区分"真的是 0"还是"这个指标压根不产生数据"。**
差点因为这个把一个成功的修复判成失败。

### 坑 3 · 对照脚本自己是错的

Part 2 跑到一半时顺手跑了对照分析，脚本报"陷入站着不动局部最优"——
而且精确复述了坑 1 的真实结论，很有欺骗性。

两个 bug 叠在一起：
1. 分组按目录名，但两个任务共用 `experiment_name`，日志落在同一目录，
   于是把正在跑的 RandomArena 当成了 baseline
2. 判据用的正是坑 2 里已经识破的 `goals_reached`

**教训**：**修好了一处认知，要顺手 grep 一遍所有实现了同一判据的地方。**
「知道 X 是错的」和「代码里没有 X」是两回事。

## 6. 结果

### Part 1

| 指标 | 数值 |
|---|---|
| 到达率 | **97.7%** |
| 收敛轮数 | 984（官方推荐 30000，占 **3%**） |
| 位置进展奖励 | +0.00165（正值 = 确实在朝目标移动） |
| 距离误差 | 6.772 → 0.461 m |

### Part 2 · 难度扩展（随机重排障碍）

把固定竞技场换成**每个 episode 重新随机排布障碍**，
其余全部不变（同一份 PPORunnerCfg、同一 seed），是严格的单因素对照。

截到共同的 984 iter 比较：

| | 到达率 |
|---|---|
| Baseline（固定布局） | 97.72% |
| RandomArena（随机重排） | 97.08% |

差距 **+0.64%**，在噪声范围内。

**这个结果说明什么**：策略学到的不是"记住这张地图的通路"，
而是真的在用 height scan 绕障——换一张布局照样走得通。
如果策略是靠记忆，随机化布局后性能应该显著下降。

## 7. 面试可能怎么问

**Q1（概念）：什么是分层强化学习？为什么导航任务适合分层？**

分层是把策略拆成多层，上层输出下层的指令而不是环境的原始动作。
导航适合分层是因为**时间尺度分离**：保持平衡是毫秒级反馈，
路径决策是秒级决策。合在一个网络里，策略还没学会站稳就没机会
体验到到达目标的奖励。分层后高层的动作空间从 29 维降到 3 维，
且每维都有物理含义。

**Q2（实现）：高层的动作为什么要裁剪？不裁剪会怎样？**

低层策略是在特定速度范围内训练的（$v_x \in [-0.5, 1.0]$ 等）。
超出这个范围就是**分布外输入**——低层不会报错，但输出是未定义的。
更隐蔽的是：观测里也必须用**裁剪后**的值，因为那才是低层实际收到的指令。
用裁剪前的值会让高层对"我给了什么"产生错误认知。

**Q3（实现）：为什么高度扫描要做 2×2 池化？为什么是最大池化？**

1092 维直接进网络，第一层权重会爆炸，且相邻射线信息冗余。
用最大池化是因为导航关心"能不能过"——一个 2×2 区域里有一个高点就过不去，
取最大保留最坏情况；取平均会把障碍抹平。

**Q4（深挖）：讲一个你排查过的最难的 bug。**

（这题直接用 §5 坑 1。要点：现象与直觉相反、十一轮排除、
oracle 测试切分问题域、根因是默认参数、修复效果 0%→97.5%。
重点讲**怎么找到的**而不只是**是什么**。）

**Q5（深挖）：为什么 `update_history=False` 这个 bug 这么难发现？**

因为它不改变任何可观测的表面特征：张量形状正确（5 帧就是 5 帧）、
数值在合理范围、不抛异常、不产生 NaN。只有"内容重复"这一个特征，
而观测的具体数值本来就是难以肉眼判断的。这类**静默失效**只能靠
"手算一个最小例子去对"来发现。

**Q6（实现）：多时间尺度控制里，`apply_actions()` 为什么要在 `if` 外面？**

推理算出的是目标关节角，PD 控制器要在**每个物理步**根据当前角度与目标的差
算力矩。低层每 4 个物理步推理一次，但中间 3 步仍要用上次的目标持续做 PD。
写进 `if` 里就变成 3 个物理步没有力矩输出，机器人会抽搐。

**Q7（深挖）：Part 2 你怎么证明策略不是在"背地图"？**

设计单因素对照：只把固定布局换成每 episode 随机重排，其余全部不变。
如果策略靠记忆，随机化后性能应显著下降。实测差距只有 0.64%，在噪声内。

补充一点方法论：两组训练轮数不等（984 vs 2999）时不能直接比末值——
我把长的那组**截到共同的 984 iter** 再比，效果与重跑短的那组等价但省两小时。

## 8. 延伸：工业界怎么用

分层与技能复用是当前人形机器人的主流范式：

- **Unitree / 宇树**的产品线里，行走、跳跃、翻滚是分别训练的技能，
  上层做技能切换与组合
- **Boston Dynamics Atlas** 的跑酷演示，公开资料显示也是分层结构
- 论文 *Perceptive Humanoid Parkour*（本课程实践 10、11 的来源）
  用的是 Motion Matching 把多个技能拼接成长时域行为

这个实践对应的是"**技能调用层**"这一环。往上是技能库与任务规划，
