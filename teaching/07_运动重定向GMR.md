# 实践 7 教学文档 · 用 GMR 把人体动作重定向到 G1

> 这是给我自己面试前复习用的讲解稿。目标是把「运动重定向」从头讲清楚，
> 不假设你懂 SMPL-X、IK、四元数。读完能回答：这一步在整条技术栈里是什么位置，
> 为什么不能"直接抄人的关节角"，以及那几个静默出错的坑到底怎么回事。

---

## 0. 一句话概括

拿一段**人**的动作捕捉数据（真人走路、跑步、转弯），把它翻译成**G1 机器人**
能照着做的关节角轨迹，并存成实践 8 的 AMP 训练能直接读取的 `.npz` 文件。

一句话里有两个动作：**翻译**（重定向）和**打包**（存成规范格式）。作业的 20 分
里，翻译占大头，但打包错了同样是零分——因为下游读不进去。

---

## 1. 问题从哪来（Why）

### 不做这件事会怎样

实践 8 的 AMP 要教机器人"走得像人"。要"像人"，就得先有一份"人是怎么走的"的
参考数据。但人体动捕数据描述的是**人的骨架**（一套关节、一套骨长比例），
机器人是**另一套骨架**（G1 有 29 个自由度，骨长、关节范围都不一样）。

如果不翻译，直接把人的关节角发给 G1，会发生什么？举个具体的：人的髋关节可以
外展 45°，G1 的髋 roll 限位可能只有 30°；人的手臂比腿长的比例和 G1 不同。
直接复制的结果是**关节越界被仿真截断、脚不落地、身体比例失调**——动作根本不成立。

所以中间必须有一层"翻译器"，这就是 GMR（General Motion Retargeting）。

### 为什么不能用更简单的办法

面试常问"为什么不直接一一对应关节角"。答案是三条结构差异：

1. **自由度不一致**：人体腰、肩、脚的自由度和 G1 不完全对得上。
2. **尺寸比例不同**：人臂长/腿长比例 ≠ 机器人，硬拷会让手脚位置错位。
3. **关节范围不同**：人的动作可能超出 G1 的物理限位。

正确做法不是"对关节"，而是"对**关键身体点的位置和朝向**"——让 G1 的脚踝、手腕、
骨盆去**够到**人对应部位所在的地方，具体每个关节转多少由**逆运动学**求解。
这样即使骨架不同，"动作看起来一样"这件事也能保住。

## 2. 核心概念（零基础可懂）

### SMPL-X（人体参数化模型）

- **生活化类比**：像一个"人体的乐高说明书 + 万能人偶"。给它一组数字（身材参数
  betas、每个关节转多少的 pose 参数、根节点在哪），它就能摆出一个具体的人体姿态，
  还能生成整张皮肤网格。
- **严格定义**：SMPL-X（Skinned Multi-Person Linear model - eXpressive）是一个
  参数化的人体模型，用低维参数（形状 + 姿态）驱动一套固定拓扑的骨架和网格。
- **在本实践中**：AMASS/ACCAD 数据集里每条动作就是一串 SMPL-X 参数
  （`pose_body`、`betas`、`root_orient`、`trans`）。代码里
  `smplx.create(...)` 加载模型模板，喂参数后 `body_model(...)` 输出每帧的人体关节。
  文件是 `SMPLX_{NEUTRAL,MALE,FEMALE}.pkl`——这三个 `.pkl` 是"人偶本体"，
  ACCAD 是"让人偶做的动作"，两者缺一不可。

### 正运动学 FK 与逆运动学 IK

先给类比，再给定义，这两个是本实践的核心。

- **正运动学 FK（Forward Kinematics）**
  - 类比：你告诉我"肩转 30°、肘弯 90°"，我告诉你"你的手现在在空间哪个点"。
    从**关节角**推**末端位置**，答案唯一、算一遍就出。
  - 定义：给定根节点位姿和所有关节角，计算每个连杆在空间中的位置与朝向。
  - 本实践用它算 `local_body_pos`（见 §4）。

- **逆运动学 IK（Inverse Kinematics）**
  - 类比：反过来——你说"我要把手放到那个杯子上"，我要算出"肩、肘、腕各转多少"。
    从**目标位置**反推**关节角**，可能有多解、也可能无解，要靠优化去逼近。
  - 定义：给定末端（关键身体点）的目标位置/朝向，求解满足约束的关节角。
  - 本实践里 GMR 就是拿人的关键点当目标，IK 求 G1 的根位姿 + 29 个关节角。

一句话记牢方向：**FK 是"角度→位置"（好算），IK 是"位置→角度"（难算，要优化）**。
重定向的难点全在 IK：目标够不到、越限位、多解不稳定，都发生在这一步。

### 四元数与 wxyz / xyzw 约定

- **生活化类比**：描述"一个物体转到什么朝向"，可以用欧拉角（绕 x/y/z 各转多少），
  但欧拉角有万向锁、插值不平滑。四元数是另一种记法——用 4 个数
  `(x, y, z, w)` 表示旋转，没有万向锁、插值平滑。
- **严格定义**：单位四元数 q = (x, y, z, w)，满足 ‖q‖ = 1，表示三维空间中的一个旋转。
- **关键陷阱——分量顺序**：同样这 4 个数，有的库把实部 w 放**最前**（`wxyz`），
  有的放**最后**（`xyzw`）。MuJoCo 用 `wxyz`，AMP 数据规格要求 `xyzw`。
  这两种排列**数值合法、都不报错**，但含义完全不同。

### 运动重定向（Retargeting）

- **类比**：给不同身材的演员**替身**同一段舞蹈。动作的"意思"一样（走、跳、转），
  但每个人的关节怎么动不一样。
- **定义**：把源骨架（人）的运动映射到目标骨架（机器人），在保持动作语义的前提下，
  适配自由度、尺寸和关节范围差异。
- **在本实践中**：`AMASS SMPL-X → GMR → G1 参考动作 → AMP npz`。

## 3. 算法原理

### GMR 在"做什么"

一句话：**以人的关键身体点为目标，用 IK 求出 G1 的根位姿和关节角**。

官方把完整适配流程拆成 7 步，理解顺序即可：

1. 坐标系对齐（人和机器人的世界系方向对齐）
2. 零位姿态（rest pose）对齐（T-pose 对 T-pose）
3. 人体与机器人局部尺度调整（按身高缩放，代码里 `actual_human_height` 参与）
4. 人体关键身体 → 机器人连杆的映射（`smplx_to_g1.json` 定义谁对谁）
5. 位置和旋转约束下的 IK 求解（核心，得到根位姿 + 29 关节角）
6. 关节角范围与速度限制约束（别越界、别跳变）
7. 足部接触与动作质量检查（别滑脚、别穿模）

### 单帧的输出

GMR 把机器人的每一帧表示成 MuJoCo 的 `qpos`（free joint 布局）：

```
qpos[0:3]   根节点位置 root position
qpos[3:7]   根节点四元数 root quaternion —— 注意是 wxyz
qpos[7:]    29 个关节角
```

### local_body_pos 的公式，逐符号解释

AMP 需要一个"和机器人走到哪、朝哪无关，只反映姿态构型"的特征，就是
`local_body_pos`——各连杆在**根节点坐标系**下的位置：

```
p_i^b = R_b^{-1} · (p_i^w − p_b^w)
```

- `p_i^w`：第 i 个连杆在**世界坐标系**的位置。
- `p_b^w`：根节点（骨盆）在世界坐标系的位置。
- `R_b`：根节点的旋转矩阵；`R_b^{-1}` 是它的逆（把世界系的向量转回根节点系）。
- `p_i^b`：第 i 个连杆在**根节点坐标系**下的位置，就是我们要的量。

**这一项去掉会怎样**：如果直接存世界系位置 `p_i^w`，那"机器人走了 3 米"这件事
会混进特征里。实践 8 的判别器就能靠"这条轨迹从哪开始、走到哪"来区分策略和专家，
风格奖励退化成"位置检测器"，学不到步态风格。减去 `p_b^w` 是去掉平移，
乘 `R_b^{-1}` 是去掉朝向——两步都做完，剩下的才是纯粹的"姿势"。

### 作业要求的算法：怎么算 local_body_pos

作业明确给了一个巧妙的做法——**不要从世界系连杆位置去减**，而是：

```
root position = [0, 0, 0]
root rotation = identity（单位四元数）
joint position = dof_pos
        ↓  G1 forward kinematics（正运动学）
    local_body_pos
```

把根节点"钉在原点、朝向摆正"，只用关节角跑一遍 FK。得到的连杆位置天然就在
根节点系里——因为根节点本来就在原点。这等价于上面的公式，但更不容易出错。

## 4. 代码走读

核心代码在 `repos/GMR/scripts/smplx_to_robot_npz.py`（单条）和
`smplx_to_robot_dataset_npz.py`（批量）。挑三段最能体现"为什么这么写"的。

### ① 四元数重排（`qpos_to_fields`, 第 76~92 行）

```python
qpos = np.asarray(qpos_list, dtype=np.float64)
root_pos = qpos[:, 0:3].copy()
root_pos[:, :2] -= root_pos[0, :2]          # 只把首帧 xy 平移到原点，不动 z
root_rot_wxyz = qpos[:, 3:7]
root_rot = root_rot_wxyz[:, [1, 2, 3, 0]]   # wxyz → xyzw
norms = np.linalg.norm(root_rot, axis=1, keepdims=True)
root_rot = root_rot / norms                 # 归一化，模长拉回 1
dof_pos = qpos[:, 7:]
```

- `[1, 2, 3, 0]` 这个索引在**重排列**：原来 `[w, x, y, z]`，取第 1、2、3、0 位
  就得到 `[x, y, z, w]`。这跟官方给的 `root_rot_wxyz[:, [1,2,3,0]]` 逐位一致。
- **为什么只平移 xy 不动 z**：z 要保持"脚接近地面"的绝对高度。平移了 z，
  机器人会整体悬空或陷进地面。官方样例首帧 xy 恰好是 `[0,0]`，说明这是**约定**
  而非可选（我第一版漏了这条，见 §5）。
- **张量形状**：`qpos` 是 `(T, 36)`（3+4+29），切出来 `root_pos (T,3)`、
  `root_rot (T,4)`、`dof_pos (T,29)`。

### ② 用 FK 算 local_body_pos（`compute_local_body_pos`, 第 118~128 行）

```python
root_pos = torch.zeros(n, 3)          # 根节点放原点
root_rot = torch.zeros(n, 4)
root_rot[:, 3] = 1.0                   # 单位四元数（xyzw，w=1 在末位）
dof = torch.as_tensor(dof_pos)
with torch.no_grad():
    body_pos, _ = km.forward_kinematics(root_pos, root_rot, dof)
return body_pos.cpu().numpy().astype(np.float32), list(km.body_names)
```

- 完全对应 §3 的算法：根节点归零、姿态摆正、只喂关节角跑 FK。
- `km.body_names` 与 `body_pos` 的第二维**逐项对应**，所以 `link_body_list`
  直接取它，保证名字和坐标不错位。实测这 38 个连杆和课程样例顺序完全一致。
- **形状**：`body_pos` 是 `(T, N, 3)`，N=38。

### ③ 落盘前自检（`validate`, 第 131~158 行）

代码在 `np.savez` 之前跑一串断言。最有意思的一条是**物理兜底**：

```python
("局部坐标合理（最低点为负）",
 float(data["local_body_pos"][..., 2].min()) < 0.0),
```

根节点（骨盆）在原点做 FK，脚必然在骨盆**下方**，所以所有连杆 z 的最小值应为负。
如果算错了坐标系或连杆顺序，这个值会变正——一条断言就能抓住。
这比"维度对不对"更狠：维度对了不代表**内容**对，得用物理量卡。

### 为什么惰性导入 SMPL-X（第 51~56、162~168 行）

`import smplx` 被放进 `main()` 里，而不是文件顶部。原因：核心导出逻辑
（四元数重排、FK、自检）只依赖 numpy + torch + `KinematicsModel`，**不依赖 SMPL-X**。
把 import 下沉后，"没装 SMPL-X 也能单独测导出逻辑"——而导出恰恰是最容易静默出错的部分。
配套的 `verify_practice7_npz_export.py` 就是这么做的：不跑 GMR，直接拿样例
`dof_pos` 重算 `local_body_pos`，与样例自带值比对，**逐点误差 1 微米**。

## 5. 我踩过的坑（面试素材）

### 坑一：smplx 库默认 `ext='npz'`，课程发的是 `.pkl`

```
现象：加载人体模型时报 AssertionError，去找一个不存在的 SMPLX_MALE.npz。
第一反应：以为是模型文件没放对位置，或者下载的文件损坏了。
为什么这么想是错的：文件其实放对了，是 SMPLX_MALE.pkl；错在"库默认去找 .npz"。
      缺的信息是——smplx 的 SMPLX 类构造参数 ext 默认值是 'npz'
      （body_models.py:927），它会用这个后缀去拼文件名。
怎么找到真因：读 smplx 源码里 create() 怎么拼路径，发现它按 ext 拼后缀。
      课程给的是 .pkl 三件套，所以必须显式传 ext="pkl"。
根因：库的默认后缀与课程发的模型格式不一致。
教训：报"文件不存在"时，先看它到底在找哪个文件名——往往不是你放的那个。
      第三方库的默认参数要当心，尤其是文件后缀、设备、dtype 这类"隐性约定"。
```

代码里的修复（`general_motion_retargeting/utils/smpl.py:24`）：

```python
body_model = smplx.create(smplx_body_model_path, "smplx",
                          gender=str(smplx_data["gender"]),
                          use_pca=False,
                          ext="pkl")   # ← 不加这行就会去找 SMPLX_MALE.npz
```

```
现象：无。第一版导出的数据能加载、能播放，一切正常。
```

## 6. 面试可能怎么问

**概念题**

1. *IK 和 FK 有什么区别？重定向为什么必须用 IK？*
   FK 是"关节角→末端位置"，唯一解、直接算；IK 是"末端目标→关节角"，多解/无解、
   要优化。重定向的目标是让机器人关键点够到人对应部位的位置，这是"位置→角度"，
   所以是 IK。而算 `local_body_pos` 反过来是"角度→位置"，用 FK。

2. *为什么不能直接复制人的关节角给机器人？*
   自由度、骨长比例、关节范围三者都不同。直接复制会越界、脚不落地、比例失调。
   要对齐的是关键身体点的位置和朝向，不是关节角本身。

3. *wxyz 和 xyzw 差在哪？写错会怎样？*
   实部 w 放最前还是最后。MuJoCo 是 wxyz，AMP 规格是 xyzw。写错不报错，
   会让机器人整体倒置或朝向乱掉。判据：人形直立行走 w 应显著最大，
   实测样例 `[0.024, 0.025, 0.378, 0.862]`，最大值在末位 → xyzw。

**实现题**

4. *`local_body_pos` 怎么算的？为什么不能存世界坐标？*
   根节点放原点、姿态置单位四元数、只喂关节角跑 FK。存世界坐标会把全局位移
   混进风格特征，判别器靠位置就能作弊。

5. *npz 必须有哪 6 个字段？为什么要 `allow_pickle=False`？*
   `fps / root_pos / root_rot / dof_pos / local_body_pos / link_body_list`。
   `allow_pickle=False` 是实践 8 为了避免不安全的对象反序列化——存了 `dtype=object`
   或 `None` 就读不进去。所以 `link_body_list` 必须转成 Unicode NumPy 数组。

6. *怎么验证重定向结果是对的？*
   拿参考样例的 `dof_pos` 重算 `local_body_pos`，和样例自带值比对（我们做到 1 微米）；
   再加物理断言：最低连杆 z 为负（脚在骨盆下）、四元数模长≈1、脚高波动小（有支撑相）。

**深挖题**

7. *重定向的错误大多不报错，你怎么保证质量？*
   分三类查：格式（维度/字段/NaN）、约定（四元数顺序/模长/符号跳变）、物理
   （根高合理、脚接近地面、支撑相脚高波动小、速度不尖峰）。可证伪的检验优先——
   比如逐点误差比对，任何一处错都会让误差爆掉。

8. *为什么把 FK 放 CPU、不跟训练抢 GPU？*
   数据量只有几十条动作，FK 不是瓶颈；放 CPU 能和 GPU 训练并行跑，
   不必排队等显存。这是工程取舍，不是原理要求。

## 7. 延伸：这个技术在工业界怎么用

运动重定向是"人类示范 → 机器人技能"这条链路的入口。工业界的用法：

- **数据放大**：动捕一次，重定向到多种机器人（G1、H1、其它人形），一份人类数据
  喂多个平台。AMASS 就是把几十套动捕统一成 SMPL-X 参数，正是为批量重定向服务。
- **模仿学习/对抗模仿**：重定向产物作为"专家数据"，喂给 AMP（实践 8）、
  DeepMimic、AMASS-based tracking 等，让策略学到自然步态。本实践的产物直接接实践 8。
- **完整技术栈里的位置**：`动捕 → 重定向 → 参考轨迹 → 模仿/跟踪训练 → sim2sim → 真机`。
  实践 7 是第二环，它的正确性是后面所有环节的前提——一次错误会一路传到真机且极难回溯。
