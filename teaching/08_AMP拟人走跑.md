## 0. 一句话概括

不手写"走得像不像人"的奖励函数，而是**训练一个裁判（判别器）去学**什么叫像人。
裁判越觉得机器人的动作"像专家数据"，就给越高的风格奖励；这个风格奖励和原本的
速度跟踪奖励加权相加，一起喂给 PPO，最后机器人既跟得上速度指令、动作又自然。

> **PPO** 就是这个项目里所有实践都在用的那个强化学习算法
> （Proximal Policy Optimization，近端策略优化）。
> 你只要记住它是"把奖励变成策略更新"的引擎：给它一堆
> `(状态, 动作, 奖励)`，它就朝着"让高奖励动作更容易出现"的方向调网络参数。
> 本文重点不是 PPO 本身，而是**那个奖励从哪来** ——
> 通常是人手写的，而 AMP 让它由一个判别器学出来。
> （PPO 的原理见 [`00_RL算法原理_零基础完全讲解.md`](00_RL算法原理_零基础完全讲解.md) §11.3「PPO 的核心：clip」）

## 1. 问题从哪来（Why）

### 不做这件事会怎样

纯速度跟踪任务的奖励只写了一件事：**"你有没有达到目标速度"**。它压根没描述
"你是怎么达到的"。于是 PPO 会找出各种**达标但不像人**的捷径：

- 僵硬地迈步、几乎不摆臂；
- 高速时脚在地上打滑（滑步），因为滑步也能凑出速度；
- 姿态别扭但数值上速度达标。

这些在奖励函数里**都不违规**——因为奖励根本没提"自然"这回事。

### 为什么不能用更简单的办法

面试常问"为什么不直接手写'像人'的奖励项"。试过的人都知道，"像人"极难量化：
你要为摆臂幅度、步频、髋膝协调、落脚方式……每一项都写一个奖励项并调权重，
这是无穷无尽的手工特征工程，而且不同动作（走 vs 跑）的"像人"标准还不一样。

AMP 的思路是把这件事**外包给数据**：给一堆真人重定向来的专家动作，让一个神经网络
判别器自己去学"专家动作长什么样"。你不用说清"像人"的定义，判别器从数据里学。

> 这正是实践 7 的产物在这里的用处：`GMR 重定向的专家动作` 就是判别器要模仿的目标。

## 2. 核心概念（零基础可懂）

### 判别器（Discriminator）

- **生活化类比**：一个"鉴宝专家"。给它看一段动作，它判断"这是真专家做的
  还是机器人瞎凑的"。看得多了，它越来越会挑刺。
- **严格定义**：一个把"运动窗口"映射到一个分数的神经网络 D(x)。分数高 → 判为专家，
  分数低 → 判为策略。
- **在本实践中**：`AMPDiscriminator`（`discriminator.py`），一个输入 240 维、
  输出 1 维的 MLP。

### 对抗训练（Adversarial / GAN 思路）

- **生活化类比**：造假币的人和验钞机在**互相较劲**。验钞机越来越会认假币，
  造假的越来越像真的。两边一起进步，最后假币（策略动作）逼近真钞（专家动作）。
- **严格定义**：两个网络对抗优化——判别器学着区分两类，生成方（这里是策略）
  学着骗过判别器。均衡时两者难分。
- **在本实践中**：判别器学着分开"专家 vs 策略"，策略通过"风格奖励"学着让自己的
  动作被判别器判成专家。注意策略不是直接对抗判别器梯度，而是**通过奖励**间接对抗。

### 为什么判别器输入是"一段窗口"而不是单帧

- **类比**：给你一张**照片**，你分不清这人是在"走"还是在"跑"——都是一条腿在前。
  给你连续几帧，你立刻看出步频和摆动。**步态是时间上的模式，单帧看不出**。
- **本实践**：判别器输入是长度 H=3 的窗口，形状 `[B, H, d_amp] = [B, 3, 80]`，
  展平成 240 维。B 是并行环境数，d_amp=80 是单帧特征维度（下面拆解）。
- **去掉时间维会怎样**：判别器只能比"这一帧的姿势像不像"，学不到"步频/节奏"这类
  动态风格，风格奖励就管不住滑步、抽步这些**时序**问题。

### 单帧 80 维特征 d_amp

作业规定单帧特征 = `3 + 3 + 3 + 1 + 29 + 29 + 4×3 = 80`：

| 分量 | 维度 | 是什么 |
|---|---|---|
| base_lin_vel | 3 | 基座线速度 |
| base_ang_vel | 3 | 基座角速度 |
| projected_gravity | 3 | 重力在基座系的投影（等于告诉网络"身体歪没歪"） |
| base_height | 1 | 基座高度 |
| joint_pos | 29 | 29 个关节角 |
| joint_vel | 29 | 29 个关节速度 |
| key_links_pos_b | 4×3 | 双脚踝 + 双腕相对基座的位置 |

**全部是基座坐标系的量**，不含世界系位置/朝向——因为专家数据来自 GMR 重定向，
它在世界的哪个位置和仿真里的机器人无关，只有基座系特征才可比。这与实践 7 里
`local_body_pos` 必须用局部坐标是**同一个道理**。

### 风格奖励（Style Reward）r_amp

- **类比**：裁判打的"艺术分"。它不管你跑多快（那是任务分），只管你动作好不好看。
- **定义**：把判别器分数经过一个有界函数变成 [0,1] 的"运动质量"，再乘步长和缩放。
- **本实践**：`r_amp = Δt · β · q(D(x))`，公式细节见 §3。

### 参考状态初始化（RSI, Reference State Initialization）

- **类比**：教小孩跑步，不总是从"站着"开始，有时**直接把他摆到跑步中途**的姿势，
  让他体会那一刻该怎么发力。
- **本实践**：`reset_from_reference_motion`（env cfg 里 `probability=0.5`），
  一半环境重置时从专家动作的**随机时刻**开始，让策略更快接触走/跑/转弯的各种状态，
  而不是每次都从静止慢慢探索。

### 非对称 actor-critic

- **类比**：考试时**学生（actor）只能看到带噪的题面**，但**改卷老师（critic）
  能看到标准答案**。老师评估得准，学生练的是"在信息不全时也能答对"。
- **本实践**：三路观测 `policy / critic / amp`。actor 用带噪、含指令的 policy 观测；
  critic 可用无噪、含特权信息的观测；amp 是无噪的 80 维风格特征。

## 3. 算法原理

### 3.1 判别器损失（LSGAN + 梯度惩罚）

这套代码用的是**最小二乘 GAN（LSGAN）**，不是经典的交叉熵 GAN。损失有三部分
（`discriminator.py:111` `loss()`）：

**① 分类损失（把两类推向 ±margin）**

```
L_cls = 0.5 · [ E(D(x_policy) + m)²  +  E(D(x_expert) − m)² ]
```

- `m` 是 margin（我们取 0.8）。
- 策略样本目标是 `−m`，专家样本目标是 `+m`。
- 直觉：不是"越大越好"，而是**各自逼近一个固定靶子**。LSGAN 用平方误差，
  比交叉熵更稳，不容易梯度爆炸。

**② logit 正则**

```
L_logit = 0.5 · λ · [ E(D(x_policy)²) + E(D(x_expert)²) ]
```

- 惩罚分数的绝对大小（λ=0.05），防止判别器把分数推到极端，间接控制饱和。

**③ 梯度惩罚（R1，只对专家样本）**

```
L_gp = 0.5 · w_gp · E‖∇_x D(x_expert)‖²
```

- `w_gp=10`。它惩罚判别器在**专家样本附近**的梯度大小。
- **去掉这一项会怎样**：判别器会迅速把两类完全分开、分数饱和，然后
  **风格梯度消失**——策略再怎么改动作，判别器分数都不变，风格奖励失去指导意义。
  梯度惩罚强迫判别器决策面"平缓"，训练更持久。这就是作业里说的
  "梯度惩罚用于限制判别器在专家样本附近的梯度，避免判别器过快饱和"。

总损失 `L_D = L_cls + L_logit + L_gp`。

### 3.2 从分数到风格奖励（TODO3）

**运动质量函数（LSQ 模式）**：

```
q(s) = clamp(1 − 0.25·(s − 1)² , 0, 1)
```

- `s = D(x)` 是判别器分数。当 s→1 时 q→1（最像专家），偏离 1 时 q 下降，
  且被 clamp 在 [0,1]。
- **为什么要有界**：如果直接用无界的分数当奖励，判别器一旦自信起来分数飙高，
  风格奖励就会**盖过任务奖励**，策略变成"只管像人、不管走到哪"。有界的 q 天然
  不会失控。

**风格奖励**：

```
r_amp = Δt · β · q(s)
```

- `Δt` 是控制步长（`sim.dt × decimation = 0.02`），`β` 是 `reward_scale`（=5）。
- **为什么要乘 Δt**：判别器给的是"每秒的风格收益率"，而 PPO 累加的是每步奖励。
  不乘 Δt 的话，同一策略在不同控制频率下拿到的风格奖励总量不同，风格项与任务项的
  相对强度会随 decimation 悄悄漂移。乘上 Δt 后单位统一，换频率也稳定。
- 上界 = `Δt·β = 0.02×5 = 0.1`，所以 `r_amp ∈ [0, 0.1]`。

### 3.3 奖励混合（TODO4）

```
r = (1 − α)·r_amp + α·r_task
```

- `α = task_reward_weight`。`walk_to_run` 里 α=0.5。
- α=0 → 纯风格（只管像人）；α=1 → 纯任务（等价于关掉 AMP）。
- **α 怎么取**：`walk_to_run` 取 0.5 让风格和任务等权。理由：比 Walk 的 0.6 低
  （走跑切换更依赖专家示范的步态转换），比基类的 0.4 高（必须真跟上高速指令才谈得上"跑"）。
- α=0/1 这两个端点是验证时的强约束：α=1 时风格奖励必须**完全不起作用**，
  这一条能直接抓出"混合方向写反"的错误。

### 3.4 GAN 不稳定怎么治：自适应判别器预算

GAN 最出名的毛病是**不稳定**——判别器太强则风格梯度消失，判别器太弱则风格奖励没意义。
除了上面的梯度惩罚，这套代码还加了一个"平衡控制器"（`amp_stability.py`）:

```python
def recommended_updates(self, policy_score, expert_score):
    saturated = (policy_score <= -0.7 and expert_score >= 0.7)
    return 0 if saturated else 4      # 饱和就暂停更新判别器
```

- 每轮先探一下判别器：如果它已经把策略分推到 ≤−0.7、专家分推到 ≥+0.7
  （即**已经分得很开**），就**这一轮不再更新判别器**，让策略先追上来。
- 否则更新最多 4 次。这样判别器和策略保持"势均力敌"，谁都不会碾压对方。
- **实测印证**：训练后期常看到 `amp_discriminator_updates` 掉到 0——不是坏了，
  是控制器判断判别器够强了、主动歇一轮。

## 4. 代码走读

### ① 判别器：分数 → 奖励（`discriminator.py:82` `style_reward`）

```python
@torch.no_grad()
def style_reward(self, samples, step_dt):
    score = self.forward(samples)                 # 判别器原始分数
    quality = self.quality_from_score(score)      # q(s)，clamp 到 [0,1]
    style_rewards = step_dt * self.reward_scale * quality   # r_amp = dt·β·q
    return style_rewards, score                   # 同时返回 score 供日志
```

- 为什么**同时返回 score**：训练日志里要看 score 分布才能判断判别器有没有饱和
  （score 顶到 ±margin = 分得太开）。只看奖励看不出这个。
- `@torch.no_grad()`：算奖励不需要梯度，风格奖励对策略是"环境给的常数"，
  策略通过 PPO 间接优化它，而不是对判别器求导。

### ② 环境步：谁能拿风格奖励（`amp.py:135` `process_env_step`）

```python
next_age = self._amp_history_age + 1
valid_windows = next_age >= self.history_steps       # 攒够 3 帧才算数
...
mixed_rewards = self.discriminator.mix_rewards(style_rewards, rewards)
# 历史不足 3 帧的环境，退回纯任务奖励
mixed_rewards = torch.where(valid_windows, mixed_rewards, rewards)
...
self._amp_history_age = torch.where(dones.bool(), 0, next_age)   # episode 结束清零
```

- `_amp_history_age` 记录每个环境攒了几帧。**刚 reset 的环境**窗口里混着上一条
  轨迹的残帧，这时的判别器分数是假的。所以 `valid_windows` 为假的环境**退回纯任务奖励**，
  不让假风格信号污染训练。这是 TODO5 的核心。
- `torch.where(dones, 0, next_age)`：episode 一结束就把计数清零，下条重新攒。

### ③ 判别器更新：受平衡控制器调度（`amp.py:213` `update`）

```python
updates = self.discriminator_balance.recommended_updates(
    probe["policy_score"], probe["expert_score"])   # 0 或 4
for _ in range(updates):
    policy_samples = self.replay_buffer.sample(batch)   # 策略样本来自回放缓冲
    expert_samples = self._expert_samples_for(policy_samples)  # 专家样本来自数据集
    losses = self.discriminator.loss(policy_samples, expert_samples)
    losses["total"].backward()
    ...
    if self.discriminator_balance.recommended_updates(...) == 0:
        break                                    # 中途分开了就提前停
```

- **策略样本来自回放缓冲区**（`ReplayBuffer`），不是只用当前一步——这样判别器
  既看近期策略、又不会只盯着最新一帧过拟合。这是作业里 `ReplayBuffer` 的作用。
- **专家样本独立采样**，与策略的目标/状态无关（`_expert_samples_for` 直接从
  `expert_sampler` 抽），保证判别器学的是"分布差异"而不是"配对差异"。

### ④ 观测契约：顺序必须对齐（`amp_flat_env_cfg.py:57`）

```python
class AMPCfg(ObsGroup):
    base_lin_vel = ObsTerm(func=mdp.base_lin_vel)      # 顺序必须与
    base_ang_vel = ObsTerm(func=mdp.base_ang_vel)      # motion_dataset.py 的
    projected_gravity = ObsTerm(func=mdp.projected_gravity)  # AMP_FEATURE_ORDER
    base_height = ObsTerm(func=mdp.base_pos_z)         # 逐项一致
    joint_pos = ObsTerm(func=mdp.joint_pos)
    joint_vel = ObsTerm(func=mdp.joint_vel)
    key_links_pos_b = ObsTerm(func=key_link_positions_in_base, ...)
    def __post_init__(self):
        self.enable_corruption = False   # 不加噪
        self.concatenate_terms = True    # 拼成单个 [B,80] 向量
```

- **`enable_corruption = False`**：如果策略侧加噪、专家侧无噪，判别器可以直接靠
  "有没有噪声"区分两者，风格奖励退化成**噪声检测器**。这是个很隐蔽的失效。
- 顺序错位**不报错**，只让判别器学到"第 i 维在两个分布里含义不同"这种伪差异。

### 坑一：`clip_weights` 引用了数据集里不存在的片段

这是最有代表性的坑，直接来自实践 7 参考答案点名的检查项。

```
现象：启动 walk_to_run 训练直接抛
      ValueError: AMP clip weights reference missing clips: B3_-_walk1 ...
第一反应：以为是数据没拷全，或者路径配错了。
为什么这么想是错的：数据确实拷了，但原表引用的 B3_-_walk1 / B5_-_walk_backwards /
      B9_-_walk_turn_left_(90) 出自 ACCAD 的 Male1Walking_c3d 子集，

怎么找到真因：把 clip_weights 里的每个文件名拿去和 data/mixed/ 下实际文件逐一比对。
      发现两处对不上：
      (a) B3/B5/B9 这一批整个目录在发的包里不存在；
      (b) C14 文件名也对不上——源文件是 C14_-_run_turn_right_90_stageii
          （单下划线、无括号），原表写的是 C14_-__run_turn_right__(90)_stageii。
          同一批数据里 C11 反而是带括号的（来自 Female1Running 子集），
          两个子集命名风格不同，不能按一种模式套。
根因：motion_cfg.py 的采样权重表与实际重定向产物不同步。
教训：① 专家数据的文件名是"配置契约"，必须逐字对齐，不能靠模式猜。
      ② 缺一段专家数据会悄悄改变风格分布，训练出来步态不对却无任何提示——
         所以默认必须硬报错（`UNITREE_AMP_ALLOW_MISSING_CLIPS` 默认关），
         宁可启动即失败，也不要静默学错。
```

修复后的 `clip_weights`（`motion_cfg.py:122`）只保留**实际存在**的片段，
并保证三类覆盖齐全（走 `B1_-_stand_to_walk`、跑 `C3`、切换 `C5_-_walk_to_run`、

### 坑二：熵项符号写成加号（TODO6）

```
现象：训练早期策略迅速塌缩成几乎确定的动作，步态僵死，判别器轻易识破。
第一反应：以为是学习率太高或者奖励尺度不对。
为什么这么想是错的：真因在 PPO 总损失的熵项符号。
      L = L_policy + c_v·L_value − c_e·H(π)
      优化器是"最小化 loss"，而我们希望"最大化熵"（鼓励探索），
      所以熵项前必须是负号。写成 + 号会让优化器去"减小熵"，探索被扼杀。
怎么找到真因：盯 Policy/mean_std——健康时它从 0.8 缓慢收窄，
      写错时它会瞬间掉到接近 0（探索崩塌）。
根因：熵项符号写反，探索坍缩。
教训：这和实践 5 的"探索塌缩"是同一类失效。凡是"loss 最小化"和
      "某个量最大化"打架的地方，符号都要盯死。
```

## 6. 面试可能怎么问

**概念题**

1. *AMP 的核心思想一句话？*
   不手写"像人"的奖励，而是训练判别器从专家数据里学"像人"的定义，把判别器输出
   变成风格奖励，和任务奖励一起喂 PPO。

2. *判别器为什么看窗口不看单帧？*
   步态是时间上的模式。单帧看不出"走 vs 跑"、看不出滑步，必须有时序才能描述风格。
   我们用 H=3 帧，窗口 3×80=240 维。

3. *风格奖励为什么要有界、为什么乘 Δt？*
   有界（q∈[0,1]）防止判别器自信时风格奖励盖过任务奖励；乘 Δt 是把"每秒收益率"
   变成"每步奖励"，保证换控制频率时风格/任务的相对强度不漂移。

**实现题**

4. *`r = (1−α)r_amp + α·r_task` 里 α 怎么选？两个端点各是什么？*
   α 是任务权重。α=0 纯风格、α=1 纯任务（等价关掉 AMP）。walk_to_run 取 0.5，
   比 Walk 的 0.6 低、比基类 0.4 高。做"有无 AMP 对照"时跑 α=0.5 vs α=1.0 即可，
   不用改代码。

5. *刚 reset 的环境为什么不能用风格奖励？*
   它的窗口里混着上一条 episode 的残帧，判别器分数是假的。所以历史不足 3 帧的环境
   退回纯任务奖励（`torch.where(valid_windows, mixed, task)`）。

6. *AMP 观测为什么不加噪、为什么用基座系？*
   加噪的话判别器会靠"有没有噪声"区分策略和专家，风格奖励退化成噪声检测器；
   用基座系是因为专家数据来自 GMR 重定向，世界系位置/朝向与仿真机器人无关，不可比。

**深挖题**

7. *GAN 训练不稳定，你这套怎么治的？*
   三层：① 梯度惩罚（R1）压专家附近的梯度，防止判别器过快饱和；② logit 正则压分数
   绝对值；③ 自适应预算——判别器一旦把两类分到 ±0.7 就暂停更新，让策略追上来。
   实测能看到后期 `discriminator_updates` 主动掉到 0。

8. *怎么判断训练是不是走在正轨上？看哪几个指标？*
   `policy_score` 与 `expert_score` 要分向相反方向但都不饱和（我们实测 ∓0.70）；
   `style_task_ratio` 要 ~1（不失衡）；`episode_length` 要长（没摔）；
   `feet_slide` 要小（不滑步）；`mean_std` 缓慢收窄（在收敛而非塌缩）。
   判别器 loss 降低**不代表**策略学好了——这是作业特意强调的。

## 7. 延伸：这个技术在工业界怎么用

AMP 出自 SIGGRAPH 2021（Peng 等，"AMP: Adversarial Motion Priors for Stylized
Physics-Based Character Control"），最早用在**物理动画角色**上，后来被广泛搬到
人形/四足机器人：

- **风格与任务解耦**：任务奖励管"做什么"（速度、目标点），风格奖励管"怎么做得自然"。
  这套解耦让同一个任务能换不同风格库（走路库、跑步库、舞蹈库）而不改任务奖励。
  代码里的 `MOTION_CONFIGS`（walk / run / omni_run / walk_to_run / dance / mixed）
  就是这个思路——换 profile 就换风格。
- **减少奖励工程**：工业界最费人力的就是奖励调参。AMP 把"自然度"这块外包给数据，
  显著减少手写奖励项。
- **在完整栈里的位置**：`动捕 → 重定向(实践7) → AMP 专家库 → AMP+PPO 训练(本实践)
  → sim2sim → 真机`。本实践是"让策略学会自然运动"的一环，产物（策略）再往下做
  sim2sim（实践 11 的方法）和真机部署。
- **后续变体**：WASABI、AMP + 目标条件、多技能 AMP（一个判别器管多种风格）等。
  实践 11 的跑酷训练里也用到了 AMP/WASABI 式的动作参考学习。
