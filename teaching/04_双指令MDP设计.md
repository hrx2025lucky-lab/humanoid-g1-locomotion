## 0. 一句话概括

让一台 Unitree G1 人形机器人**一边按你给的速度走，一边按你给的高度蹲低或站高**——
你把高度滑块拉到 0.5 m，它就压低骨盆蹲着走；拉到 0.78 m，它就站直了走。
难点不在"让它会走"（这是已有的速度任务），而在**多加一条"高度指令"**并让它真正生效。
听起来只要加个"高度奖励"就行，但这恰恰是本作业最大的陷阱——只加奖励是不够的。

---

## 1. 问题从哪来（Why）

### 反面场景：只写高度奖励，机器人学会了"无视你"

假设我图省事，只做一件事：加一个奖励项，惩罚"骨盆实际高度和目标高度的差"。
训练完一看曲线，总回报涨得很漂亮。但一到 Viser 里拉高度滑块——机器人**纹丝不动**，
始终维持在某个固定高度走路，不管你要它蹲到 0.45 还是站到 0.80。

为什么？因为**策略的输入（观测）里根本没有"目标高度"这一维**。奖励函数在背后惩罚
"高度不对"，可策略压根**看不到**目标是多少，它只能瞎猜一个折中值一直用。
训练目标在数学上就**不成立**——你在考一个蒙着眼睛的学生"这道题的答案对不对"。

这就是本作业要立起来的核心认知：**"按指令做某事"这类任务，指令必须同时出现在
三个地方——采样端、观测端、奖励端。三者缺一，任务就退化。** 助教点名的最常见错误，
正是漏了"观测端"这一段。

### 为什么不用更简单的办法？

**"为什么不直接把高度写死成一个函数，不用强化学习？"**
因为蹲着走是个**全身协调**问题：压低骨盆会改变重心、缩短摆动腿的离地裕度、
改变落脚时机，这些耦合没法用一条解析规则表达。RL 让策略在几千个并行环境里
自己摸索出"蹲多低时该怎么迈腿"。

**"为什么不训练两个策略——一个站着走、一个蹲着走，用的时候切换？"**
因为你要的是**连续可调**（0.45~0.80 m 之间任意高度）和**平滑过渡**（边走边从站变蹲）。
离散地切两个策略，过渡瞬间会跳变、摔倒。单策略 + 连续指令才能覆盖整个区间。

## 2. 核心概念（零基础可懂）

### 概念一：MDP 与"指令型 MDP"

**生活化类比。** MDP（Markov Decision Process，马尔可夫决策过程）描述的是一个
"看情况 → 做决定 → 拿反馈 → 情况变了 → 再看再做"的循环。就像打游戏：
你看屏幕（状态）、按手柄（动作）、得分数（奖励）、画面更新（下一状态）。
"马尔可夫"是说**下一帧只取决于当前帧和你的操作，跟更早的历史无关**。

**四个要素落到本作业：**
- **状态/观测**：机器人自身的姿态、速度、关节角，**外加你给的指令**
- **动作**：23 个关节的目标角（和实践 3 一样，PD 控制器再转力矩）
- **奖励**：走得准 + 蹲得准 + 姿态好 - 各种不良行为
- **状态转移**：MuJoCo 物理引擎算出下一帧

**什么是"指令型 MDP"。** 普通 MDP 的目标是固定的（比如"尽量往前走"）。
指令型 MDP 把**目标本身也变成状态的一部分**——每个 episode 随机给一个目标
（"这次走 0.5 m/s、蹲到 0.6 m"），策略要学会"看目标办事"。
本作业的联合指令是一个 4 维向量：

```
c = [v_x, v_y, ω_z, h_cmd]
     前进  横移  转向  骨盆高度
```

其中高度指令 `h_cmd ~ Uniform(0.45, 0.80) m`——每次重采样时在这个区间**均匀**抽一个数。

**为什么用均匀分布而不是固定值或高斯？** 均匀分布保证 0.45~0.80 之间**每个高度都得到
同等训练量**。若用高斯，两端的极限蹲姿/站姿会欠训练——而那恰恰是最难、最能体现
"高度真的可控"的区域。

### 概念二：三段闭环（本作业的题眼）

**生活化类比。** 让厨房学徒"按订单做菜"，需要三件事同时成立：
① 有人把订单**递到**后厨（采样指令）；② 学徒**看得到**订单写的是什么菜（观测）；
③ 有个考核**按订单验菜**给他打分（奖励）。少了任何一个：没订单他不知道做啥；
看不到订单他只能瞎做；没考核他做错了也无所谓。三者缺一，"按订单做菜"就不成立。

```
① 采样高度指令   →   ② Actor 观测到指令   →   ③ 奖励高度跟踪
   TODO 1/3            TODO 4                   TODO 5/6
```

**这条闭环是全篇最重要的一句话。** 它的通用形式是：
**任何"按指令做某事"的任务，指令必须同时接入采样、观测、奖励三处。**
第 5 节的消融实验，就是逐段切断这条闭环来证明"缺一不可"。

### 概念三：坐标系——高度用世界系，速度用机体系

**生活化类比。**
- "骨盆离地多高"是个**绝对**概念——不管你面朝东还是朝西，蹲到 0.5 m 就是 0.5 m。
  这用**世界坐标系**（固定在地面上的参考系）。
- "往前走多快"是个**相对**概念——"前方"是相对机器人自己的朝向说的。
  你转个身，"前方"就换了方向。这用**机体坐标系**（固定在机器人身上、跟着它转的参考系）。

```
高度奖励  →  世界系   root_link_pos_w[:, 2]        （骨盆的世界 z 坐标）
速度奖励  →  机体系   root_link_lin_vel_b / ang_vel_b  （机体系下的线/角速度）
```

**为什么这是本作业最容易混淆的地方？** 因为高度和速度这两条指令**紧挨着**，
坐标系却相反。用错的后果很具体：如果速度误用世界系，机器人**转个身、同样的迈腿动作**
就会被算出完全不同的速度误差，策略永远学不会"朝自己前方走"。

> ⚠️ **高度用世界系只在平地成立。** 本作业地面 z ≡ 0，世界系 z 恰好等于离地高度。
> 实践 2 的粗糙地形上我栽过一次：下坡和倒金字塔楼梯的地面本身低于 0，
> 用世界系绝对高度做判据，会把姿态正常的机器人误判成"太矮 = 摔倒"。
> 那边的解法是用 `height_scanner` 先测出脚下真实地面高度再相减。

### 概念四：weight 和 std 是两回事

跟踪类奖励统一长这样：`r = exp(−error / std²)`。有两个旋钮，含义完全不同：

| 旋钮 | 通俗含义 | 决定什么 | 本作业取值 |
|---|---|---|---|
| `weight` | 这一项**有多重要** | 奖励的上限（乘在最外面） | 高度 1.0，速度 2.0 |
| `std` | **多大误差算"差"** | 曲线陡不陡（区分度） | 高度 0.1，线速度 0.5 |

**生活化类比。** `weight` 是"这门课占总分几个学分"，`std` 是"这门课判卷松还是严"。
两者独立：一门 1 学分的课也可以判得很严。

**为什么高度的 std（0.1）要比速度（0.5）严得多？** 因为高度指令的量程只有 0.35 m
（0.45~0.80），比速度窄得多。同样差 0.1：

```
std=0.1（高度）：差 0.10 m 得 exp(−1)   = 0.37 分；差 0.05 m 得 exp(−0.25) = 0.78 分  ← 有区分度
std=0.5（速度）：差 0.10 m 仍有 exp(−0.04)= 0.96 分                                  ← 几乎满分，没区分度
```

如果高度也用 0.5，整个 0.35 m 工作区间内奖励几乎恒定，**等于没有梯度**，策略学不到
"蹲得够不够"。（实践 5 踩过这个坑：`1−tanh(d/std)` 的 std 取小了，5~10 m 范围内恒等于 0。）

**为什么高度的 weight（1.0）反而比速度（2.0）小一半？** 这是刻意的：
**行走是主任务，高度是附加的姿态约束。** 若把高度权重提到 2.0，策略会为了把高度稳住
而牺牲步幅——蹲下来但走不动，甚至干脆站着不动（静止是很多奖励项的隐藏最优解，
实践 2 刚踩过）。1.0 让高度足以塑形、又不至于压倒主任务。

### 概念五：非对称 Actor-Critic 与特权观测

**生活化类比。** 训练时有两个角色：**Actor（运动员）**负责真正做动作，
**Critic（教练）**只负责给运动员的表现打分、指导训练，**比赛时教练不上场**。
既然教练只在训练时存在，就可以让他掌握一些**运动员比赛时拿不到的信息**——
比如场边的传感器数据。这叫**特权观测（privileged observation）**。

本作业里 `foot_contact`（脚是否触地，0/1）就是特权信息，**只给 Critic**：

```python
foot_contact = (sensor.data.found > 0).float()   # 只进 Critic 观测
```

**为什么这样分？** Actor 是最终要部署到**真机**的网络，真机上"脚触地"要靠足底力
传感器，未必可靠或存在，所以 Actor 不能依赖它。但仿真里这个信息免费且精确，
给 Critic 用能让价值估计更准 → 优势函数 `A = R − V` 方差更小 → 梯度更稳。
**让"打分的人"比"做事的人"看得更多**，这是特权学习的基本形态。

> ⚠️ **别把"指令"当成"特权信息"。** `height_command` 必须给 Actor——那是**任务输入**，
> 不给它策略就瞎了（这正是消融 B）。`foot_contact` 才是特权信息，只给 Critic。
> 这两者的区分是本作业一个高频混淆点。

## 3. 算法原理

### 三个跟踪奖励的结构：跟踪项 + 惩罚项，合体

三个跟踪奖励形式统一（都是 `exp(−error/std²)`），但**误差的构成**有讲究：

```python
# TODO 6 高度
height_error  = (h_cmd − z_root)²

# TODO 7 线速度
lin_vel_error = Σ(v_xy_cmd − v_xy_actual)²  +  v_z_actual²
                └──── 跟踪 xy ────┘           └─ 惩罚 z ─┘

# TODO 8 角速度
ang_vel_error = (ω_z_cmd − ω_z_actual)²  +  Σ(ω_xy_actual)²
                └──── 跟踪 yaw ────┘        └─── 惩罚 roll/pitch ───┘
```

**为什么把"惩罚项"并进跟踪误差，而不是单开一项？**
`v_z`（上下颠簸）和 `ω_xy`（左右摇晃、前后点头）都**不在指令里**，期望值恒为 0。
把它们并进同一个 `exp(−·/std²)`，是让它们和跟踪项**共享同一条饱和曲线**——
一旦机器人开始颠簸或摇晃，**整个跟踪奖励会一起塌下去**，策略必须同时管好
"走得准"和"走得稳"。

如果拆成独立项，策略可以**套利**：跟踪那项拿满分，颠簸那项认罚，总分可能还更高。
（这和实践 2 里"站着不动白拿 `feet_clearance` 满分"是同一类结构性漏洞。）

**为什么角速度只跟踪 yaw，惩罚 roll/pitch？** 机器人转向是绕自身竖直轴（yaw）的旋转，
这是唯一由指令控制的旋转自由度。roll/pitch 上的角速度全是不想要的扰动——身体在晃。
注意这里惩罚的是角**速度**不是角度：姿态角本身由 `upright` 奖励管，
这里管的是"晃动的剧烈程度"。一个管位置、一个管导数，互补。

### 奖励的四维组织（作业要求按此分析）

作业明确要求把奖励按 **Task / Style / Reg / Penalty** 四维组织。真实权重取自
`velocity_env_cfg.py`：

| 维度 | 奖励项 | weight | 作用 |
|---|---|---|---|
| **Task** | `track_linear_velocity` | +2.0 | 跟上 v_x/v_y 指令 |
| | `track_angular_velocity` | +2.0 | 跟上 yaw 指令 |
| | `track_base_height`（TODO 6） | +1.0 | 跟上骨盆高度——本作业新增的第二条指令 |
| **Style** | `upright` | +1.0 | 躯干直立 |
| | `pose` | +1.0 | 靠近默认姿态，抑制怪异构型 |
| | `foot_clearance` | −2.0 | 摆动腿抬脚高度不够就重罚 |
| | `foot_swing_height` | −0.25 | 摆动轨迹形状 |
| **Reg** | `action_rate_l2` | −0.1 | 动作平滑，抑制抖动 |
| | `soft_landing` | −1e-5 | 落地冲击 |
| **Penalty** | `dof_pos_limits` | −1.0 | 关节越界 |
| | `foot_slip` | −0.1 | 支撑脚打滑 |

**为什么 `foot_clearance` 用 −2.0 这么大的负权重？** 它是唯一能阻止"拖着脚滑行"的项。
蹲姿压低了骨盆，摆动腿的离地裕度本来就被压缩，惩罚不够重策略就会退化成蹭地走。
配合 `foot_slip`（−0.1）形成两道防线：前者管抬脚、后者管支撑脚打滑。

（`body_ang_vel`、`angular_momentum`、`air_time` 的 weight 是 0.0，注释写明
"Override per-robot"——框架保留接口但 G1 未启用。注意**零权重项不会被 RewardManager
跳过**，它仍参与日志统计，所以看到它出现在指标里不等于它在影响训练。）

### 课程学习（Curriculum）与它的单位陷阱

**直觉。** 别一上来就让还站不稳的策略跑到 3 m/s——绝大多数 episode 会在起步瞬间摔倒，
采样全是失败样本，学不到有用梯度。**先在窄范围里学会稳走，再逐步加码。**

```python
"velocity_stages": [
    {"step": 0,          "lin_vel_x": (-1.0, 1.0), "ang_vel_z": (-0.5, 0.5)},
    {"step": 5000 * 24,  "lin_vel_x": (-1.5, 2.0), "ang_vel_z": (-0.7, 0.7)},
    {"step": 10000 * 24, "lin_vel_x": (-2.0, 3.0)},   # ang_vel_z 沿用上一阶段
]
```

**陷阱：`step` 的单位是"环境步"不是"训练迭代数"。** `24` 是 `num_steps_per_env`
（每次 PPO 迭代、每个环境 rollout 的步数）。所以 `5000 * 24` 表示第 **5000** 次迭代
才切到 Stage 1。**若误写成 `5000`，课程会在第 `5000/24 ≈ 208` 次迭代就跳档**——
助教点名的高频错误。

### 如果去掉某一段会怎样

- **去掉 Actor 观测（消融 B）** → 策略看不到目标高度，只能收敛到一个固定折中高度
  （详见第 5 节，误差劣化 5 倍）。
- **去掉高度奖励（消融 A）** → 策略没动机跟踪高度，骨盆停在让速度奖励最大化的姿态
  （误差劣化 5.6 倍）。
- **课程写错单位** → 第 208 迭代就被要求跑 2 m/s，起步即摔，训练崩溃。
- **`foot_contact` 误给 Actor** → 真机部署时 Actor 依赖一个可能拿不到的传感器，
  sim2real 失败。

### TODO 6/7/8 — 三个跟踪奖励（`mdp/rewards.py`）

核心一行各自是（完整误差构成见第 3 节）：

```python
# TODO 6 高度：世界系
actual_height = asset.data.root_link_pos_w[:, 2]
return torch.exp(-torch.square(command[:, 0] - actual_height) / std**2)

# TODO 7 线速度：机体系
actual = asset.data.root_link_lin_vel_b
lin_vel_error = torch.sum(torch.square(command[:, :2] - actual[:, :2]), dim=1) \
              + torch.square(actual[:, 2])
return torch.exp(-lin_vel_error / std**2)
```

**张量形状。** `command` 是 `(num_envs, 4)`，`actual` 是 `(num_envs, 3)`。
`torch.sum(..., dim=1)` 把每个环境的误差**求和成标量**，得到 `(num_envs,)`——
每个并行环境一个奖励数。形状对不上（比如忘了 `dim=1`）会广播成错误维度，
最典型的人形控制 bug。

## 5. 我踩过的坑

### 坑一：怎么设计一个能"证明因果"而不只是"效果更好"的实验（本篇最核心）

**现象。** 作业要求 ≥2 组消融实验证明"高度指令闭环有用"。最省事的做法是：
跑一个"有高度功能"的完整版，再跑一个"啥都没有"的裸版，比总回报——完整版高，收工。

**第一反应。** 这不就行了吗？完整版回报高，说明我加的东西有用。

**为什么这么想是错的。** 这个对比**什么都没证明**。裸版和完整版差了太多东西
（指令、观测、奖励全都不一样），你根本不知道是**哪一部分**带来的提升，
甚至无法排除"只是训练随机性"。这是典型的**多变量混淆**——改了一堆东西，
无法归因。而且比"总回报"最误导：总回报里速度、姿态、高度全揉在一起，
高度这一路的好坏被淹没了。

**怎么找到真因（正确的实验设计）。** 我把它建成一条**单因素对照**：
以第 1 节那条三段闭环为骨架，设三组，**每组只切断其中一段，其余全同**
（同一份 `rl_cfg`、`seed=42`、`num_envs=4096`、`max_iterations=3000`）：

| 组别 | ①采样指令 | ②Actor 观测 | ③高度奖励 | 改了什么 |
|---|---|---|---|---|
| **baseline** | ✅ | ✅（Actor 8 项） | w=1.0 | 完整闭环 |
| **消融 A** no_height_rew | ✅ | ✅ | **w=0** | 只切断第③段 |
| **消融 B** blind_actor | ✅ | **✗**（Actor 7 项） | w=1.0 | 只切断第②段 |

关键做法有三个：
1. **主判据用分项指标 `error_height`，不用总回报。** 总回报会掩盖高度这一路的变化。
2. **消融 A 用 `weight=0` 而非删除该项。** `RewardManager` 不跳过零权重项，
   TensorBoard 里仍记录 `track_base_height`（恒为 0），三组曲线能直接叠图对照。
3. **消融 B 只从 Actor 移除 `height_command`，Critic 保留。** 我要测的是
   "Actor 知不知道目标"，不是"系统里有没有这个信息"。Critic 保留能让价值估计质量
   与 baseline 一致，把变量隔离在**策略网络这一侧**——否则 Critic 也变瞎，
   优势函数的方差变化会污染对照。

**为什么三段都要单独验，不能只验最终效果？** 因为"最终效果好"不能反推"每一段都必要"。
只有**逐段切断、逐段看到劣化**，才能证明这条闭环**缺一不可**。这正是从
"相关"走向"因果"的关键——不是"加了这套东西效果好"，而是"抽掉任意一根柱子房子就塌"。

**根因（我一开始的认知错误）。** 我最初把消融理解成"证明我的方案好"，
所以本能地想跟"最差的裸版"比。但消融的真正目的是**归因**——证明**每个组件各自的必要性**，
所以必须单因素、必须看分项指标。

**教训（可迁移）。** 设计对照实验时问自己两句：
① "如果结果变差，我能唯一地归因到某一个改动吗？"（→ 强制单因素）
② "我看的指标，会不会把我关心的效应平均掉？"（→ 用分项指标，别用总分）。

### 坑二：`target_height_mean` 指标是真值的 2.49 倍——一个自带校准物的 bug

**现象。** 日志里 `Metrics/base_height/target_height_mean` 实测约 **1.554**。
但高度指令是在 `[0.45, 0.80]` 上均匀采样的，它的真值**必然是中点 0.625**。1.554 离谱。

**第一反应。** 以为高度指令采样写错了，采出了远超区间的值。

**为什么这么想是错的。** 采样没错。我打印过瞬时 `height_command`，都在 `[0.45, 0.80]` 内。
问题在**指标的累加方式**。

**怎么找到真因。** 我盯住 `_update_metrics` 里的除数：

```python
max_command_step = resampling_time_range[1] / step_dt   # 8.0 / 0.02 = 400
metrics["error_height"] += torch.abs(...) / max_command_step
```

metrics 实际累积了**整个 episode**（约 997.7 步）而不是单条指令的生命周期，
于是所有量被同一个因子放大：`997.7 / 400 = 2.494`。
实测比值 `1.554 / 0.625 = 2.486`——**吻合到小数点后两位**，确认了这个解释。

**根因。** 累加除以的是"单条指令最大步数（400）"，但 metrics 在整个 episode
（997 步）里持续累加，中途指令重采样了好几次却没清零，导致系统性膨胀 2.49 倍。

**教训（这个坑给了我一个意外的礼物）。** `target_height_mean` 的真值可以由指令分布
**解析地算出来**（均匀分布的期望 = 中点 0.625）。所以它**自带一个校准物**：
用实测/真值反推出膨胀因子 2.49，就能校正 `error_height`。
**设计日志指标时，顺手记一个"已知真值的量"，事后就能自查整条数值管道对不对。**
而且三组 episode 长度几乎相同（997.5~997.9），膨胀因子一致，**组间相对比较不受影响**——
所以消融结论依然成立，只是绝对值要除以 2.49 才是真实误差。

### 坑三：blind_actor 落在一个可证伪的理论区间内

**现象。** 消融 B（Actor 看不到指令）的 `error_height` 校准后约 **0.12 m**。

**第一反应（弱版本）。** "比 baseline 差，说明观测有用"——就这么写结论。

**为什么这不够。** "差一点"是**不可证伪**的——差多少都能事后编个理由。
好的实验应该**事先给出可被推翻的定量预测**。

**怎么做（把结论变得可证伪）。** Actor 看不到目标高度时，它只能输出一个**固定高度**
`h*`。对 `h_cmd ~ U(0.45, 0.80)`，固定值的期望绝对误差为：

```
E|h_cmd − h*| = [(h*−0.45)² + (0.80−h*)²] / (2 × 0.35)
```

- 取区间中点 `h* = 0.625` 时**最小**：**0.0875 m**
- 取区间端点时**最大**：0.1750 m

所以理论预测：`error_height` 应落在 **[0.0875, 0.175] m** 且**不随指令变化**。
校准后实测 **0.12 m**，正落在区间内。反推 `h* ≈ 0.731 m`。

**根因/洞察。** `h* = 0.731` 比最优折中值 0.625 **更高**，恰恰说明策略在做**权衡**：
速度跟踪等其它奖励把姿态往自然站高（约 0.78 m）拉，高度奖励把它往 0.625 拉，
最终停在两者之间。而 baseline 校准后只有 **0.024 m**，只有理论最优折中值 0.0875 的
**27%**——证明它确实在**按指令逐条调整**，而不是输出一个固定值。

**教训。** 消融实验最有说服力的形态，是**事先写下一个能被推翻的数值预测**，
再看实测落不落进去。"效果更差"是观察，"落在 [0.0875, 0.175] 内"是证明。

### 坑四：`--agent.logger` 默认是 wandb，三组日志差点没落地

**现象。** 第一次跑消融，本地 `logs/` 里没生成 TensorBoard 事件文件。

**第一反应。** 以为训练没跑起来。

**为什么这么想是错的。** 训练跑了——终端在正常刷 reward。只是日志被送去了 **wandb**（云端），本地没存。

**怎么找到真因。** 我翻终端启动日志，看到一行 "logging to wandb"，再去查 runner 的
参数默认值，发现 `--agent.logger` 默认就是 `wandb` 而不是 `tensorboard`。

**根因。** RSL-RL runner 的 `--agent.logger` 默认值是 `wandb`。

**教训。** 跑对照实验前先确认日志后端。我在 `run_p4_ablation.sh` 里显式改成
`tensorboard`，保证三组数据都落在本地、能离线叠图。

## 6. 面试可能怎么问

### 概念题

**Q1：什么是"指令型 MDP"？和普通 MDP 的区别？**
普通 MDP 目标固定；指令型 MDP 把目标本身塞进状态，每个 episode 随机给一个指令，
策略要学"看指令办事"。本作业指令是 4 维 `[v_x, v_y, ω_z, h_cmd]`，
高度 `h_cmd ~ U(0.45,0.80)` 均匀采样。

**Q2：为什么高度用世界系、速度用机体系？**
"离地多高"是绝对概念（转身不改变），用世界系 `root_link_pos_w[:,2]`；
"往前走多快"的"前"是相对机器人朝向的，用机体系 `root_link_lin_vel_b`。
用错会让机器人转身后误差算错，学不会朝自己前方走。注意高度用世界系只在平地成立。

**Q3：weight 和 std 有什么区别？为什么高度 std 比速度小？**
weight 是重要性（决定奖励上限），std 是"多大误差算差"（决定曲线陡度）。
高度量程只有 0.35 m，比速度窄，所以 std 要更严（0.1 vs 0.5），否则整个区间内
奖励几乎恒定、没有梯度。

### 实现题

**Q4：加一条高度指令，只写高度奖励够吗？还要改哪里？**
不够。要打通三段闭环：TODO 1/3 采样并注册指令、TODO 4 把指令加进 Actor（和 Critic）
观测、TODO 5/6 注册并实现高度奖励。漏掉观测端是最常见错误——策略看不到目标，只能瞎猜。

**Q5：`foot_contact` 为什么只给 Critic 不给 Actor？指令为什么两个都给？**
`foot_contact` 是特权信息：Critic 训练完丢弃，可以用真机拿不到的信息把价值估计做准；
Actor 要部署真机，不能依赖足底传感器。而 `height_command` 是**任务输入**不是特权信息，
Actor 必须看到才知道蹲多低，所以两个都给。

**Q6：课程学习里 `5000 * 24` 的 24 是什么？写成 5000 会怎样？**
24 是 `num_steps_per_env`，每次 PPO 迭代每个环境 rollout 的步数。`step` 单位是环境步，
所以 `5000*24` 表示第 5000 次迭代切档。写成 5000 会让课程在第 208 迭代就跳档，
策略还站不稳就被要求跑高速，起步即摔。

### 深挖题

**Q7：你怎么设计消融证明"这套高度机制真的有用"，而不只是"看起来有用"？**
单因素对照 + 分项指标。以三段闭环为骨架设三组，每组只切断一段（消融 A 高度奖励 w=0、
消融 B Actor 观测去掉 height_command），其余全同（同 seed/num_envs/iters）。
主判据用 `error_height` 不用总回报（总回报会淹没高度这一路）。结果：切断任一段，
高度误差都劣化 **5 倍以上**（baseline 0.0597 → blind_actor 0.2982 → no_height_rew 0.3352，
原始值），而速度误差三组几乎不变（约 0.55），证明改动被正确隔离、闭环缺一不可。

**Q8：消融 B 你为什么只从 Actor 移除指令，Critic 保留？**
我测的是"Actor 知不知道目标"，不是"系统有没有这个信息"。Critic 保留能让价值估计
质量与 baseline 一致，把变量锁在策略网络一侧；否则 Critic 也变瞎，优势函数方差变化
会污染对照。这是刻意制造的病态配置，用来反证观测接线的必要性。

**Q9：blind_actor 组你事先做了什么预测？实测符合吗？**
预测它会收敛到一个固定高度，误差落在 [0.0875, 0.175] m 且不随指令变化
（0.0875 是取区间中点的理论最小值）。校准后实测 0.12 m，落在区间内，反推固定高度
≈0.731 m——比 0.625 高，说明策略在"高度奖励拉低"和"其它奖励拉向自然站高"之间折中。
而 baseline 只有 0.024 m，是理论最优折中的 27%，证明它在按指令逐条调整。

**Q10：训练收敛到什么程度？怎么判断三组对照是公平的？**
baseline 总回报从 ≈−1 爬到 **≈70**（3000 迭代，控制台记录 −1.1→25.4→51.2→65.0→67.7→70.2
分别在迭代 0/600/1200/1800/2400/3000）。判公平看两点：三组速度误差几乎相同
（约 0.55，差异 <3.6%）说明主任务没被污染；三组 episode 长度几乎相同（997.5~997.9）
说明指标膨胀因子一致，组间相对比较不受影响。三组都已进入平台期，没有一组还在单调改善。

## 7. 延伸：这个技术在工业界怎么用

**双指令 / 多指令 MDP 是人形控制的通用范式。** 真实产品里，一个行走策略往往要同时
响应多条指令：速度、朝向、步态频率、身高、甚至上半身姿态。本作业的"速度 + 高度"
是最小的双指令样例。掌握"指令必须同时接入采样、观测、奖励三处"这条原则，
就能推广到任意多指令任务——加一条新指令，就照着这条闭环接三处。

**蹲姿行走本身有实际价值。** 人形机器人钻低矮空间（桌下、车厢、管廊）、
搬运时降低重心、在人群里"蹲下来"降低压迫感，都需要"边走边控高度"。
把高度做成连续可调的指令，比训练一堆离散姿态策略实用得多。

**非对称 Actor-Critic（特权学习）是 sim2real 的主力工具。** 仿真里有大量真机拿不到的
"上帝视角"信息（精确接触、地面摩擦、外力）。把它们只喂给 Critic 加速训练、
Actor 只用真机可得的本体感知，是 Isaac Lab / mjlab 这类框架的标准玩法。
本作业的 `foot_contact` 是这个范式最小的一个例子。

**关于 mjlab（本作业的训练框架）。**
- **MuJoCo Warp（mjwarp）** = MuJoCo 物理引擎的 **GPU 并行版**。普通 MuJoCo 是 CPU
  单实例（一次算一个机器人），mjwarp 用 NVIDIA 的 Warp（把 Python 编译成 CUDA kernel）
  把求解器搬到 GPU，一次 `step` 推进几千个环境，供 RL 采样。
- **它不是 MJX。** MJX 是 MuJoCo 的 JAX 后端（走 XLA 编译）；mjwarp 走 Warp/CUDA，
  两条完全不同的技术路线。本机没装 jax，实践 4 照跑不误。
- **mjlab** = 建在 mjwarp 之上的 RL 环境框架，Manager 架构几乎照搬 Isaac Lab
  （Command/Observation/Reward/Curriculum Manager 一一对应）。好处是从 Isaac Lab
  迁过来**心智模型不用换**，而且启动是**秒级**（Isaac Sim 要 3~5 分钟）。
  本作业配的是 RSL-RL（PPO）+ Viser（浏览器里可视化调滑块）+ uv（包管理）这套工具链。
