## 0. 一句话概括

有一个"作弊的老师"（Teacher）——它训练时能看到未来 20 帧参考动作，跟得又稳又准，
但正因为它靠"偷看未来"，真机上没有未来信息可看，它没法直接部署。
我们要训练一个"只能看到当下"的学生（Student），让它在信息更少的条件下，
学到老师的控制本领。**这个"用一个网络去教另一个网络"的过程，就叫蒸馏（distillation）。**

这个实践的核心不是训练老师，而是回答一个问题：
**把老师的知识传给学生，应该"对齐动作"还是"对齐整个动作分布"？哪个更好，好多少？**

---

## 1. 问题从哪来（Why）

### 1.1 一个绕不开的矛盾：训练时能作弊，部署时不能

先看两种观测（observation，策略网络的输入）：

| | Teacher 看到的 | Student 看到的 |
|---|---|---|
| 当前参考帧 | ✅ | ✅ |
| **未来 20 帧参考动作** | ✅（特权） | ❌ |
| 本体感受（关节角、角速度…） | ✅ | ✅ |
| 历史信息 | ✅ | ✅ |

Teacher 的观测是 **3007 维**，其中 command 部分 **1344 维 = 21 个参考步 × 64 维**
（`t+0` 当前帧 + 20 个未来帧），这段"未来"就是它的作弊来源
（`ASSIGNMENT.md` §4.2）。能提前看到未来 20 帧，意味着它在转弯、起步、停步之前
就知道该怎么调重心——跟踪自然稳。

问题是：**真机部署时，机器人不知道你下一秒想让它做什么。** 未来参考帧这种
"特权信息（privileged information）"在部署时不存在。所以 Teacher 这个网络本身
**不能上真机**——它是一个"知道答案的陪练"，不是最终产品。

我们真正要的，是一个**只吃当前帧 + 本体 + 历史**就能跑的 Student。

### 1.2 为什么不直接从零训练 Student，非要蒸馏？

这是面试最爱问的"为什么不用更简单的办法"。三个理由：

**① 受限观测下，探索太难。** Student 看不到未来，它得靠试错自己摸索出
"看到当前这一帧、该怎么提前准备下一步"。从零 PPO 训练要撞很多次墙才找到方向。
而 Teacher 已经知道正确动作长什么样——**有一个"标准答案"在旁边指着，
比自己瞎试快得多。** 这就是蒸馏的价值：把难探索的问题，变成有监督信号引导的问题。

**② 直接部署 Teacher 不行**（上一节说了，它依赖未来信息）。

**③ 那为什么不干脆让 Student 也看未来？** 因为那样训出来的东西真机上没法用——
真机拿不到未来帧，观测对不上，策略直接失效。**观测空间必须匹配部署条件**，
这是硬约束。蒸馏正是"训练用特权、部署用受限"这套范式的标准解法。

> 一句话：**Teacher 负责"知道答案"，Student 负责"能上真机"，蒸馏负责"把答案搬过去"。**

## 2. 核心概念（零基础可懂）

### 2.1 高斯策略（Gaussian policy）

**生活化类比**：你让一个人"往前走一步"，他不会每次都迈得一模一样——
有时步子大点有时小点，围绕一个"平均步长"上下浮动。策略也一样：它不是输出一个
写死的动作，而是输出一个**动作的概率分布**，实际动作从这个分布里随机采样。

**严格定义**：连续控制里，策略对每个动作维度输出一个正态分布 N(μ, σ)。
μ（mean，均值）是"最想做的动作"，σ（standard deviation，标准差）是"我有多不确定"。
真正执行的动作 a ~ N(μ, σ)。训练时靠这个随机性做**探索**；越训到后期 σ 越小，
动作越确定。

**数学形式**：这里用的是**对角高斯（diagonal Gaussian）**——各个动作维度相互独立，
协方差矩阵是对角阵。所以一个 D 维动作的分布，就是 D 个独立的一维正态，
用两个 D 维向量 μ 和 σ 完整描述。

**在本实践中的体现**：Teacher 和 Student 都是高斯策略。蒸馏时，Teacher 给出
一对 (μ_teacher, σ_teacher)，Student 给出 (μ_student, σ_student)。
"对齐动作"就是对齐 μ；"对齐分布"就是同时对齐 μ 和 σ。

### 2.2 蒸馏（distillation）

**生活化类比**：老师做了一遍题，把解题步骤（甚至"这一步我也拿不准"的犹豫）
展示给学生，学生照着模仿。学生不用重新发明解法，跟着老师的示范学就行。

**严格定义**：蒸馏 = 用一个已训练好的模型（Teacher）的输出，作为监督信号，
去训练另一个模型（Student）。经典蒸馏来自 Hinton 2015（分类任务里用 Teacher 的
"软标签"教 Student）；在 RL 里，Teacher 的"软标签"就是它在每个状态下的动作分布。

**在本实践中的体现**：总损失里加一项蒸馏损失

```
L = L_PPO + λ(step) · L_distill
```

- `L_PPO`：Student 自己和环境交互得到的强化学习损失（让它真的能完成任务）
- `L_distill`：Student 的输出和 Teacher 的输出之间的差距（让它模仿老师）
- `λ(step)`：蒸馏系数，随训练步数**退火**（见 2.6），控制"听老师"和"自己练"的比重

### 2.3 KL 散度（KL divergence）——本实践必须讲透的东西

这是整个实践的数学核心，也是面试深挖点。慢慢讲。

**生活化类比**：你以为一枚骰子是均匀的（你的信念分布 Q：每面 1/6），
但它其实灌了铅、偏向 6（真实分布 P）。你用"均匀"这个错误信念去打赌，
长期会亏钱。**KL 散度衡量的就是：用错误的分布 Q 去近似真实分布 P，你平均要多付出多少代价。**
P 和 Q 越像，KL 越小；完全一样时 KL = 0。

**严格定义**：

```
KL(P ‖ Q) = Σ_x P(x) · log( P(x) / Q(x) ) = E_{x~P}[ log P(x) − log Q(x) ]
```

它衡量"用 Q 编码来自 P 的样本，比用 P 自己编码，平均多浪费多少信息（bit/nat）"。
性质：**KL ≥ 0**，当且仅当 P = Q 时取 0。

**为什么它不对称**——这是重点。看清楚求和里的**权重是 P(x)**：

- 只在 **P 概率高**的地方才认真计较 P 和 Q 的差异；
- 在 **P 概率≈0** 的地方，即使 Q 差得离谱，前面乘一个 P(x)≈0，也罚不到。

所以 `KL(P‖Q)` 关心的是"P 高的地方 Q 有没有跟上"，
`KL(Q‖P)` 关心的是"Q 高的地方 P 有没有跟上"——**两者关注的方向完全相反，
数值自然不等。** 这不是 bug，是 KL 的定义性质。

**一个你可以手算验证的小例子**：设 teacher = N(0, 1)（窄），student = N(0, 2)（宽）。
用对角高斯 KL 闭式解 `KL(N(μ₁,σ₁)‖N(μ₂,σ₂)) = log(σ₂/σ₁) + (σ₁²+(μ₁−μ₂)²)/(2σ₂²) − 1/2`：

```
forward  KL(teacher‖student) = ln(2/1) + (1+0)/(2·4) − 0.5 = 0.693 + 0.125 − 0.5 = 0.318
reverse  KL(student‖teacher) = ln(1/2) + (4+0)/(2·1) − 0.5 = −0.693 + 2   − 0.5 = 0.807
```

**0.318 ≠ 0.807**，亲手算一遍就体会到不对称了。
（我们代码里 teacher/student 是别的数值，实测 forward=0.6363、reverse=1.6137，
`tests/test_distillation_reference.py` 就用这两个值断言非对称性。）

**forward KL vs reverse KL：mode-covering vs mode-seeking**

这是面试深挖点里的深挖点。想象 **Teacher 是双峰分布**——比如在某个状态下，
"先迈左脚"和"先迈右脚"都是合法走法，Teacher 学到了两个峰。
而 Student 是**单峰**高斯（只能有一个 μ 一个 σ），它没法同时精确复现两个峰，
只能妥协。两种 KL 会逼它做出**完全不同的妥协**：

| 目标 | 别名 | Student 的妥协方式 |
|---|---|---|
| `KL(teacher‖student)`（forward） | **mode-covering / mass-covering**（覆盖式） | Student 把峰放在两峰**中间**、方差撑大，去**覆盖**两个峰。宁可在中间低概率区放点概率，也不能漏掉任何一个峰——因为 teacher 高、student 低的地方会被巨额惩罚。 |
| `KL(student‖teacher)`（reverse） | **mode-seeking**（找峰式） | Student **挑一个峰**精确贴上去，另一个峰直接丢掉。因为 student 高、teacher 低的地方要挨罚，它不敢把概率放到两峰中间的"山谷"里，于是缩进某一个峰。 |

蒸馏要的是 **forward**：我们希望 Student **继承 Teacher 的完整行为分布**，
知道"这里其实有两种走法"，而不是只学会其中一种、把另一种彻底忘掉。
forward KL 的覆盖性正好保证了这一点。

> 补充诚实说明：我们代码里 Teacher 和 Student 都是**单峰**对角高斯，
> 没有真的双峰。单峰情形下，forward KL 的作用体现为**矩匹配**——
> 它会把 student 的 μ 拉到 teacher 的 μ，把 σ 拉向 teacher 的 σ（既不许过窄也不许过宽），
> 相当于"连老师有多不确定都一起学过来"。多峰的 mode-covering 直觉是理解
> "为什么是这个方向"的最好方式，但落到本实现，它的实际效果是"完整地匹配一个高斯"。

### 2.4 Action Matching vs KL Matching

有了上面的铺垫，两种蒸馏目标的区别就一句话能说清：

| | 对齐对象 | 损失 | 传递了什么 |
|---|---|---|---|
| **Action Matching** | 只对齐**均值 μ** | MSE 或 Huber | Teacher 在每个状态"**做什么**" |
| **KL Matching** | 对齐**整个高斯 (μ, σ)** | forward KL | 额外传递 Teacher 的"**不确定性结构**"——在哪些状态它也拿不准、该留多大探索 |

**KL 多传的那部分（σ）为什么有用**：Student 观测受限，它需要知道
"老师在哪些情况下其实也没把握"，从而在那些情况下保留探索、别过度自信照抄均值。
这个信息对 Student 后续用 PPO 继续自我改进很有价值。

### 2.5 特权观测 / 受限观测（privileged vs restricted observation）

**生活化类比**：开卷考试（能看资料 = 特权）训练出的直觉，要迁移到闭卷考试
（只能靠记忆 = 受限）。你不能把开卷时的做法照搬，得练出"没资料时怎么办"。

**在本实践中的体现**：Teacher 用带未来帧的特权观测，Student 用只含当前帧的受限观测。
**关键工程点**：两者吃的是**同一个** `batch.observations`，各自在网络内部取自己需要的切片
（代码里 `teacher_forward` 和 student 的 `forward` 内部分别取），
**绝不能在外面手动把观测切开分别喂**——这是助教点名的高频错误（下面坑 5 展开）。

### 2.6 线性退火（linear annealing）

**生活化类比**：学骑车，一开始有人扶（λ 大，强依赖老师），慢慢松手（λ 变小），
最后自己骑（λ→0，靠自己）。松手太快会摔（指导不足），一直扶着永远学不会
自己平衡（过度约束）。

**严格定义**：让蒸馏系数 λ 从 `start` 随训练进度**线性**降到 `end`。

```
progress = clip(step / duration, 0, 1)
λ = start + (end − start) · progress          # = (1−progress)·start + progress·end
```

**为什么必须退火而不是固定**：因为**信息不对称**。Teacher 看得到未来，Student 看不到，
Student **永远无法完全复制** Teacher 的动作。训练后期如果还硬压着 Student 去匹配 Teacher，
反而**阻止它学出"只有当前帧时该怎么补偿"的策略**。所以后期要把权重让给 PPO 回报，
让 Student 适应自己的受限观测。（`distillation_utils.py` L20-25 的注释就是这个道理。）

## 3. 算法原理

### 3.1 整体流程

```
每次参数更新：
  1) Student 前向：吃 batch.observations → 得到 (μ_s, σ_s)、采样动作、log_prob
  2) 算 PPO 的 surrogate loss（Student 自己和环境的强化学习损失）
  3) 若 λ>0，算蒸馏损失：
       Action Matching → teacher 前向拿 a_teacher，L = MSE(a_student, a_teacher)
       KL Matching     → teacher 前向拿 (μ_t,σ_t)，L = KL(teacher ‖ student)
  4) 总损失 loss = surrogate + c_v·value + (−c_e·entropy) + λ·L_distill
  5) 反传、裁剪梯度、optimizer.step()
  6) λ 按更新次数退火一格
```

这套逻辑在 `distillation_ppo.py` 的 `update()` 里（L35-160），
两种蒸馏只是覆写 `_compute_distillation_output`。

### 3.2 对角高斯 forward KL 的公式，逐项拆解

Student 要最小化的蒸馏损失（`distillation_utils.py` L115-120）：

```
KL = log(σ_s/σ_t) + (σ_t² + (μ_t − μ_s)²) / (2σ_s²) − 1/2     # 逐维
     然后 .sum(dim=-1)（各维独立，求和）.mean()（batch 平均）
```

符号：`μ_t,σ_t` = teacher 的均值/标准差，`μ_s,σ_s` = student 的。逐项看，
**并说清"去掉这一项会怎样"**（这是写作标准强调的）：

| 项 | 作用 | 去掉会怎样 |
|---|---|---|
| `log(σ_s/σ_t)` | 宽度匹配（惩罚 σ_s 偏离 σ_t） | σ_s 可以随便放大不挨罚 → Student 探索噪声爆炸、动作发飘 |
| `(μ_t−μ_s)²/(2σ_s²)` | **均值匹配**（核心项） | Student 均值可任意偏离 Teacher → 动作根本学不对 |
| `σ_t²/(2σ_s²)` | 把 Teacher 的宽度信息灌进来 | 丢掉"Teacher 有多确定" → 退化得接近只匹配均值 |
| `−1/2` | 归一化常数，保证 P=Q 时 KL=0 | 对梯度无影响（对参数导数为 0），但数值不再"0=完全一致"，失去可读性 |

分母里的 `2σ_s²` 很关键：它让**均值误差按 Student 自己的不确定性缩放**——
Student 越自信（σ_s 越小），同样的均值偏差 (μ_t−μ_s)² 惩罚越重。这正是我们想要的：
"你说你很确定，那就必须更准。"

### 3.3 ★ 蒸馏的 KL ≠ PPO 的 desired_kl（面试高频坑）

同一份代码里出现了**两个 KL**，名字都带 KL，但**是完全不同的东西**，
初学者极易混。看 `distillation_ppo.py`：

| | 蒸馏 KL | PPO 的 `desired_kl` |
|---|---|---|
| 比较谁和谁 | **Student ↔ Teacher** 的分布 | **新策略 ↔ 旧策略**（同一个 Student 更新前后） |
| 代码位置 | L121-134，作为 loss 项 `+ distill_coef * distill_loss` | L79-102，`kl_mean` 只用来调学习率 |
| 用途 | **参与反向传播**，是训练信号 | **不反传**（在 `torch.inference_mode()` 里），只做自适应 LR |
| 方向 | forward KL(teacher‖student) | 新旧策略间的 KL，用于判断这步走大了还是走小了 |

具体看代码就一清二楚：L79-94，PPO 拿 `old_distribution_params`（采样时的旧策略）
和当前 `distribution_params` 算 `kl_mean`，`kl_mean > desired_kl*2` 就把学习率除以 1.5，
`< desired_kl/2` 就乘 1.5——**它在调学习率，压根不碰 Teacher。**
而 L121 的蒸馏 loss 才涉及 Teacher。

**一句话记忆**：`desired_kl` 是 PPO 给自己踩刹车（别让策略一步更新迈太大），
蒸馏 KL 是让 Student 追 Teacher。**一个是"和过去的自己比"，一个是"和老师比"。**

## 4. 代码走读

挑 4 段最能体现"为什么这么写"的核心代码。

### 4.1 TODO 1 · 线性退火与除零保护

`distillation_utils.py` L28-31：

```python
if duration <= 0:
    return end
progress = min(max(step / duration, 0.0), 1.0)
return start + (end - start) * progress
```

- `duration <= 0` 直接返回 `end`：`duration` 是分母，为 0 会**除零**（`step/0`）。
  返回终值也顺带给了"关闭退火"一个明确入口——想固定用终值，把 duration 设 0 即可。
- `min(max(..., 0), 1)`：把 progress 夹在 [0,1]。`step` 可能超过 `duration`
  （训练比预定的退火期更长），不夹的话 progress>1，λ 会被外推到 `end` 之外，
  甚至反向。
- 验证：`linear_anneal(1.0, 0.1, 5, 10)`：progress=5/10=0.5，
  结果 = 1.0 + (0.1−1.0)·0.5 = **0.55**，与 `tests/test_distillation_reference.py` L20 断言一致。

### 4.2 TODO 4 · 对角高斯 KL 与 `clamp_min` 数值保护

`distillation_utils.py` L113-120：

```python
t_d = teacher_std.clamp_min(std_eps)   # std_eps = 1e-6
s_d = student_std.clamp_min(std_eps)
kl = (
    torch.log(s_d / t_d)
    + (t_d.pow(2) + (teacher_mean - student_mean).pow(2)) / (2.0 * s_d.pow(2))
    - 0.5
)
return kl.sum(dim=-1).mean()
```

**张量形状**：`teacher_mean/std` 等都是 `(batch, action_dim)`。
逐元素运算后 `kl` 仍是 `(batch, action_dim)`；`.sum(dim=-1)` 把 action_dim 求和
（对角协方差 → 各维独立 → 联合 KL = 各维 KL 之和）得 `(batch,)`；`.mean()` 再对 batch
平均得标量。**顺序不能反**：先 sum 再 mean 是对的；如果直接 `.mean()` 整个张量，
等于把 action 维也平均了，KL 会小 action_dim 倍。

**`clamp_min(1e-6)` 为什么必须有**：`std` 若为 0，`log(σ_s/σ_t)` 里 `log(0) = −inf`，
`1/(2σ_s²)` 里除零得 `nan`。**一旦 nan 进入梯度，整个网络的参数会在一次 `optimizer.step()`
里全变成 nan**，而 loss 打印可能还在跑（nan 不报错）。这类"静默失败"最难查——
下面坑 4 展开。

### 4.3 TODO 6 · Action Matching 集成：Teacher 必须 `no_grad`

`action_matching.py` L64-70：

```python
with torch.no_grad():
    teacher_actions = self.actor.teacher_forward(batch.observations)
student_actions = self.actor(batch.observations)
loss = action_regression_loss(student_actions, teacher_actions, self.bc_loss_type)
```

**为什么包 `no_grad`，明明 Teacher 参数已经 `requires_grad=False` 了？**
（`student_teacher.py` L92-93 确实把 teacher 所有参数冻结了。）两个原因：

1. `requires_grad=False` 只是让 Teacher 的**参数**不更新，但前向仍会为它的
   **中间激活**构建计算图并保留——白白占显存。`no_grad` 连图都不建。
2. 在共享模块的写法下，不加 `no_grad` 梯度可能被错误引流回去。

**Teacher 在这里的身份是"数据源"，不是"网络"。** 它只负责吐出监督目标 `teacher_actions`，
这个张量应当是**常量**，`action_regression_loss` 里的 MSE 只对 `student_actions` 反传。

### 4.4 TODO 7 · KL Matching 的顺序陷阱：只读状态，别重新前向

`kl_matching.py` L67-71：

```python
with torch.no_grad():
    teacher_mean, teacher_std = self.actor.teacher_distribution_params(batch.observations)
student_mean, student_std = self.actor.output_distribution_params   # ← 只读，不重新前向
loss = diagonal_gaussian_kl(teacher_mean, teacher_std, student_mean, student_std)
```

`output_distribution_params` 是 actor **上一次前向留下的状态**——由 `distillation_ppo.py`
主循环 L66-71 的 `self.actor(batch.observations, ...)` 刚刚写入，L76 又把它读进
`distribution_params` 供 PPO 用。

**陷阱**：如果你在这里写成 `student_mean, student_std = self.actor(batch.observations)`
（再前向一次），会**覆盖掉那次前向留下的分布参数**。后果是：PPO 的 surrogate loss
（基于第一次前向的 log_prob）和蒸馏 loss（基于第二次前向）**建立在不同的前向结果上**，
两者不再自洽，梯度打架。所以这里**只读不算**。

> 这个坑不报错、形状也对，纯粹是语义错误——属于最难查的一类。

## 5. 我踩过的坑（面试素材）

### 坑 1 · KL 方向写反：一行之差，静默改变训练行为

```
现象：把 diagonal_gaussian_kl 的参数顺序写成 (student, teacher) 而非 (teacher, student)，
      代码照跑不误、不报错，loss 也在下降，只是训出来的 Student 探索行为变"僵"。
第一反应："KL 不就是衡量两个分布差距吗，谁前谁后应该差不多。"
为什么这么想是错的：KL 天生不对称（见 2.3）。forward KL(teacher‖student) 是 mode-covering，
      逼 Student 覆盖 Teacher 的完整分布；反向 KL(student‖teacher) 是 mode-seeking，
      Student 会缩到 Teacher 的一个峰上、丢掉其余行为模式。方向反了，学到的东西质变。
怎么找到真因：写一个断言——forward 和 reverse 数值必须不同。
      forward = diagonal_gaussian_kl(tm, ts, sm, ss)  # 0.6363
      reverse = diagonal_gaussian_kl(sm, ss, tm, ts)  # 1.6137
      assert not torch.allclose(forward, reverse)      # 非对称性是 KL 的定义性质
      再拿同分布代入，KL 必须恰好为 0，验证公式本身没写错。
根因：把"对称的距离"和"不对称的散度"搞混了——KL 是散度不是距离。
教训：任何不对称量，第一件事就是写"交换参数结果必须变"的测试。
      形状对、能跑、loss 降，都不能证明方向对；只有非对称断言能。
```

### 坑 2 · 首轮下结论"KL 更优 21.3%"——但那是个不干净的对照（诚实性修正）

这是我最想在面试讲的一个坑，因为它是"**发现自己之前的结论不严谨，然后修正**"的过程。

```
现象：首轮跑完 action_matching 和 kl_matching，一比，KL 组关节跟踪误差低 21.3%
      （AC 0.4941 vs KL 0.3878）。我差点写下"KL 蒸馏目标明显更优 21%"。
第一反应："差距这么大，KL 目标肯定更好，结论成立。"
为什么这么想是错的：两组除了蒸馏目标，还差三处超参——
      learning_rate（5e-4 vs 3e-4）、entropy_coef（0.0025 vs 0.005）、desired_kl（0.005 vs 0.008）。
      这意味着 21.3% 里混进了超参的贡献，无法归因到蒸馏目标本身。
      对照实验的价值完全取决于"是否真的只差一个因素"。
怎么找到真因：补跑一组"超参对齐"的 action_matching——把它的三个超参改成和 KL 组一致，
      其余不变。这样"AC 对齐"和"KL"之间就只差蒸馏目标一个变量，可归因。
      · 纵向（AC 原始 vs AC 对齐）：关节误差 0.4941 → 0.4491，光换超参就改善 9.1%。
      · 横向（AC 对齐 vs KL）：0.4491 vs 0.3890，差距 13.4%。
根因：首轮把"蒸馏目标"和"超参"两个变量捆在一起变了，是多变量对照，不能单因素归因。
教训：① 21.3% 里有 7.9 个百分点其实来自超参，真正归因给蒸馏目标的只有 13.4%——
        不做对齐重跑，会把结论强度高估近三分之一。
      ② 对照实验做不干净时，结论不是"错"，而是"强度不明"，而强度恰恰是决定
        要不要用某个方法的依据。
      ③ "是否只差一个因素"必须在训练**之前**逐项核对，事后无法补救。
```

一个附带的小插曲：对齐值我取的是 KL 组的超参，所以"AC 对齐"和"KL 原始"超参已经
完全相同（两份 `agent.yaml` 逐项一致），**KL 组根本不用重跑**。但我一开始还是排了
一次 KL 重跑，跑到 1500 iter 才反应过来是无用功。**教训：排实验前先画个 2×2 表，
看看哪一格和已有的重复。**

### 坑 3 · 两组训练轮数不一致，对照不公平

```
现象：复查日志发现 KL 组日志末行 ETA 00:56:49（被中途终止），action 组 ETA 00:00:00（跑完）。
      实际 KL 只跑了 1515 轮，action 跑了 2999 轮——KL 只跑了对方一半。
第一反应："KL 只跑一半还更优，那它肯定更优。"
为什么这么想是错的："大概率"不是证据。KL 组在 1515 轮可能还在快速改善（跑满差距扩大到 20%+），
      也可能已过拟合（跑满差距缩小甚至反转）。两种可能都会让原结论失效，而我没证据排除。
      训练量不足只是"结果没到最好"，而**不公平的对照会给出方向可能都错的结论**，更严重。
怎么找到真因：把 KL 组按 3000 轮补跑，两组都到 2999 轮 · ETA 00:00:00，再重算。
      结果差距 13.4%——和用 1515 轮数据算的 13.5% 几乎一致，方向和幅度都确认了。
根因：多组对照没核对每组的实际完成轮数，默认"启动参数一样，结果就可比"。
教训：日志末尾的 ETA 是最便宜的检查点——`ETA: 00:00:00` 才是跑完，其它值都意味中断。
      "碰巧对了"和"有证据支撑"是两回事，现在这个 13.4% 是后者。这个检查成本几乎为零，
      以后每组对照都该做。
```

### 坑 4 · `std=0` → nan 的静默传播

```
现象：某次实验 loss 突然变 nan，但训练不报错、还在往下跑，checkpoint 保存的全是 nan 权重。
第一反应："是不是学习率太大梯度爆了？"先去调小 lr。
为什么这么想是错的：调 lr 没用，nan 依旧。梯度爆炸通常是 loss 冲到很大再 nan，
      而这次是 loss 直接跳 nan，更像除零/log(0)。
怎么找到真因：定位到 KL 公式，检查 std 的取值范围，发现某些维度 student_std 贴到了 0，
      log(σ_s/σ_t) = log(0) = −inf，1/(2σ_s²) = 除零 = nan。
根因：高斯策略后期 σ 会很小，一旦某维到 0，KL 公式里的 log 和除法就出 nan，
      一次反传污染整个网络。
教训：所有含 log/除法的地方都要加数值下界，代码里 clamp_min(1e-6) 就是干这个的。
      这和实践 2 里 height_scanner 打空射线产生 inf 是同一类"静默失败"——
      不报错的错误最贵，防御性 clamp 是标配。
```

### 坑 5 · 手动切分观测喂 Teacher/Student（助教点名的高频错误）

```
现象：想当然地把 batch.observations 手动切成"Teacher 那份"和"Student 那份"分别喂进去，
      结果要么维度对不上报错，要么蒸馏静默失效（loss 在降但学不到东西）。
第一反应："Teacher 要特权观测、Student 要受限观测，那我在外面切好再喂天经地义。"
为什么这么想是错的：Teacher 和 Student 吃的是**同一个** batch.observations，
      各自在网络内部取自己需要的切片（teacher_forward / student.forward 内部处理）。
      在外面手动切，既容易切错边界，也绕过了内部的归一化/编码逻辑。
怎么找到真因：对照 ASSIGNMENT.md §5.1 和 student_teacher 的前向实现，
      确认观测分发是网络内部职责，外部只传整个 observations。
根因：把"观测空间设计"（网络内部的事）和"数据喂入"（外部的事）职责搞混。
教训：接口契约要照着实现读，别照直觉猜。凡是"框架已经替你做了"的事，
      自己再做一遍往往是错的。
```

## 6. 面试可能怎么问

**概念题**

1. **什么是 KL 散度？为什么它不对称？**
   衡量用分布 Q 近似 P 的信息损失，`KL(P‖Q)=Σ P log(P/Q)`。不对称是因为求和权重是 P：
   只在 P 高的地方计较差异，P≈0 处不罚。所以 KL(P‖Q)≠KL(Q‖P)。举窄/宽高斯例子：
   forward 0.318、reverse 0.807（可当场手算）。

2. **蒸馏为什么用 forward KL(teacher‖student) 而不是反向？**
   forward 是 mode-covering，逼 Student 覆盖 Teacher 的完整行为分布（继承所有走法）；
   reverse 是 mode-seeking，Student 会缩到 Teacher 的一个峰、丢掉其余模式。
   蒸馏要继承完整分布，所以用 forward。

3. **Action Matching 和 KL Matching 差在哪？**
   前者只对齐均值 μ（Teacher"做什么"），后者对齐整个高斯 (μ,σ)，多传了 Teacher 的
   不确定性结构（哪里该保留探索）。

**实现题**

4. **蒸馏的 KL 和 PPO 的 desired_kl 是一回事吗？**
   完全不是。蒸馏 KL 比较 Student↔Teacher、参与反传、是训练信号；desired_kl 比较
   新旧策略、不反传、只用来自适应调学习率。代码里前者在 `_compute_distillation_output`，
   后者在 `update()` 的 `inference_mode` 块里调 LR。

5. **Teacher 参数已经冻结了，为什么前向还要 `torch.no_grad`？**
   `requires_grad=False` 只让参数不更新，前向仍会为中间激活建图占显存，
   某些写法还会把梯度错误引流回去。Teacher 是数据源，`no_grad` 连图都不建。

6. **蒸馏系数为什么要退火？固定不行吗？**
   因为信息不对称：Teacher 看得到未来、Student 看不到，Student 永远无法完全复制 Teacher。
   后期还硬压着匹配，会阻止它学出受限观测下的补偿策略。退火让后期把权重让给 PPO 回报。
   KL Matching 退火到一个非零下限 `kl_coef_min`，保留轻微约束防止漂移。

**深挖题**

7. **你说 KL Matching 更优，凭什么？这个结论有多可靠？**
   公平对照（两组均 2999 轮、同一 Teacher、同一份受限观测、同一超参，唯一变量是蒸馏目标）下，
   KL 组关节跟踪误差 0.3890 vs AC 组 0.4491，**低 13.4%**；失败占比、身体姿态误差同向更优。
   但我会主动补两点边界：① 首轮看到的是 21.3%，那次超参混杂，对齐后才是 13.4%，
   有 7.9 个百分点来自超参；② Action 组末段还在 +5.7% 上涨、KL 组已进平台，
   所以"KL 更优"**只在 2999 轮这个预算下成立**，不能推广成"KL 的收敛上限更高"——
   要回答上限得两组都跑到平台再比。

8. **你怎么保证你的对照是干净的？**
   训练**之前**逐项核对唯一变量（用 2×2 表看哪格重复），训练**之后**用日志末尾 ETA
   确认每组都真跑完（`ETA 00:00:00`），最后用收敛曲线判断"够不够"而不是看轮数百分比。
   这几条都是踩过坑总结的（见第 5 节坑 2、坑 3）。

## 7. 延伸：这个技术在工业界怎么用

**Teacher-Student / 特权蒸馏是 sim-to-real 的主流范式之一。** 招聘 JD 里
"privileged learning""teacher-student distillation"点名率很高，因为它解决的是
真机部署绕不过的矛盾：**仿真里能拿到的信息（精确身体状态、地形高度图、未来指令），
真机上拿不到或很贵。**

- **ANYmal（ETH，Science Robotics 2020/2022）**：Teacher 用特权地形信息训练，
  Student 只用本体感受 + 一个信念状态编码器蒸馏，最终四足在野外走复杂地形。
  这是特权蒸馏的经典代表作。
- **人形运控（本课程所在领域）**：Teacher 看未来参考帧把动作跟踪学稳，Student 用
  可部署观测蒸馏，再迁真机。VisualMimic、Perceptive Behavior Foundation Model 等
  近期工作（ASSIGNMENT 参考文献）都在这条线上。
- **经典分类蒸馏（Hinton 2015）**：同样的思想在监督学习里更早出现——大模型（Teacher）
  的软标签训练小模型（Student），既压缩又保留"类别间相似性"这种暗知识。
  RL 里 Teacher 的动作分布，就相当于分类里的软标签。

在完整技术栈里，这个实践是 **"训练用特权、部署用受限"** 这一环。它上游接
运动重定向（实践 7，把人体动作转成 G1 能做的参考）和 Teacher 训练，
下游接真机部署。理解了这一环，就理解了为什么"能作弊的老师"反而是好东西——
它把难探索的问题变成有答案可抄的问题，抄完再把答案搬到部署条件下。
