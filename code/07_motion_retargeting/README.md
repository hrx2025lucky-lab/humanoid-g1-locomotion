# 实践7：走、跑、转弯三类提交候选

本轮补齐了单独的行走、跑步片段，连同上一轮完整右转，形成三类动作、实际AMP目录/配置和视频报告的本地提交候选。类别、数值格式和CPU加载已有证据；步态片段较短，脚地接触仍有厘米级几何误差，不能据此宣布P8可稳定控制或最终数据质量全部通过。

## 数据来源与裁切披露

三条数据分别源于ACCAD的Female1Running子集C4、C5、C16，共三个独立人体源。原始人体文件、完整GMR输出和失败样本均保留。走跑片段没有调整关节角、根姿态、局部连杆位置或fps，也没有补帧循环；仅选取时间区间，并把第一帧根位置XY平移到原点。右转沿用上一轮最多4.12mm的单独根高度校正。

| 文件 | 实际内容 | 完整GMR源帧区间（从0计数，两端包含） | 帧数/实际fps | 首尾采样时间跨度 |
|---|---|---|---|---|
| walk_C4_f050_105.npz | 跑转走完成后的行走 | C4第50–105帧 | 56 / 30 | 1.833秒 |
| run_C5_f120_161.npz | 走转跑完成后的加速跑 | C5第120–161帧 | 42 / 29.907692 | 1.371秒 |
| turn_right_C16_full.npz | 完整跑步右转 | C16第0–69帧 | 70 / 29.893238 | 2.308秒 |

“跑步片段”不等于匀速、直线或长时间稳定跑；这里依据人体源、腿部交替、抬脚幅度和速度阶段进行分类。行走中位根速度0.881m/s，加速跑3.311m/s。完整C4/C5仍是切换动作，不把同一文件改名字就当作新增类别。[segment_manifest.json](evidence/segment_manifest.json)包含原文件哈希、裁切索引、XY偏移和对应人体源的插值帧坐标。

## 原文要求与实现

根据实践7原文第16–18页，提交物包括修改/新建的NPZ导出代码、至少一条走路、一条跑步和一条切换或转弯、可视化及实验说明；数据应能被实践8直接读取，并与`motion_cfg.py`同步。原文没有要求先训练出P8动态策略。

- `smplx_to_robot_npz.py`：读取SMPL-X，调用GMR将人体姿态转换成G1，再导出六个字段。MuJoCo根四元数wxyz重排为xyzw；根位置归零、根姿态设为单位四元数后计算局部正运动学。
- `build_segments.py`：在完整转换结果上作可追溯切片，并断言关节角、根姿态、局部位置、fps及连杆顺序逐元素保留；只有根XY作平移。
- GMR参考映射中，人体pelvis对应G1 pelvis，foot对应toe，腕关节对应wrist_yaw_link。参考表为躯干/下肢配置0.9、上肢0.8的比例因子，并结合人体身高处理；本轮没有声称重新设计或调优这些IK权重。骨盆/足端较高的位置权重用于优先贴近关键目标，仍不是接触力约束。
- `motion_cfg.py`新增可显式选择的`G1P7SegmentsMotionCfg`，注册名为`p7_segments_20260911`。实际数据放在AMP的`data/p7_segments_20260911/`，三个文件各权重1.0；仅用于本轮课程加载检查，不是已调优的P8训练配方。旧`walk_to_run`仍指向旧`mixed`。

本轮尚未增加新Isaac环境注册或切换Agent。后续P8必须让环境的`motion_style`、专家数据的`profile_name`和Agent的`amp_motion_profile`一致；只把新文件放入目录，不会自动改变当前训练。

## 质量与可视化

| 检查 | 行走 | 加速跑 | 右转 |
|---|---:|---:|---:|
| 地面/自碰撞最大穿透 | 0 / 0 | 0 / 0 | 0 / 0 |
| 关节越限 | 0 | 0 | 0 |
| 局部FK最大误差 | 1.71e-6m | 1.61e-6m | 1.54e-6m |
| 最大相邻帧关节变化 | 0.343rad | 0.502rad | 0.471rad |

全序列数值检查通过不等于无足滑。行走最低足底高度中位数约2.53cm、最大约4.13cm；在一段0.733秒的近地窗口内脚的水平净位移约4.51cm。加速跑近地窗口内约0.201秒净位移1.86cm。这些使用30mm阈值的几何诊断没有接触力，不能直接称为支撑期真实滑动，也不能写成“零足滑”。最终课程质量审阅及后续P8数据改进仍应关注落脚高度和连续性。

已生成与人体源逐帧对应的对照视频，使用原始SMPL-X的前22个人体关节点，按完整转换器相同的线性插值位置取样。左右画面采用相同观察角度、各自跟随骨盆，人体保留原尺寸；骨架关节点不是脚底接触点。G1只做运动学播放，没有推进动力学。人体场景的初始地面显示和软件阴影伪影已修复，最终采用v3。

## 实际加载检查与失败记录

三类动作先通过真实MotionDataset的80维×3帧、4096连续窗口、1024一致参考状态、独立NumPy插值和非恒等关节重排检查；再通过实际配置工厂构造数据集，验证4096组240维输入有限，以及配置应用方法和旧目录保持不变。详见[profile_verification.json](evidence/profile_verification.json)、[amp_loader_verification.json](evidence/amp_loader_verification.json)。

验证工具第一次调用`MotionDatasetCfg()`缺少必填参数，发生TypeError；已修正为复制实际配置后检验apply方法，核对既有输入哈希后重试通过。保留`profile_host.log`和`profile_retry_host.log`，这不是训练或加载器实现错误。

## 提交候选与后续顺序

本地候选包包含三条NPZ、三个视频、导出与切片代码、动作配置、报告及哈希清单。人体原始数据、SMPL-X人体模型和GMR依赖不放入包；包内源码保留本机路径，离开本机需要配置依赖和路径。它是私人课程材料，不上传公开展示仓库。

后续优先审阅候选质量、补较长的走跑数据与落脚改进，再准备P8实际环境短验证和同预算AMP/纯任务对照。P6继续按既定20k预算训练，P2/P10短验证沿原队列执行；不会因为生成这些数据而中断或重启当前训练。
