# 实践 03 · HoST 起身与增量动作部署 — 我的改动清单

对照基准：上游动作空间基线包（仅提供 `deploy_mujoco_host_student.py` 骨架）

## 我修改的文件

- `deploy_mujoco_host_student.py` — 补全四处核心实现：

| # | 内容 | 函数 |
|---|---|---|
| 1 | 读取 MuJoCo 浮动基座状态与投影重力 | `read_robot_state` |
| 2 | 拼接 76 维单帧观测 | `build_single_observation` |
| 3 | 维护 6 帧 FIFO 历史，输出 456 维 | `update_observation_history` |
| 4 | HoST 增量动作空间映射 | `action_to_joint_targets` |

单帧 76 维 = 基座角速度 3 + 投影重力 3 + 关节角 23 + 关节角速度 23
+ 上一帧动作 23 + 动作尺度 1。历史长度 6，策略输入 456 维。

## 我新增的文件

- `ablation_action_space.py` — 增量动作空间与残差动作空间的对照实验

两组唯一差别是动作映射的基准：增量式取当前实际姿态 `q* = q_current + 0.25a`，
残差式取固定标称站姿 `q* = q_default + 0.25a`。其余全部相同，包括预训练策略、
观测拼装、PD 参数与随机种子。

20 秒仿真结果：

| | 峰值高度 | 后半程均值 | 判定 |
|---|---:|---:|---|
| 增量式 | 0.747 m | 0.742 m | 站起并维持 |
| 残差式 | 0.096 m | 0.065 m | 全程平躺未动 |

残差式失败的原因是可达关节空间受限。策略输出量级约为正负 1，乘动作尺度 0.25 后，
膝关节目标角被锁在标称值附近约正负 0.25 rad 的区间内，而从仰卧撑起需要屈曲到
1.5 至 2.0 rad。由于每步目标都相对同一固定基准计算，误差不累积，无论运行多久都
无法到达。增量式把基准锚在当前姿态上，50 Hz 控制下累积行程可覆盖整个关节空间。

## 验证范围

使用既有预训练策略，未进行 HoST 自主训练；验证仅覆盖默认仰躺初态，
未评估任意跌倒姿态下的恢复能力。
